# Trade Opportunities Workflow

Trade Opportunities is one of the two local-suite jobs ([local-models.md](local-models.md)).
This document specifies its end-to-end control flow; the feature's design rationale — the archetype lens, the 3×3 matrix, the two detection modes, the two-arm opportunity record, the continuity vocabulary — lives in [trade-opportunities.md](trade-opportunities.md).

Trade Opportunities is **two on-demand jobs sharing one page** — **Discover (DTO)** and **Audit (ATO)** ([trade-opportunities.md §The two jobs](trade-opportunities.md#the-two-jobs)).
The step table below specifies **DTO's** end-to-end control flow (the full funnel); **ATO** is a reduced, user-directed flow over selected opportunities that **reuses DTO's stages** — its **Deep Audit** is the Step-5 per-candidate loop, its **Quick Audit** the engine-only cheap re-derivation — and is described in [§ATO: the audit flow](#ato-the-audit-flow).

The **DTO** job:
- loads the house view and the run-level macro / positioning context, then scores every due horizon in the episode store
- **discovers** candidates through three converging feeders — bottom-up structured screens, a model-led hypothesis-research lane (its edge), and a carried-forward watchlist (the persisted discovery memory, re-read each run by a watchlist review) — rather than reading a fixed list
- classifies each candidate by archetype, computes a deterministic, archetype-weighted financial picture for it, and holds out at the engine's evidence floor the names that cannot earn the model's time
- researches each candidate on the open web with the shared per-topic loop — building the leading-metric case **and a mandatory bear case** — and consolidates the research into one **analysis**
- on a carried name reviews its prior call against what happened since, then writes each candidate's **thesis document** and transcribes its typed appendix — the risk tier and horizon that place the card, the conviction, and the expected price at three months, twelve months and three years — beside the engine's reads: the two-arm opportunity record
- runs the entry gate on both arms, carries prior opportunities forward with an updated status, opens the episodes the next run's checks score, and flags any overlap with current holdings

Both jobs run **on demand only**; their model work runs **entirely on local models** (ATO's Quick Audit makes no model call at all), with **no cost at the model layer**.
A **single global run slot** serializes both against the report and Portfolio Analysis (only one runs at a time).
Both run under one **`trade_opportunities` job identity**, each run record carrying its **mode** — `discover` / `audit-quick` / `audit-deep` — so job history, retention, and the page footer's last-run stamp read a single mode-labeled pool ([scheduling.md §Job Status Visibility](scheduling.md#job-status-visibility)).
For job states, the global run slot, cancellation, and error handling, see [scheduling.md](scheduling.md) and [run-tracking.md](run-tracking.md); for the failure posture (per-candidate checkpoint/resume, fail-soft research and discovery), see [trade-opportunities.md §Failure posture](trade-opportunities.md#failure-posture).

Unlike Portfolio Analysis, the feature is **not tied to current holdings** — **DTO discovers new ideas**, while ATO maintains the existing matrix.
It still **requires a connected Schwab account**, whose option chains supply the per-candidate options-activity signal ([schwab-integration.md](schwab-integration.md)); holdings are read only for the deterministic owned/not-owned **cross-reference** (Step 8 in DTO, the touched names in an ATO audit), which never influences what is discovered or chosen.

## How to read this workflow

Every step below is tagged with a **Type** so it is obvious what the step actually does — the same three Types the Portfolio Analysis and report flows use:

- **Computed (app layer)** — deterministic Rust logic, with no model and no external network: local SQLite and filesystem reads, the candidate dedup / tradability filter, the deterministic **risk-tier and horizon rules**, the **evidence floor**, the **accuracy checks**, and the **financial-analysis engine** (every sub-score, target, and derived read).
  A maintenance step that re-pulls external series while staying model-free is tagged **Computed + API retrieval** below — "engine-only" always means *no generative model*, never *no network* (the same convention Portfolio's step table uses).
- **API retrieval** — fetches from external sources: the **FMP discovery layer** (screener / peers / industry classification — the universe scan; **no `*-bulk` endpoint, off-plan**) and the **FMP per-symbol surface** (fundamentals, the revision signal, positioning, segments, deep price history); company cross-checks from **SEC EDGAR / FINRA**; run-level macro / commodity / positioning context from **FRED / FMP-commodity / CFTC / CBOE**; the free-tier **FMP Articles** feed (on the shared FMP key) the discovery scan reads (**no GDELT**); option chains from **Charles Schwab**; and the **web tool** (**keyless SearXNG only**) the orchestrator runs *on a model's behalf*.
  The full per-source endpoint surface, with each call's **discovery / per-candidate / run-level** cardinality, is in [data-sources.md §Trade Opportunities — endpoint surface](data-sources.md#trade-opportunities--endpoint-surface).
- **Local-model call** — invokes the primary reasoner **`Qwen3.5-122B-A10B`** on the app-supervised **Ollama** daemon ([local-models.md §Serving runtime](local-models.md#serving-runtime)) in **thinking** mode (route planning, the research gathering turns and their write-ups, the hypothesis document, the watchlist review, archetype confirmation, the analysis, the self-review, the thesis document) or **non-thinking** mode (distilling write-ups, and transcribing a document's stated values into its typed appendix or decisions).
  The job makes no embedding call.
  Four calls return a typed object under Ollama's native `format` grammar and are app-checked on type: the route plan and the archetype label (thinking), and the transcriptions — a hypothesis document's appendix, a watchlist review's or refresh write-up's decisions, a thesis document's appendix (non-thinking); the gathering turns carry the tool-call schema and no grammar; every other call — a write-up, a distillation, the analysis, the review, the hypothesis document, the thesis document — returns prose with no grammar and no validation.
  **Mode caveat:** Ollama bug #14645 is verified fixed on the pinned version, so a `format`-carrying transcription runs `think: false` directly — but an Ollama version bump **re-locks** every `format`-carrying `think: false` call until the schema-integrity check passes on the new version, such calls riding thinking-enabled until it does (the rule is canonical in [local-model-operations.md](local-model-operations.md) §Structured output × thinking).

Two load-bearing architectural rules frame the whole table, the same ones the report and Portfolio pipelines hold: **agents are pure stages, and the application layer owns all I/O** — a model stage consumes the structured input handed to it and emits its document or typed object; when a research stage needs the web it *requests* a tool call and the orchestrator performs the fetch.
And **the engine computes every deterministic number** — metrics, sub-scores, tiers, scenario bands, the horizon rule, the gate ([local-models.md §Context-memory discipline](local-models.md#context-memory-discipline)) — while the model authors its **own arm** of the judgment: the thesis document with its placement, conviction and expected prices, clearly typed as model-authored; the engine's values stay the incorruptible baseline — the model arm never alters or binds it ([trade-opportunities.md §The opportunity](trade-opportunities.md#the-opportunity)) — and the model's are displayed and scored beside them, with the divergence recorded, never enforced.
Engine-owned values are app-stamped directly and **never echoed through the model**; the app reads a model document as text and validates nothing in it, and checks a typed appendix on type alone, never on content.
Placement reads the model arm — its tier × horizon set the cell — while the engine's rule-derived pair persists beside it as the baseline and alone feeds the gate's shared legs ([trade-opportunities.md §The opportunity space](trade-opportunities.md#the-opportunity-space)).
Every prompt follows the frame Portfolio's prompts share — one message in two parts, Part 1 the inputs with each data section glossed once, Part 2 the task — and tells the model nothing about the app that produced its inputs ([local-models.md §Prompt posture](local-models.md#prompt-posture)).
For each model stage, the **Local-model call** block lists what the prompt includes and what the model returns.
Per-step progress, per-request rows, and token/reasoning output stream to the run tracker over the shared `progress` seam ([run-tracking.md](run-tracking.md)), with **per-cell progress** as the matrix fills.

The job is a **funnel**: broad, cheap discovery narrows to a small candidate set, then each survivor gets expensive per-name validation — the condense-as-you-go discipline the rest of the suite uses, and the shape the data budget requires (the richest per-symbol signals are rate-relevant, so they are spent only on the narrowed set).
The cardinality bands in the endpoint table track this directly: **discovery** calls scan the universe a handful of times, **per-candidate** calls are the budget driver, and **run-level** calls fire once.

## Step 1: Job Start and Gate

**Type:** Computed (app layer) — the local-suite execution gate.
No model and no external API (credential and daemon *presence/reachability* are checked, not analysis).

The job will not start unless four preconditions hold, the same gate Portfolio Analysis clears ([portfolio-workflow.md §Step 1](portfolio-workflow.md#step-1-job-start-and-gate)):
- the **single global run slot** is free (no report or other local job is running — see [scheduling.md §Concurrent Job Protection](scheduling.md#concurrent-job-protection));
- the **local-model daemon is reachable and the configured roster is present** (the 122B reasoner — neither local job makes an embedding call) — health-checked at the Ollama endpoint ([local-models.md §Serving runtime](local-models.md#serving-runtime));
- a **connected Schwab account** with a valid (≤7-day) refresh token ([schwab-integration.md §A connected Schwab account is required](schwab-integration.md#a-connected-schwab-account-is-required)) — Trade Opportunities needs it only for the per-candidate options-activity signal and the closing holdings cross-reference, but the connection is a hard precondition all the same;
- the **shared FMP and FRED credentials are present** — the engine's structured surface and rate anchors; presence-only, via the existing missing-provider-credentials warning, and Tavily deliberately does not gate the local suite ([portfolio-workflow.md §Step 1](portfolio-workflow.md#step-1-job-start-and-gate)).

This gate is **independent of the cloud-report gate** — a machine with no OpenAI/Anthropic keys can still run the local suite.
Missing **configuration** (the Ollama endpoint or the reasoner id unset, Schwab not connected / refresh token lapsed, or the FMP / FRED credential missing) locks the local-suite Run buttons and shows a persistent warning *before* this step — **local models not configured**, **Schwab connection**, and the shared **missing provider credentials**, one per category.
A live **local-model connectivity** failure caught here at the run-gate (daemon unreachable, the reasoner not pulled) blocks the attempt **inline**, not as a persistent warning; ATO's **Quick Audit** reuses this gate but, making no model call, skips the daemon-connectivity check ([§ATO: the audit flow](#ato-the-audit-flow)).
Schwab *API* reachability is not tested at this step — it surfaces later, when the options-activity signal / holdings cross-reference fetch runs ([portfolio-workflow.md §Step 1](portfolio-workflow.md#step-1-job-start-and-gate), [interface.md §Connection status](interface.md#connection-status-local-suite)).

## Step 2: Load Shared Context

**Type:** Computed (local read — house view, prior run; the engine's accuracy checks) + API retrieval (run-level FRED / FMP-commodity / CFTC / CBOE, and the dated-EOD closes the accuracy checks read).
No model.

Loaded **once per run and shared across every candidate**, not re-requested per name:
- the **Market Signal house view** — the latest report's Thesis, Investment Strategy, and Forward Outlook sections plus recent report summaries (`thesis_stance`, `forward_outlook_themes`, `key_risks`), loaded **deterministically** from the report store (retrieve-don't-dump — never by vector-searching the report's memory; see [local-models.md §Context-memory discipline](local-models.md#context-memory-discipline)).
  The report's **creation date** rides into the context, and the same **one-week freshness window** Portfolio applies holds here: a house view older than one week is **omitted and recorded as a gap** rather than fed as current ([portfolio-workflow.md §Step 5](portfolio-workflow.md#step-5-load-shared-context)).
  The house view supplies the **macro / regime backbone of the job's worldview** — its `market_cycle` and `risk_posture` are a compact growth × inflation regime read ([trade-opportunities.md §The research method](trade-opportunities.md#the-research-method)) — and steers *where the job hunts* (it biases the top-down theme scan and the archetype-appropriate read) without being a number the engine consumes; the **forward thematic map** that completes the worldview is the job's own, built in the Step-3b hypothesis research.
  In every prompt it is rendered as a market-level analysis and never named by product ([local-models.md §Prompt posture](local-models.md#prompt-posture));
- run-level market context — the **risk-free rates** (FRED `DGS10` / `DGS2`) that anchor the engine's scenario-target function (`DGS10`, the v2 rate-anchored multiples — [portfolio-analysis.md §Starting parameters](portfolio-analysis.md#starting-parameters-calibratable)) and the entry-asymmetry hurdle (`DGS2`, the suite's short-end anchor for its ~12-month window — [trade-opportunities.md §Starting parameters](trade-opportunities.md#starting-parameters-calibratable)).
  The full run additionally loads the **anchor-window `DGS10` history** the v2 percentiles join against (one date-ranged request per run, retained as dated observations; the acquisition rule on the Portfolio DGS10 row — [data-sources.md §Portfolio Analysis — endpoint surface](data-sources.md#portfolio-analysis--endpoint-surface)).
  A rate retrieval still failing after the shared bounded retries **hard-fails the run here, before any per-candidate work** — the canonical rate-anchor rule ([trade-opportunities.md §Failure posture](trade-opportunities.md#failure-posture)).
  **Cyclical commodity prices** (FRED daily energy + monthly IMF metals, FMP daily commodity series — copper `HGUSD` plus the job's canonical **gold `GCUSD` / silver `SIUSD`** series, the identity table in [data-sources.md §Financial Modeling Prep](data-sources.md#financial-modeling-prep)) are read both as the **commodity-cyclical discovery feeder** (a price turn surfaces the sleeve) and as per-candidate context.
  The context also carries **CFTC Commitments-of-Traders positioning** on the bellwether contracts (the commodity sleeve's positioning read); the **CBOE venue-level put/call backdrop** (a broad-market sentiment context, not a per-name signal); and the **macro-release calendar** (FRED `/release/dates`, names + dates — the same free endpoint the report's calendar uses), the schedule fed to the Step-3b routes as leads ([§Step 3b](#step-3b-model-led-hypothesis-research));
- the **prior run's persisted opportunity matrix**, loaded for the Step-7 carry-forward continuity check; the **persisted opportunity graph** — the job's **discovery memory** (prior hypothesis documents with their appendix fields, and the **watchlist** of worthy-but-unpicked names with each one's leading metric and status), loaded so Step 3c's review can judge the watchlist and Step 3b can extend or retire existing theses rather than re-deriving blind; and the **discovery-coverage ledger** — last attempted / last successfully completed timestamps for the canonical route classes and the broad industry / active-theme subjects actually researched — loaded so the Step-3b agenda rotates beyond whichever topics are currently loud ([trade-opportunities.md §Discovery memory](trade-opportunities.md#discovery-memory-the-opportunity-graph)).

The investor profile is **not loaded**: the opportunity record is a profile-independent read, and no Trade Opportunities prompt carries the profile ([trade-opportunities.md §The opportunity](trade-opportunities.md#the-opportunity)).

Then, before discovery, the deterministic **accuracy checks** run over the **episode store** ([trade-opportunities.md §Outcome learning](trade-opportunities.md#outcome-learning-calibration)) — in every mode, the engine-only Quick Audit included, since they need no model.
An episode is a price record tagged with its decision class — `picked`, `gate-reject` or `excluded`: the symbol and lifecycle, the creation date, the spot that day and the anchor close that bridges the record across a later split, the model's expected price at three months, twelve months and three years, and the engine's base value at the same horizons.
The checks visit every episode in the store with a horizon that has passed and is not yet checked — a live pick, a departed one and a turned-away name alike, since the record measures the forecast.
The dated-EOD series is refreshed through the shared price-bar cache for every symbol with a due horizon.
Each check reads the close on the horizon date, or the last session at or before it within the drafted few-session proximity, bridges the episode's prices across any split since creation, and writes the check onto the episode — date, horizon, expected, actual and the score, for the model's price and for the engine's — the per-check score one hundred times one minus the absolute error over the actual, floored at zero (the constants are Portfolio's — [portfolio-analysis.md §Starting parameters](portfolio-analysis.md#starting-parameters-calibratable)).
A horizon whose series the run could not refresh stays pending for a later run; one whose refreshed series serves no close inside that proximity is written unscorable at once and leaves the due set, the symbol spending no further pull.
From the checks the pass derives each lifecycle's **accuracy scores**: at each horizon, the mean per-check score over the lifecycle's checks, for the model and for the engine separately, 0 to 100, "no score yet" before the first check.
The checks run here rather than after the loop so that this run's self-reviews read every check that has come due ([§Step 5f](#step-5f-self-review)); they land in the store as they are written, and the due query excludes a written horizon, so a resumed run never re-scores one.
Opening this run's episodes waits for the loop, since it needs this run's expected prices ([§Step 7](#step-7-continuity-check--carry-forward)).

## Step 3: Candidate Discovery

**Type:** mixed — three converging feeders (see 3a–3c).
This is where ideas are **found**, not merely vetted: model-led research is a first-class *discovery* feeder that runs here, before candidate selection, not only as a downstream validation step ([trade-opportunities.md §The pipeline](trade-opportunities.md#the-pipeline)).
The three feeders are the **bottom-up structured screens** (3a), the **model-led hypothesis research lane** (3b — the edge: it forms investable *hypotheses* and reasons its way to names), and the **carried-forward watchlist** (3c — the persisted discovery memory, re-read each run).
In execution order the 3a screens and 3c's engine refresh and **watchlist review** run first, so 3b's planner reads the review's decisions; the 3b routes follow; and 3c's bounded research refresh lane runs last, from whatever discovery budget the routes leave.
All are **fail-soft** — a failed screen, sweep, or review degrades to fewer candidates, never a failed run.

### Step 3a: Bottom-Up Structured Screens

**Type:** API retrieval (FMP discovery layer + FINRA) + Computed (app-layer slicing, including the commodity-turn read over the Step-2 run-level context).
No model.

Cheap, broad, structured feeders over the whole universe, run deterministically and tagged with the signal that surfaced each name.
**The plan carries no `*-bulk` endpoint, and the company screener exposes only coarse market-structure fields** (market cap, sector / industry, beta, price, dividend, volume, exchange — no valuation / profitability / growth filter; [data-sources.md §FMP — current paid-plan tier audit](data-sources.md#fmp--current-paid-plan-tier-audit)), so this stage **cannot pre-score the universe**.
It *generates and stratifies* a candidate longlist; the multi-factor quant composite and the forensic reads move entirely to the per-candidate engine (Step 5c), computed only on the narrowed set the budget can afford:
- **Company screener → universe definition + breadth stratification** — `company-screener` applies the **hard tradability gates** (price / volume / market-cap floors, `isActivelyTrading`, the allowed exchange set, equities only) and tags every eligible name with its **market-cap band and sector / industry**.
  This is the breadth backbone — it defines the strata Step 4 fills, **not a ranked shortlist** (there is no fundamental field to rank on).
- **Event / catalyst & positioning feeds** — the market-wide **insider-buy feed** (`insider-trading/latest`) for cluster buys, **short-interest extremes** (FINRA's consolidated biweekly file, fetched once per run), and the **event feeds** (`mergers-acquisitions-latest`, `sec-filings-8k`, `ipos-calendar`, the report's free movers / earnings-calendar) for fresh catalysts.
  The activist-stake and congressional feeds are **symbol-keyed** on the current plan — no market-wide read — so they enter per-candidate at Step 5b, never as discovery feeders ([data-sources.md §Trade Opportunities — endpoint surface](data-sources.md#trade-opportunities--endpoint-surface)).
  Alongside them runs the **post-earnings surprise screen**: the same `earnings-calendar` read **backward** over the trailing window (the paid calendar carries consensus + actuals), surfacing recent reporters whose **standardized surprise** (scaled by the name's own surprise history, SUE-style — never raw %) is large and positive, **prioritized where the revenue surprise agrees with the EPS surprise** (post-earnings drift is markedly stronger when both point the same way), as **continuation-mode** candidates.
  The streak itself is confirmed per-candidate at Step 5c from `earnings` history, at discovery cardinality and zero new endpoints.
  This is the most selective structured feeder — a name surfaces because something **already moved**, so it skews coincident / lagging; that is a *defect* for early detection (those names come from the Step-3b research lane) but exactly *right* for continuation, whose licence to buy is demand visibility already showing ([trade-opportunities.md §What the job hunts](trade-opportunities.md#what-the-job-hunts)).
- **Commodity-price turns** for the **cyclical sleeve** — read from the **Step-2 run-level FRED / FMP-commodity context, not re-fetched** (Step 2 is the sole commodity owner): a spot / contract-price turn at washed-out sentiment surfaces commodity-cyclical candidates.

Each feeder reduces to a candidate set with its surfacing signal attached.
**The per-symbol rate discipline now binds** — the rich factors `*-bulk` once amortized across the universe are spent per candidate downstream, which is exactly what the Step-4 budget rations ([data-sources.md §Trade Opportunities — endpoint surface](data-sources.md#trade-opportunities--endpoint-surface)).

### Step 3b: Model-Led Hypothesis Research

**Type:** Local-model call (122B, thinking; the appendix transcription non-thinking) + API retrieval (news stack + web tool), **looped**.
The job's **edge**: a research-active feeder that forms investable **hypotheses** and reasons its way to names — not a "theme → tickers" lookup.
It runs **worldview → hypothesis → mechanism → value-chain node → leading metric → candidate**, so the model commits to a *hypothesis first* and only then to the public-company expressions of it.
It builds the **forward thematic map** — the job's worldview layer ([trade-opportunities.md §The research method](trade-opportunities.md#the-research-method)) — inside the **same bounded per-topic research loop the per-candidate stage uses** ([web-research.md §The research loop and context management](web-research.md#the-research-loop-and-context-management)), here aimed at *discovery*, in three movements (**each topic its own isolated conversation over a clean context**, so the local model is never handed a sprawling prompt):

1. **Research-strategy planning** — rather than a fixed agenda, the reasoner (given the Step-2 house view, the carried-forward opportunity graph with the watchlist review's decisions, and the app-computed coverage state) **chooses which research routes to spend the discovery budget on**: e.g. a *policy / regulatory* route, a *supply-chain* route, a *technical-bottleneck* route, a *procurement / grant / capex* route, a *customer-capex* route, an *industry-history* route, a *failure-analogue* route, and an *event-impact / value-chain-repricing* route.
   **Each carries its own source strategy** so a route targets the right source types rather than leaning on generic web search: *policy* → legislation, agency notices, procurement databases; *supply-chain* → trade journals, filings, customer / supplier commentary; *technical-bottleneck* → standards bodies, engineering blogs, patent / product docs, trade publications; *event-impact* → the announcing company's primary materials (spec sheets, reference designs, keynote / launch docs), standards bodies, teardown / engineering analysis, and the affected names' segment disclosures.
   And so on per route; at implementation these per-route source strategies are expressed as a **rubric the prompt renders**, so a route reliably targets its source types.
   **The event-impact route's materiality gate keeps it from chasing every product headline, but the gate is research-derived and unknowable at planning time — so the planner may schedule the route speculatively**; the gate — the announcement plus a corroborating condition named in the appendix — is checked downstream, **at card formation**, per the canonical lens contract ([trade-opportunities.md §The event-impact / value-chain repricing lens](trade-opportunities.md#the-event-impact--value-chain-repricing-lens)), and a scheduled route whose research surfaces no qualifying event **emits nothing and stays dormant**, so a normal run behaves exactly as before.
   **One route is always a mandatory *outside-view challenge*, run graph-blind** — "assume the carried-forward graph is stale: what world-change are we missing?" — so stateful memory can't anchor the job to its own prior hypotheses (the live complement to Step 3c's carry-horizon pruning).
   **Coverage rotation constrains the next route slot whenever coverage debt exists**: the app computes age separately for each canonical route class and each coverage subject (the stable broad-industry taxonomy plus currently active house-view themes), pairs the oldest compatible overdue class + subject, and inserts that route after the outside-view route before the model fills the remaining slots.
   Age ties break by canonical route order, then stable subject id; a model-proposed duplicate merges into the inserted route rather than consuming a second slot.
   The configured coverage window is counted in **calendar time, never run count**; a newly active theme starts due, a successfully completed route advances every class / subject it actually researched even when it correctly emits no hypothesis, and a failed / budget-exhausted route records an attempt but **does not clear its debt**.
   If the configured route cap leaves no slot beyond the mandatory outside-view route, coverage debt remains overdue and the run audit surfaces it; liveness is best-effort under the cap, never achieved by silently dropping the outside-view guard.
   The inserted route consumes the same route cap and discovery fetch / wall-clock budget as every other route, and coverage can require research but can never require a hypothesis, promotion, or opportunity — it fixes agenda starvation without weakening any quality gate.
   Route selection is itself bounded (a capped number of routes per run, priority-ordered); this is where aggressive deep research becomes real rather than "search the web for themes."
2. **Hypothesis formation** — each route's research is consolidated into a **hypothesis document**, the worldview reasoning made explicit and auditable: per hypothesis, *what is changing in the world* → *the affected system / mechanism* → *who gains pricing power / where the margin is captured* (the economic value-chain trace — margin capture, bargaining power, capacity constraint / bottleneck, and pricing power **versus mere exposure**, deliberately past the crowded pure-plays to the **picks-and-shovels enablers** at the constrained, margin-capturing nodes, often mid / small cap) → *the leading metric that would prove it* (named with its **re-check class** — see Step 3c) → *the likely public-company expressions* → *bear case* → *the key falsifiers + sources to verify*.
   An **event-impact route's document is explicitly two-sided** — it traces the chain into **beneficiaries**, **feared losers** (the names that sold off, with the *actually-exposed* revenue / profit pool sized), and **latent names** (chain nodes that did not move but should be affected) — and sizes each affected name's **technology read** in prose (substitute / complement / mix-shift, the exposed pool, the deployment timeline, switching costs, the margin-capturing node — [trade-opportunities.md §The event-impact / value-chain repricing lens](trade-opportunities.md#the-event-impact--value-chain-repricing-lens)) so the panic-vs-real and euphoria-vs-real reads are *sized*, not narrative.
   The document **decides each hypothesis on its own merits, before any ticker** — magnitude, durability, time horizon, **leading-metric observability**, crowding / priced-in risk, and **margin-capture clarity** are the dimensions the task names — and states its decision: **promote** (its names enter validation this run), **watchlist** (a still-live hypothesis the graph remembers — Step 3c), or **none**.
   Names are therefore promoted from *strong* hypotheses, not merely interesting narratives.
   The model commits to a hypothesis before it names a ticker; the value-chain trace is the centerpiece, not an afterthought.
3. **Adversarial vetting & promotion** — before a hypothesis's names flow on, the document runs explicit adversarial passes alongside the mandatory bear case, over the route's write-ups and its **disconfirming pass** ([web-research.md §Source quality and evidence weighting](web-research.md#source-quality-and-evidence-weighting)): **why is this already priced?**, **why might the obvious beneficiary be the wrong expression?**, and **who actually captures the margin instead?** — and, for any **feared-loser** name an event-impact route surfaced, the **symmetric pass**: **is the impairment real or panic, and what is the actually-exposed revenue / profit pool?** (the mirror of the beneficiary-side challenge, so an oversold incumbent is promoted as an early-detection candidate only when its real exposure is genuinely narrow, and a truly impaired one is left alone).
   A hypothesis the document **promotes and that survives the adversarial passes** maps to candidate names (resolved against FMP's industry classification / peers); one it does not promote is **recorded in the opportunity graph** (its document section with its appendix fields and the failing pass) rather than forced into a name — a hypothesis decided `watchlist` becomes a **watchlist** node (Step 3c).

The research nests **route ⊃ topic ⊃ pass ⊃ fetch** — a route is worked as one or more **topics** (each its own isolated conversation over a clean context), each topic is a root **pass** plus ≤2 app-governed follow-ups, and each pass is itself a bounded multi-turn loop of web-tool **fetches** followed by its **synthesis write-up** ([web-research.md §The research loop and context management](web-research.md#the-research-loop-and-context-management)).
The two ceilings therefore bind at different levels: **per-topic depth ≤2 (≤3 passes/topic — counting passes, not searches, and not per route)** and a **per-run discovery fetch + wall-clock budget that binds first**, capping fetches across every route, spent in route-priority order, fail-soft on exhaustion — so the discovery research has a hard ceiling and can never run away.
After a route's topics, one **disconfirming pass** runs for the route — a gathering conversation searching for evidence against the route's write-ups so far, then its own synthesis conversation writing its own write-up and asking no follow-up — spent from the same discovery budget and outside any topic's depth, fail-soft to a recorded gap when the budget is exhausted.
The Step-2 house view steers the hunt (aligning it with the current regime / thesis) without confining it.
Search is **keyless SearXNG only** — **no Tavily and no GDELT for discovery**: GDELT's escalating rate-limit / IP-lockout makes it unreliable (the same reason the report job doesn't trust it), and Tavily is **not a discovery dependency**; if SearXNG is unavailable this lane **fail-softs to fewer candidates** rather than falling back to a keyed provider.
The **FMP structured news feeds** (`news/general-latest`, `news/stock-latest`, on the paid key — `news/press-releases-latest` is off-plan, [data-sources.md §FMP — current paid-plan tier audit](data-sources.md#fmp--current-paid-plan-tier-audit)) plus the free-tier **FMP Articles** feed (the shared FMP key) and the macro-release calendar (Step 2) ride each route's gathering brief as **leads** — ticker-tagged, dated headlines with their addresses, what to pursue and never evidence a write-up may rest on ([web-research.md §The research loop and context management](web-research.md#the-research-loop-and-context-management)); the web tool deep-reads what they point at, and provenance rides the page roster.

**The hypothesis-document prompt is sized, and the route's write-ups are distilled only when it is over budget.**
The orchestrator sizes the card-formation prompt — the route's write-ups, the house view, the graph context — against the call's input budget ([configuration.md §Research Context Management](configuration.md#research-context-management-hierarchical-distillation)).
Within budget, the write-ups go in as written.
Over it, the merged write-ups are distilled into one shorter document; where the merged write-ups themselves exceed one distillation call's budget, each write-up is distilled first and the merge of those outputs is distilled again — the two shapes chosen deterministically from size, never by the model, logged to the audit record with the call count, the shared primitive at [portfolio-workflow.md §Step 6d](portfolio-workflow.md#step-6d-consolidation).
The write-ups persist on the audit as written, never as distilled.

**Returns.**

A topic ends with one write-up; the route ends with one per worked topic plus the disconfirming pass's, and they flow whole to card formation.

### Step 3c: Carried-Forward Watchlist Re-check

**Type:** Computed + API retrieval (engine refresh of `structured` / `filing` prints, evidence events) + Local-model call (the watchlist review, thinking; its decisions non-thinking) + a bounded local-model / web-tool refresh for one selected `research`-class node + app-layer promotion.

Discovery is **no longer stateless**.
The persisted **opportunity graph** (loaded at Step 2) carries forward every worthy-but-unpicked candidate from prior runs as a **watchlist node** — its hypothesis document section, the leading metric by name with its re-check class, its status, and its refresh timestamps ([trade-opportunities.md §Discovery memory](trade-opportunities.md#discovery-memory-the-opportunity-graph)).
A node qualifies for the watchlist on typed facts alone — a named leading metric with its class, and a decision of `watchlist`, a `promote` without a validation slot, or an ordinary `gate-reject` at Step 5h (a debut no arm's gate admitted — never a hard-trigger exclusion and never a floor hold-out) — the mechanism and falsifiers living in the document the review reads (the hypothesis section, or the thesis document for a gate-rejected debut).
Whether a gate-rejected debut's thesis is still worth watching is not a question the app can read off its prose; the next run's watchlist review decides it, typed, like every other node's fate.
This closes the silent-loss gap in stateless re-discovery: a deferred name that quietly starts compounding would otherwise depend on chance to re-surface in a later sweep, and there is no promise it would.

Not every leading metric is equally cheap to refresh, so each node's metric carries its **re-check class** — the **canonical three-value vocabulary** (`structured` / `filing` / `research`) this step owns, shared with the opportunity record ([trade-opportunities.md §The opportunity](trade-opportunities.md#the-opportunity)) and persisted as part of the graph / opportunity schema ([storage.md §Local Analysis Suite Storage](storage.md#local-analysis-suite-storage)):
- **`structured`** (revision velocity, relative strength, short interest, earnings surprise) — re-pulled **free every run** from the engine's structured feeds;
- **`filing`** (margins, inventory, or another standardized statement line the engine can extract from the filing-cadence feeds **without a model** — the FMP statement rows; backlog, disclosed outside the standardized statements, is `research`-class) — refreshed on **filing cadence**, not every run;
- **`research`** (product ASPs, channel checks, scuttlebutt with no structured feed) — has no engine re-pull, so it refreshes only through **current web research**: when the name or theme re-surfaces in Step 3b, or through this step's small targeted refresh lane below; absent either, the last observation carries with its original vintage until the node's calendar-time carry horizon elapses.

The class is a **type, not a claim**: the appendix names a `structured` metric from the engine's series menu and a `filing` metric from the standardized statement-line menu, so a metric the engine can refresh model-free is one chosen from a menu, and anything else is `research` by construction ([§Step 3b](#step-3b-model-led-hypothesis-research)).

The step runs in three movements.
First the **engine refreshes** every `structured`- and `filing`-class node's print at its class's cadence (a short-interest metric reads the run's **once-per-run FINRA consolidated file** as a local lookup — one fetch per run, shared with discovery — [data-sources.md §Trade Opportunities — endpoint surface](data-sources.md#trade-opportunities--endpoint-surface)) and collects any **evidence event** tied to a watchlist name — a new item-classified 8-K or a material filing from the shared sweep, the quick check's primitive ([portfolio-analysis.md §The quick check](portfolio-analysis.md#the-quick-check-engine-only)); a failed refresh types that print `unknown`, never a fabricated value.
Then the **watchlist review** — one thinking conversation over every live node — judges each on its hypothesis text, its latest refresh write-up where the lane has produced one, its refreshed prints and its events, and returns a prose review and, by a non-thinking transcription, a typed decision per node: **promote** (the node enters Step 4 as a priority feeder, so a maturing thesis is never missed for want of a fresh trigger), **keep** (carried forward; its refresh timestamp advances only on a successful evidence refresh — a served `structured` / `filing` print this run, or a refresh write-up from the lane — never on the review alone, the review's own date recorded separately), or **retire** (removed from active monitoring, kept in history).
The engine applies only the deterministic rules around the review: a node whose **carry horizon** has elapsed — a configurable cap counted in the leading metric's **own reporting periods**, not runs, cadence-independent by construction since run frequency is user-chosen — retires regardless, and the retention cap below binds at add time; so the watchlist self-prunes and cannot grow unbounded.
Last, the **research-watchlist refresh lane** selects at most the configured small number of `research`-class nodes (drafted **one per DTO run**) for a narrow current-search pass, after the Step-3b routes, from the discovery budget they leave.
Selection is deterministic and priority-ordered: a newly detected filing or material event tied to the node first, then the oldest successful research refresh, then ticker.
The pass is a bounded gathering conversation and a synthesis conversation on the shared loop — it may search for **fresh evidence on the node's named metric and falsifiers only**, not reopen the full per-candidate agenda, revise the thesis, set conviction, or judge the candidate investable — and returns a **refresh write-up** and the same typed decision; a confirmed metric promotes the node into Step 4, a tripped falsifier may retire it, and no result or a failed call leaves it unchanged without advancing its refresh timestamp.
The lane spends from the existing discovery fetch + wall-clock ceiling, never adds unbounded work, and promotion only buys normal Step-4 candidacy — every Step-5 floor, gate and trigger still binds.
It is a discovery refresh, **not a deep re-evaluation**: it never stamps `last_deep_researched_at`, rewrites an opportunity record, clears an attention warning, or archives anything.

## Step 4: Candidate Consolidation

**Type:** Computed (app layer) — a deterministic merge before any per-candidate stage.
No model.

The three feeders' outputs — the bottom-up structured screens (3a), the model-led hypothesis names (3b), and the promoted carried-forward watchlist nodes (3c) — are **deduped** into one candidate list, **sanity-filtered for tradability** (exchange listing, a liquidity / price floor, an instrument-type filter — funds and non-equities drop out, since the job hunts operating businesses by archetype), and each surviving name is **tagged with every signal that surfaced it** (which screen, which hypothesis, the positioning flag, whether it is a maturing watchlist name).
This is the **cross-route / cross-feeder reduce, and it is deliberately deterministic** — distinct hypotheses are never collapsed by a model (which would destroy auditable breadth and could silently drop a name); the only model-side consolidation in discovery is *within* a route's own card formation, where the route's write-ups become one hypothesis document (Step 3b).
The contrast with the per-candidate stage is intentional: Step 5e's analysis *is* a model call because it consolidates one candidate's research into one document, whereas discovery's reduce must keep many distinct candidates and so stays computed here.

The narrowed set is bounded by a **research budget** — a ceiling on how many names get the expensive per-candidate validation in one run — and the budget exists for **compute, not quality**: deep per-candidate web research runs on a local reasoner, so a single run cannot validate the whole universe ([trade-opportunities.md §The pipeline](trade-opportunities.md#the-pipeline)).
Two properties follow, and both matter: the budget is **generous and user-configurable** (Settings → Trade Opportunities discovery breadth — [configuration.md §Local Analysis Suite Configuration](configuration.md#local-analysis-suite-configuration)); and it is **never a quality verdict** — nothing is validated at this point, so a name that doesn't make the cut is **not rejected, only deferred**.
Crucially, deferral is **no longer a coin-flip on re-surfacing**: a genuinely worthy deferral (a hypothesis the document decided `watchlist` or `promote`, with a named leading metric) is **written to the persisted opportunity graph as a watchlist node** and **re-read every later run** by the watchlist review (Step 3c), its leading metric refreshed where a feed carries it, so a deferred name that quietly compounds is caught rather than lost to chance.
This **discovery-memory carry-forward** is distinct from — and upstream of — the *validated* carry-forward (the opportunity matrix reloaded at Step 2 for the Step-7 continuity check).
A name not even worth watchlisting carries no state and is simply re-derivable by a later sweep; the watchlist itself is bounded (the retention cap with its deterministic oldest-refresh-first bind eviction + the review's retirements and the carry horizon, Step 3c), so the store never grows unbounded.

Within that budget the slots are filled **not by a flat top-N**.
There is no universe-wide composite to rank on at this point — the fundamental multi-factor score and the forensic reads are computed per candidate only at Step 5c, on the names that clear this stage — so with bulk pre-scoring off-plan the **stratification itself is the breadth mechanism**: a pure rank on the cheap surfacing signals alone (feeder strength, theme fit, the coarse screener fields) would collapse the funnel onto whatever is loudest (mega-cap momentum, the most-covered AI names, one crowded macro theme) and throw away the breadth that is the job's edge ([trade-opportunities.md §The research method](trade-opportunities.md#the-research-method)).
The slots are therefore filled **under deliberate diversity guardrails**, each a floor-and-ceiling rather than a single ranking:
- **market-cap band** — a **floor for mid- and small-cap** slots so the mega-cap tail can't fill the slate (the enabler the worldview prizes is frequently sub-large-cap), and a **ceiling on mega-cap** names;
- **feeder** — no single feeder (a structured screen, the model-led hypothesis lane, the carried-forward watchlist, a positioning scan) may supply more than a set share, so the narrowed set reflects *converging* signals rather than one loud one;
- **archetype** — each of the five archetypes gets representation up to a cap, so a single archetype (today, ai-infra) can't monopolize the set; since the model-confirmed archetype is not set until Step 5a, the quota uses a **provisional archetype** assigned deterministically here from the cheap classification features already in hand (sector / industry + the Step-4 surfacing tags), with Step 5a's confirmed archetype the authoritative one for 5c–5g;
- **sector / theme** — a per-sector and per-theme ceiling so one crowded macro theme (AI, GLP-1) can't dominate discovery.

Within each axis's floor and ceiling the names are still ranked by **signal strength × house-view fit** (ties resolving by ticker), hypothesis-lane names ranking within their feeder by the model's priority order; the guardrails shape the *composition* of the narrowed set, never relax the per-name bar, and a candidate displaced by a quota is **likewise only deferred** (watchlisted if worthy and re-read next run, else re-derivable), not dropped.
The rounding rule, the relaxation order when a small slate makes the ceilings jointly infeasible, the multi-tag counting rule, and the ranking score's exact formula are **not yet drafted** — marked for the implementation plan's sweep ([trade-opportunities.md §Starting parameters](trade-opportunities.md#starting-parameters-calibratable)).
The result is the narrowed candidate set the expensive per-name loop runs over — the funnel's waist, kept deliberately broad.
None of this caps the *output*: the budget bounds only how many names get **researched** this run; how many **validated** opportunities reach the matrix is set by the gates alone (Step 6).

The budget is **distributed equally across the cap-band × sector buckets** — an explicit allocation rule: equal-per-bucket maximizes breadth, so no single crowded stratum consumes the per-name compute.

**The budget splits three ways — rotation first, new names second, re-surfacers last.**
The feeders surface brand-new names *and* existing live opportunities that re-tripped a feeder.
DTO first spends a **reserved rotation slice** (a configured share, default ~20%, **never rounding below one slot** — [configuration.md §Local Analysis Suite Configuration](configuration.md#local-analysis-suite-configuration)) on live opportunities in **maintenance-priority order**: warning-bearing names first (a tripwire or continuation break must not queue behind an uneventful stale name), then proximity to the next earnings date, then names near the entry-asymmetry threshold, then **stalest by `last_deep_researched_at`**.
A **max-age service level** force-promotes any live name whose research age exceeds the configured bound, whether or not it re-surfaced; ties break by `became_opportunity_at` then ticker — the matrix's self-refresh, so no live name's research can age indefinitely.
DTO then spends the remainder on **new names first** (filled under the diversity guardrails above).
Only **leftover** budget goes to the re-surfaced existing opportunities, ordered by **oldest `last_deep_researched_at`** (the stalest first, same tie-break).
The diversity guardrails scope to the **new-name remainder only**: the rotation slice and the re-surfacer leftover are **maintenance spend, exempt from diversity** — a quota never blocks a warning-bearing or max-age-promoted name (maintenance precedence over discovery diversity — [configuration.md §Local Analysis Suite Configuration](configuration.md#local-analysis-suite-configuration)).
When more live names are overdue than the slice can service, the slice does **not** expand — the overflow forms an **overdue backlog** drained **stalest-first** across successive runs through a **reserved overdue sub-slot**: each run's rotation slice holds at least one slot for the backlog's stalest name, so a fresh warning outranks everything except that reservation and a sustained warning stream can no longer starve the backlog.
The max-age service level is still never a wall-clock guarantee (DTO is user-run, so none is possible), but liveness — no name starved forever — is structural rather than best-effort: the reserved sub-slot drains the finite backlog at one or more names per run, and the run audit plus the pre-run notice surface the **overdue backlog count and oldest research age** so a growing backlog is visible rather than silent.
**All three classes — rotation picks, new names, and budget-winning re-surfacers — enter the same Step-5 validation loop as candidates** (a rotation pick or re-surfacer flagged carried-forward, so Step 5b loads its prior record); a carried name's deep pass therefore runs **in Step 5, before matrix assembly**, not in a separate Step-7 pass.
A re-surfaced existing opportunity that doesn't win a leftover slot is **not researched** — it falls to the Step-7 cheap re-derivation like any other live name, and its re-surfacing raises the attention warning so the user can choose a Deep Audit.
Every ticker DTO deep-researches — rotation, new, or re-surfaced — is recorded in a **run-scoped deep-research set** so Step 7 never also cheap-sweeps it: within a run a ticker is deep-researched **at most once** ([trade-opportunities.md §The two jobs](trade-opportunities.md#the-two-jobs)).

## Step 5: Per-Candidate Validation Loop

Each candidate from Step 4 is processed through the chain below.
Candidates are independent, so the loop **checkpoints per candidate** — each candidate's completed stages persist, so a cancellation or a single model failure resumes the unfinished candidates rather than restarting the (potentially long) run, and recent fetches are cached within a freshness window — the **document-level** cross-run cache: fetched pages reused by normalized URL at their original vintage, searches always run live ([trade-opportunities.md §Failure posture](trade-opportunities.md#failure-posture)).
The resident **122B reasoner fills every model role in this loop** by switching mode (thinking ↔ non-thinking), so moving a candidate across archetype confirmation (thinking), its research passes and write-ups (thinking), distillation (non-thinking, only where over budget — Step 5e), the analysis (thinking), the review (thinking), the thesis document (thinking) and its appendix (non-thinking) pays no model-swap cost ([local-models.md §The model roster and per-task routing](local-models.md#the-model-roster-and-per-task-routing)).
The shared **financial-analysis engine** is the same one Portfolio Analysis uses ([portfolio-analysis.md §The per-holding pipeline](portfolio-analysis.md#the-per-holding-pipeline)); the difference is the **archetype** selects which signals it weights and which valuation lens it applies.
The loop's order is deliberate: the engine and its floor run before any research is spent, the research meets the engine's reads only at the thesis document, and the entry gate runs on both arms after the model has written.

### Step 5a: Archetype Classification

**Type:** API retrieval (FMP classification prefetch) + Computed (deterministic features) + Local-model call (confirmation).
The lens that decides which signals matter for this candidate.

The application first pulls the candidate's **classification subset** — FMP `profile` plus the statement-derived rows the feature extractor reads (income statement and `key-metrics` / `ratios` for margin structure, the annual segment rows for recurring-revenue structure, statement history for cyclicality) — **once per candidate, cached for the run**: Step 5b's dossier reuses these responses, so the rows fire once, never twice ([data-sources.md §Trade Opportunities — endpoint surface](data-sources.md#trade-opportunities--endpoint-surface)).
It then computes the **classification features** — sector / industry, margin and recurring-revenue structure, cyclicality, and the signals that surfaced it (Step 4 tags) — and the reasoner **confirms** one of the five archetypes (secular-compounder / ai-infra / commodity-cyclical / disruptor / quality-compounder).
The confirmed archetype selects the **signal weighting and valuation lens** for 5c–5g ([trade-opportunities.md §Archetype](trade-opportunities.md#archetype--the-lens-that-decides-which-signals-matter)) — e.g. a commodity cyclical is judged on P/B, P/NAV, and mid-cycle EPS with trailing P/E suppressed, while an ai-infra name is judged on segment-revenue acceleration and forward P/E against its revision rate — and informs the engine's horizon rule (its long branch has a compounder-archetype leg — [trade-opportunities.md §Starting parameters](trade-opportunities.md#starting-parameters-calibratable)); the lens's one *target-math* leg is the **archetype driver override** on the shared v2 scenario-target function ([trade-opportunities.md §Starting parameters](trade-opportunities.md#starting-parameters-calibratable)).
Archetype is a first-class dimension (deterministic features, model-confirmed); the deterministic **risk-tier takes no archetype input** — any archetype-tier correlation is emergent through the rule's measurable legs ([trade-opportunities.md §Archetype](trade-opportunities.md#archetype--the-lens-that-decides-which-signals-matter)).

#### Local-model call — Archetype confirmation (Qwen3.5-122B, thinking)

**Model.**
The resident 122B in thinking mode; schema-constrained output, app-checked on type.

**Prompt — input.**
The candidate's classification features and surfacing signals only — a compact, clean context; for a **carried-forward candidate** the prior label beside them.
No web access (this is a classification, not research).

**Returns.**
The **archetype label** under the grammar, plus a short rationale as prose.
The branch is **total — one authoritative archetype always emerges**: the label the model returns stands for 5c–5h, its doubt and any runner-up lens living in the rationale, which rides the audit record only — never a second lens in targets, weights, or gates; a **schema-invalid confirmation or a failed call** adopts the **Step-4 deterministic provisional archetype** as authoritative, flagged and logged, keeping the fallback deterministic rather than model-retried.
For a **carried-forward candidate** the model affirms or overturns the prior label in its rationale, and the prior and current labels both persist on the record, so a lens that churns between passes on a borderline name is visible on the card and the audit rather than policed ([trade-opportunities.md §Archetype](trade-opportunities.md#archetype--the-lens-that-decides-which-signals-matter)).

### Step 5b: Dossier Assembly

**Type:** API retrieval (FMP per-symbol / SEC EDGAR / FINRA / Schwab chains) + Computed (assemble the packet).
No model.

The application builds the candidate's evidence packet deterministically; the Step-5a classification-subset responses are **reused from the run cache, never re-fetched**, and the per-candidate rows fire once.
The **FMP per-symbol surface** on the paid key supplies fundamentals — statements / ratios / key metrics, `financial-scores` for Altman Z + Piotroski, owner earnings, enterprise values, DCF, **multi-year `financial-growth`** per-share CAGRs, and `dividends` (the trailing distributions used as the v2 target function's twelve-month payout proxy, not a forward estimate).
It supplies **product / geographic revenue segments** (annual-only — trajectory context and the engine's segment-acceleration series; [data-sources.md §Trade Opportunities — endpoint surface](data-sources.md#trade-opportunities--endpoint-surface)) and the **analyst / revision signal** (forward estimates snapshotted for velocity, price-target consensus + summary trend, the `grades-historical` rating distribution + consensus, upgrades / downgrades, earnings surprises).
It supplies **symbol-keyed positioning** — insider, **SC 13D / 13G activist filings**, Senate / House congressional; FMP **13F + holder-level analytics are off-plan** → SEC EDGAR 13F or omitted, and held out of the grade until calibrated regardless ([data-sources.md §FMP — current paid-plan tier audit](data-sources.md#fmp--current-paid-plan-tier-audit)).
It supplies **stock peers**, **share float / liquidity**, the **next earnings date** (the rotation slice's proximity key — never an engine-horizon input), the **symbol-scoped structured news** (`news/stock` — the holding's **news leads**, leads never evidence; `news/press-releases` is off-plan, primary-source disclosures via `sec-filings-8k` + web), and **M&A involvement** (acquirer or target — via market-wide `mergers-acquisitions-latest` + `sec-filings-8k`, since the per-symbol `mergers-acquisitions-search` is off-plan; an announced transaction with a dated close is the engine horizon's Short input).
Earnings-call transcript language (backlog / book-to-bill / guidance / supply-discipline) is off-plan on FMP and reaches the model through the Step-5d research lane, never an FMP pull.
That is joined with **SEC EDGAR** (10-K/Q/8-K + XBRL company facts) as the authoritative cross-check — the **item-classified 8-K sweep** the hard-forensic filing kinds read from, an unresolved CIK typing the sweep `unknown`, never a fabricated clear ([data-sources.md §SEC EDGAR](data-sources.md#sec-edgar)); **FINRA** short interest (looked up in the once-per-run file); **FMP** deep price history (dated EOD) and a live **FMP `quote`**; the **Schwab option chain** for the candidate if it is optionable (→ the options-activity signal, computed in 5c); and the Step-2 shared context.
Before research, the app also derives a **limited-history eligibility mode** from objective identity facts — `new-listing`, `spin-off-carve-out`, or `new-economic-perimeter` — only when the candidate's comparable public history is short because that event occurred, never merely because a provider response is missing.
For an eligible candidate the dossier carries the filing identifiers and source plan the reconstruction topic deep-reads (S-1 or Form 10 historicals, carved-out or predecessor segment disclosures, contracts, customer / supplier observations, and dated operational / technical milestones); the model does not choose eligibility, and an ineligible old issuer cannot relabel a data gap as limited history ([trade-opportunities.md §Evidence floor](trade-opportunities.md#evidence-floor)).
For a **carried-forward candidate** (an existing opportunity being deep-re-evaluated — via a DTO rotation-slice pick or leftover-budget re-surface, or an ATO Deep Audit), the dossier carries the **prior record loaded deterministically by lifecycle id**: the prior pass's date and the price then, its thesis document verbatim, its analysis verbatim, its appendix values — tier, horizon, conviction, the three expected prices with their horizon dates, status — its prior archetype, and the lifecycle's accuracy scores from Step 2; a name re-entering from the archive is a new lifecycle and carries none of it ([trade-opportunities.md §Continuity and isolation](trade-opportunities.md#continuity-and-isolation)).
The full input list and every endpoint, with cardinality, is in [trade-opportunities.md §Signal inputs](trade-opportunities.md#signal-inputs) and [data-sources.md §Trade Opportunities — endpoint surface](data-sources.md#trade-opportunities--endpoint-surface).
This is the **per-candidate** surface — the budget driver — so it runs only for the narrowed set, never the discovery longlist.

### Step 5c: Deterministic Analysis (Archetype-Weighted Engine)

**Type:** Computed (the financial-analysis engine, shared with Portfolio Analysis; the evidence floor).
No model.

The engine computes the candidate's quantitative picture, **weighted by the Step-5a archetype** — the archetype selects which sub-scores dominate and which valuation lens applies.
It produces the **multi-factor quant composite**: value / quality anchored on gross-profitability / price + fundamental momentum / low-volatility / revision flow — **computed here for the first time**, since discovery only stratified by coarse fields.
It is built as a **winsorized composite over factor scores normalized against sector-adjusted absolute bands plus the company's own-history distribution**, the sector adjustment keeping the composite from being a disguised sector bet.
It is deliberately **not** a within-cohort rank, because no honest within-app cross-section exists to rank within: a within-run cohort has no statistical mass (the diversity quotas deliberately spread the narrowed set to one-to-three names per bucket), ranking against live peers would multiply the per-symbol call budget by cohort size, and a store accumulated from the names the funnel happened to analyze is a **selected convenience sample, not a market percentile** (discovery surfaces names *because* they are extreme on something).
The persisted **factor-distribution store** (one current observation per issuer per factor, cap-band × sector bucketed, both jobs contributing — [storage.md §Local Analysis Suite Storage](storage.md#local-analysis-suite-storage)) is therefore **diagnostic-only — never a score input** (selection bias doesn't shrink with weight).
It rides the dossier and audit as context once a bucket clears the unique-issuer floor, and graduates into the score only when fed by the representative-universe snapshot.
A composite resting on thin own-history carries a **low-confidence degraded-input flag** — a data-health note the model reads, never a gate ([trade-opportunities.md §Starting parameters](trade-opportunities.md#starting-parameters-calibratable)).
Any per-symbol factor that failed to resolve is **imputed to its band's neutral midpoint** so a missing call can't silently sink a name, and the factors are **integrated at one final composite score** rather than chained hard cutoffs — value and momentum are negatively correlated, so sequential cutoffs would collapse breadth.
The step also produces the **value-creation read**: **ROIC vs cost of capital**, the reinvestment runway *g* ≈ ROIC × reinvestment, owner earnings with **R&D capitalized** so research-heavy names aren't mis-scored, and the moat-source features.
It produces the **leading-metric series** of the archetype's metric family from the structured and filing-cadence feeds — revision velocity, segment-revenue acceleration from the annual segment rows, a commodity-price turn, margin decoupling — and applies the family's **inflecting test** to it where the series is measurable ([trade-opportunities.md §Starting parameters](trade-opportunities.md#starting-parameters-calibratable)); a family that lives only in research — product ASPs, channel checks, net-adds — has no engine series, and its inflection is the thesis document's judgment from the write-ups.
It produces the **earnings surprise / SUE**; **positioning** (insider net, congressional, activist 13D/G, short interest, COT for the cyclical sleeve, and the **options-activity signal** from the Step-5b chain — put/call by volume and open interest, IV/skew; FMP 13F institutional is off-plan → SEC EDGAR or omitted); and scenario **price targets at three months, twelve months and three years** from the **v2 rate-anchored scenario-target function** under the archetype's driver override — the driver ladder off estimates, the `DGS10` spread-anchored scenario multiples ([portfolio-analysis.md §Starting parameters](portfolio-analysis.md#starting-parameters-calibratable), [trade-opportunities.md §Starting parameters](trade-opportunities.md#starting-parameters-calibratable)) — methodology recorded in the typed `TargetMeta` provenance flags, from structured data alone.
It produces a **price-action confirmation read** (relative strength vs the market / sector and proximity to a multi-year base breakout, from the dated-EOD deep history — a confirmer, not a trigger).
And it produces the **three derived reads the interpretation leans on**.
The **narrative-vs-reality ratio** is estimate-revision pace vs multiple change, with the **operating-reality-vs-price** fallback for thinly-covered names whose estimates are absent or stale — both defined in [trade-opportunities.md §The two non-negotiables](trade-opportunities.md#the-two-non-negotiables).
The **forensic flags** are margin compression while revenue accelerates, net-income-vs-operating-cash-flow divergence, receivable / inventory build outpacing sales, plus `financial-scores` Altman Z + Piotroski — the **soft flags**, persisted as engine annotations the thesis document weighs — and the **hard forensic state**, read from the item-classified SEC EDGAR 8-K submissions alone within the drafted lookback: a restatement from an Item 4.02 non-reliance filing, an auditor change from an Item 4.01 filing ([data-sources.md §SEC EDGAR](data-sources.md#sec-edgar)); where the candidate's CIK doesn't resolve (the resolver stays non-blocking here), those legs read **unknown** — a logged degraded input, never a fabricated clear and never a silent no-event.
A fraud allegation has no filing leg: it reaches the model only through the research write-ups and the analysis, as prose it weighs, and never trips the state.
The **implied-expectations read** is the engine's v2 scenario math inverted at the live quote under the archetype's driver override — the driver growth the spot implies across the scenario multiples, the margin dimension where the driver is revenue-based → the **range** of growth / margin trajectories the price *already assumes* under stated assumptions, never one solved number, since many combinations justify a price; methodology recorded, the computed anchor for the thesis document's priced-in / crowding judgment and the adversarial "why is this already priced?" discipline.
It assigns the **engine arm's risk tier** (high / medium / low) deterministically by rule from its measurable inputs (profitability, market cap, liquidity, volatility, leverage, drawdown, event exposure — no archetype term) and the **engine arm's horizon** by the drafted rule over the archetype and the dated transaction events the feeds carry — Short on an announced transaction with a close inside three months, Long for a compounder or a multi-year runway, else Mid — its matched branch persisting as the horizon's derived basis ([trade-opportunities.md §Starting parameters](trade-opportunities.md#starting-parameters-calibratable)); both ride the self-review and thesis-document prompts as computed reads and feed the Step-5h gate's shared legs.
A **tradability flag** (Amihud-style illiquidity + days-to-cover) rides alongside — resolved here into the entry gate's **banded liquidity haircut** (unflagged 0 / flagged −3pts / severely flagged −6pts, the band and its points computed from the flag's own inputs — [trade-opportunities.md §Starting parameters](trade-opportunities.md#starting-parameters-calibratable)) — so a small / illiquid name is flagged and discounted rather than silently excluded.
For a **carried-forward candidate** (one with a prior opportunity record), the engine additionally computes its **since-flagged performance read** — the price legs (running return since it became an opportunity, `became_opportunity_at`, absolute and vs sector / market, and maximum drawdown over that window) from the same dated-EOD history, the continuation state of its metric family where the family is structured or filing class, and the realized block the self-review reads: the price now and its move since the prior pass, each prior expected price's horizon state, and the engine's own composite, targets, tier, horizon, narrative-vs-reality and forensic reads then and now ([trade-opportunities.md §Outcome learning](trade-opportunities.md#outcome-learning-calibration)).

**The evidence floor runs here**, over the same structured data, before any research is spent ([trade-opportunities.md §Evidence floor](trade-opportunities.md#evidence-floor)).
It computes the floor's **freshness states** — `fresh` / `stale` / `freshness-unscorable` per floor-bearing input, from timestamps and cadence against the typed evidence-floor freshness basis ([trade-opportunities.md §Starting parameters](trade-opportunities.md#starting-parameters-calibratable)) — with named gap reasons, so the "stale / conflicting data" hold-out is a deterministic read, never an ad hoc age judgment, and tests the floor-bearing legs: the quote and price history, the measurability and freshness of the engine's metric family where the archetype's tell is structured or filing class, the statements for a proven-economics archetype or the structured operating rows for an emerging-economics one, the `no-admissible-driver` carve-out, and — for an app-eligible new listing or separation — the limited-history branch, which waives the metric leg and asks one full reported period since the event.
Three outcomes follow for a **debut**: a name missing a floor-bearing input or carrying stale or conflicting data is held out as **`insufficient-evidence`** — missing evidence, an abstention rather than a low-conviction guess; a name whose structured metric family is measurable and **not inflecting** is held out as a **story stock** (`no-inflecting-metric`) — the engine's affirmative read, the leading-metric non-negotiable holding before the model is asked; and a name clearing both proceeds to research.
Neither hold-out spends a model call, and neither opens an episode.
For a **carried live opportunity** the floor's missing-evidence reading is an **inconclusive refresh, never a turn-away**: the name holds its last verdict, conviction and matrix identity, a typed refresh gap is recorded, no research is spent, and the pass stamps nothing and clears nothing; whatever engine-only fields this step could compute refresh under the cheap re-derivation's rules ([trade-opportunities.md §Evidence floor](trade-opportunities.md#evidence-floor)).
A carried name whose metric family reads not inflecting is **not** inconclusive: evidence is present, so its deep pass proceeds with the read as an engine annotation — where anchorless `hype` is a hard trigger at Step 5h and a flat metric without `hype` is a read the review and the thesis document must confront.
Everything this step produces is the **engine arm** — the deterministic baseline, carried into Step 5g with its methodology exposed (the `TargetMeta` derivation flags, the driver ladder rung taken, the normalization basis and any neutral-midpoint imputation), so the model can dispute a *derivation* and not merely a number when it writes its own arm ([trade-opportunities.md §The opportunity](trade-opportunities.md#the-opportunity)).
Nothing the model returns downstream alters these values.

### Step 5d: Bounded Web Research

**Type:** Local-model call (122B, thinking) + API retrieval (the web tool), **looped**.
This is the only stage in the loop that itself loops.

The orchestrator assembles a small **agenda** deterministically from the three research lenses of [trade-opportunities.md §The research method](trade-opportunities.md#the-research-method), which the reasoner works **one topic at a time** — **each topic a separate isolated conversation and research loop over a clean context** (the candidate-constant block plus that topic's own questions; no other topic's write-up is fed in), so the local model reasons over a tight prompt, never a sprawling one:
- **leading-metric validation** — confirm the leading metric is real, countable, dated, and inflecting from a third-party source (the mandatory anchor); for a metric the feeds never carry, this topic deep-reads the name's own 10-Q / press-release disclosures and the write-up states each period's **dated, sourced observation**, which the thesis document judges;
- **limited-history reconstruction, when app-eligible** — read the identified S-1 / Form 10 / carve-out / predecessor disclosures and third-party operating evidence, recover dated observations, and state exactly whether each observation is directly comparable, requires a disclosed recast, or is only a proxy; the write-up never treats a customer / supplier proxy as the issuer's revenue or merges unlike economic perimeters, and nothing it recovers enters the engine's series;
- **macro / thematic-fit** — which theme the name rides and where it sits on the S-curve (against the Step-3b hypothesis documents), pure-play vs enabler, bottom-up TAM, and the economist's front-running indicators (capex commentary, book-to-bill, freight, the cycle) the structured feeds don't carry;
- **investor-judgment** — the driving **narrative and market sentiment** (how much of the price is emotion about *what might come* vs present fundamentals), management / capital-allocation quality, and the pre-consensus tells — the candidate's symbol-scoped FMP news (`news/stock`) riding the brief as leads, deep-read on the open web;
- **pattern / case-study** — check the candidate against the early-winner cases and the look-alike failures (the shipped **case library**, its matching cases supplied to this topic's context as structured retrieval, never left to model recall — [trade-opportunities.md §The lenses](trade-opportunities.md#the-lenses)): the recurring early tells (a high-margin segment compounding inside a lower-margin whole, an oligopoly's supply discipline turning, a usage metric inflecting ahead of revenue) against the red-flag set the interpretation discipline enforces;
- **external corroboration** the feeds can't give — customer / hyperscaler capex, supply discipline, transcript backlog / TAM / inflection language, and **DRAM/NAND ASP direction**;
- **mandatory — the contemporaneous bear case** — why the name might fail (the winning traits also rode the famous failures down).

The orchestrator — not the model — owns every request, so the loop has a hard ceiling: **per-topic depth ≤2 (≤3 passes/topic)**, at most 8 accepted tool calls from one gathering turn, an aggregate gathering-history input guard, and a **per-candidate fetch + wall-clock budget that binds first**, spent in topic-priority order (the leading-metric and bear-case topics first, so the bear case is never the topic the budget drops), fail-soft on exhaustion — the lowest-priority topics drop to a recorded gap rather than overrunning the run.
Failed-fetch memory spans all candidates of the invocation, and each automatic retry spends a separate attempt under the same candidate budget ([web-research.md §Failed fetch memory and bounded retry](web-research.md#failed-fetch-memory-and-bounded-retry)).
The **disconfirming-fetch pass** ([web-research.md §Source quality and evidence weighting](web-research.md#source-quality-and-evidence-weighting)) runs **once per candidate, after its topics** — one gathering conversation searching for evidence against the run's write-ups so far, then its own synthesis conversation writing its own write-up and asking no follow-up — spent from the candidate's fetch / wall-clock budget and outside any topic's three-pass depth, fail-soft to a recorded gap when the budget is already exhausted — the same placement Portfolio holds at [portfolio-workflow.md §Step 6c](portfolio-workflow.md#step-6c-bounded-web-research).
The full loop and its bounds are in [web-research.md](web-research.md).

#### Local-model call — Per-candidate research (Qwen3.5-122B, thinking)

**Model.**
The resident 122B reasoner in thinking mode, requesting `web_search` / `web_fetch` tool calls the orchestrator executes (SearXNG-only; SSRF-guarded; untrusted page text inserted as quoted evidence, never as instructions).
**One isolated conversation per agenda topic** (a bounded multi-turn pass loop — [web-research.md §The research loop and context management](web-research.md#the-research-loop-and-context-management)) — topics do not share a context, and each pass's write-up is authored by a **separate synthesis conversation** carrying the gathered evidence and no tools.

**Prompt — input (gathering).**
The initial brief is one message in two parts on the frame every suite prompt shares.
Part 1 leads with the candidate-constant block, so consecutive topic conversations on one candidate share it: the candidate header with the archetype and the analysis date; FETCHED VALUES; NEWS LEADS; on a carried name PRIOR ANALYSIS and PRIOR THESIS, the prior pass's analysis and thesis document verbatim, each with its date and, where a split intervened, its split-context line; and PAGES ALREADY RETRIEVED, the bounded candidate-scoped reuse block.
The topic's own text follows: TOPIC, the topic's questions; on a follow-up pass FOLLOW-UP and WRITE-UP SO FAR; on the disconfirming pass WRITE-UPS SO FAR.
**FETCHED VALUES** is the candidate's fetched data as the providers return it, glossed once and never engine-computed: the profile line (name, exchange, sector, industry); the quarterly statements' headline lines for the latest eight quarters as reported; the annual revenue segments; the forward consensus for the next two fiscal years and the revision snapshot; the last four dividends; the quote with its 52-week range, and the closes on the prior pass's date and three, twelve and thirty-six months back; the 8-K filings of the trailing twelve months by date and item; the latest short-interest print; the positioning rows; the next earnings date; and the `DGS10` and `DGS2` prints.
The engine's reads are **not** in the brief: research fills the gaps the numbers leave, and the engine's reads and the research meet at the thesis document ([§Step 5g](#step-5g-interpretation)).
The same block, byte for byte, leads the synthesis message and the thesis-document message, so the three share one rendering.
Before each gathering request the app appends a short user message stating the replies remaining in this pass; the brief and every previously issued message stay unchanged.
Part 2: what to find, how to weigh a source, the per-reply tool-call bound, and when to stop; where pages are shown it asks the model to read them before searching for the rest.

**Prompt — input (synthesis).**
A fresh conversation, thinking on, no tools, no grammar.
Its first message leads with the candidate header and FETCHED VALUES, then EVIDENCE — every page the pass's gathering conversation carried, the reused pages first, each under the header `web_fetch` gave it — then the topic's own text.
Part 2 asks for the write-up: what the research established on the topic's questions, each figure with the date or period its source gives for it and that source — the page's address, or FETCHED VALUES where the figure comes from there — where pages disagree, and what the evidence leaves unanswered, within the write-up's length band ([portfolio-analysis.md §Starting parameters](portfolio-analysis.md#starting-parameters-calibratable)); on a follow-up pass the topic's write-up rewritten whole with the new evidence folded in.
Its second message asks whether the research has a follow-up question, skipped on the topic's last pass under the depth cap and on the disconfirming pass.

**Returns.**
The gathering conversation returns tool calls, executed by the orchestrator, and ends on a reply with no tool call or at a bound.
The synthesis conversation returns the pass's **write-up** as prose — read as text, validated by nothing — and, where asked, the follow-up question verbatim or the one word `none`, the only reply the app interprets; a question becomes the next pass's question under the depth cap and the budget.
A pass that retrieved no page spends no synthesis conversation and leaves the topic's write-up so far standing.
A topic ends with one write-up; the candidate ends with one per worked topic plus the disconfirming pass's, and they flow whole to consolidation.
Every page shown to the model enters the candidate's **page roster** — address, title, publication date, retrieval time and source tier — persisted on the audit record ([§Step 5h](#step-5h-deterministic-risk-tier-gate-validation--checkpoint)).

### Step 5e: Consolidation

**Type:** Computed (the budget check) + Local-model call(s): the distillation of the write-ups where the analysis prompt is over budget (122B non-thinking; the optional 35B fast tier if resident), then the **analysis** (122B thinking).

The orchestrator first sizes the analysis prompt — the write-ups, FETCHED VALUES and, on a carried name, the prior analysis — against the call's input budget ([configuration.md §Research Context Management](configuration.md#research-context-management-hierarchical-distillation)).
Within budget, the write-ups go in as written.
Over it, the merged write-ups are distilled into one shorter document; where the merged write-ups themselves exceed one distillation call's budget, each write-up is distilled first and the merge of those outputs is distilled again.
The prior analysis is never distilled.
The shape is chosen deterministically from size, never by the model, logged to the audit record with its call count, and sized once more at issue by the adapter seam ([local-models.md §The local-model adapter seam](local-models.md#the-local-model-adapter-seam); the shapes are canonical at [web-research.md §The research loop and context management](web-research.md#the-research-loop-and-context-management)).
This is the *only* place research is condensed, and it condenses write-ups, never already-distilled notes.

#### Local-model call(s) — Distillation (Qwen3.5-122B, non-thinking)

**Model.**
The resident 122B in non-thinking mode by default (no model-swap cost); the fast 35B tier is a benchmark-gated option ([local-models.md §The model roster and per-task routing](local-models.md#the-model-roster-and-per-task-routing)).
A distillation whose rendered prompt outgrows the fast tier's budget issues on the resident reasoner instead, and one over the widest budget is refused before issue ([local-models.md §The local-model adapter seam](local-models.md#the-local-model-adapter-seam)).

**Prompt — input.**
One message in two parts: the candidate header, then the write-ups to distill — the merged write-ups, or one write-up on a per-write-up call — each under its topic's heading; then the task: a shorter document that keeps every dated figure with its source, every disagreement between pages and every open question, within the distillation's length band ([portfolio-analysis.md §Starting parameters](portfolio-analysis.md#starting-parameters-calibratable)).
Consolidation, not new reasoning.

**Returns.**
Prose, read as text and validated by nothing; a length stop at the normal reservation takes one re-attempt at the wider ceiling ([local-models.md §The local-model adapter seam](local-models.md#the-local-model-adapter-seam)).

#### Local-model call — The analysis (Qwen3.5-122B, thinking)

**Model.**
The resident 122B in thinking mode; no grammar.

**Prompt — input.**
One message in two parts.
Part 1, in page order: the candidate header with the archetype and the analysis date; FETCHED VALUES; on a carried name PRIOR ANALYSIS, the prior pass's analysis verbatim with its date and any split-context line; then WRITE-UPS, this run's write-ups — or their distillate — each under its topic's heading, the disconfirming pass's last.
The engine's reads are not here: the analysis adjudicates the research lenses among themselves, and the research meets the engine at the thesis document ([trade-opportunities.md §Reconciling the lenses](trade-opportunities.md#reconciling-the-lenses-the-contradiction-check)).
Part 2 asks for the **analysis**: one document consolidating what this run's research established on the candidate — the leading metric's observed path, the thematic fit, the narrative and sentiment, management, the case-library parallels, the corroboration and the bear case — each dated figure with its source, where the research lenses disagree with each other and where sources disagree, what stays unanswered, and on a carried name what the prior analysis said that this run's research confirms, revises or leaves untouched; a topic with no write-up this run keeps what the prior analysis says about it — the budget exhausted before the topic, the reconstruction topic not eligible — within the analysis's length band ([portfolio-analysis.md §Starting parameters](portfolio-analysis.md#starting-parameters-calibratable)).

**Returns.**
The candidate's **analysis** as prose, read as text and validated by nothing.
It is the only research artifact the next deep pass reads; the write-ups persist on the audit record as written, never as distilled, and no typed research field exists.

### Step 5f: Self-Review

**Type:** Local-model call (122B, thinking), on a **carried-forward candidate only** — a debut has no prior record to review and skips the step.

The reasoner reviews its prior call against what has happened since, before the thesis document is written: the prior placement and conviction, the prior expected prices against the realized path, the falsifiers and triggers the prior document named, and the accuracy record.

#### Local-model call — Self-review (Qwen3.5-122B, thinking)

**Model.**
The resident 122B in thinking mode; no grammar.

**Prompt — input.**
One message in two parts.

### Step 5g: Interpretation

**Type:** Local-model call (122B, thinking) for the thesis document, then a second message in the same conversation (122B, non-thinking) for the typed appendix.
The stage where the model arm is written.

The reasoner interprets the engine's computed analysis and this run's research into the candidate's **two-arm opportunity record** ([trade-opportunities.md §The opportunity](trade-opportunities.md#the-opportunity)).
The engine's deterministic values ride as the **baseline arm**; this conversation authors the **model arm**: the **thesis document**, with its risk tier and horizon, its conviction and its expected price at three months, twelve months and three years stated in words as part of the argument, then transcribed into the **typed appendix** — with the engine's numbers in the prompt as evidence, never as bounds.
The document is written under explicit discipline the task states: **score the conjunction, never a single signal** — base rates are brutal: most stocks underperform Treasuries over their life, and the winner traits recur in losers; **require the leading-metric anchor plus external validation**, and **apply the narrative-vs-reality ratio**; treat **price action (relative strength / base breakout) as a confirmation overlay** that adjusts conviction but never substitutes for the leading-metric anchor; **resolve or discount a research story the engine's lenses don't support** — a quant composite that likes a name whose unit economics don't, a thematic narrative over a failing value-creation read — rather than averaging it away ([trade-opportunities.md §Reconciling the lenses](trade-opportunities.md#reconciling-the-lenses-the-contradiction-check)); run the candidate down the archetype's **track** — *proven-economics* (trailing returns on capital + a margin of safety) or *emerging-economics* (a forward TAM × penetration × margin model clearing a return hurdle) — both passing through the same moat / management / price-asymmetry judgment ([trade-opportunities.md §The research method](trade-opportunities.md#the-research-method)); and for a **carried-forward name**, weigh its **since-flagged performance** the same disciplined way: a gain unmatched by leading-metric progress reads as building multiple-unwind risk and **caps** conviction, a drawdown with the metric intact reads as improved asymmetry rather than a reason to abandon, and a gain **matched** by leading-metric progress is held **neutral — never boosted**, since the confirming metric is already in the engine's composite and crediting the gain on top would double-count it.
Every lever in that paragraph is **prompt-side discipline the task states — not an app clamp**: the app derives no conviction of its own and reads none of the document, so the levers are instructed and human-auditable rather than enforced.
The reasoner reads the engine's numbers as evidence, with their methodology exposed, and authors its own arm beside them rather than echoing them back; where it disagrees with a derivation it says so in the document.
There is **no action call**: the job has no position to act on, the investor profile is absent from every prompt, and the archive decision on a carried name is the status the appendix carries.

#### Local-model call — The thesis document (Qwen3.5-122B, thinking)

Part 1 is inputs only: each data section explained once — what it is and each field's unit or polarity — and then its values, with no instruction in it.
Part 2 is the task only: what the document covers, in order, each item naming the Part 1 section it draws on and restating no value or unit.
The system prompt is the role and the two-part shape of the message.

**Model.**
The resident 122B in thinking mode; no grammar.

**Prompt — input.**
Part 1, in page order: the candidate header with the archetype and the analysis date and FETCHED VALUES; COMPUTED — the engine arm in full: its composite and sub-scores (each axis's polarity glossed once, the imputed-score disclosure where it applies, the thin-own-history flag as a data-health note), the value-creation read, its leading-metric series and the family's inflecting read where the family is structured or filing class, its bear / base / bull targets at three months, twelve months and three years with the typed `TargetMeta` provenance flags rendered so a low-signal band is weighed, not obeyed, its risk tier and its horizon with the horizon's derived basis, the narrative-vs-reality read, the implied-expectations range beside the targets, the hard-forensic filings read as typed evidence with the rule it matched stated as a fact and the soft forensic flags as annotations, the price-action confirmer, the positioning and options-activity reads with their stated conventions, the tradability flag and its haircut band, the floor's degraded-input flags as data statements, the Step-2 context loads where they apply — the sector-matched commodity prints, the CBOE backdrop, the COT row for the cyclical sleeve — and on a carried name the since-flagged read; MARKET ANALYSIS — the house view, rendered as a market-level analysis and never named by product; HYPOTHESIS — the discovery hypothesis document's section this name expresses, verbatim with its date, or the surfacing signal for a screen-surfaced name; ANALYSIS — this run's analysis; and on a carried name REVIEW — this run's review — then PRIOR THESIS verbatim, with any split-context line; the accuracy record rides the review alone ([§Step 5f](#step-5f-self-review)).
The investor profile is absent, as it is from every prompt in the job.
The engine's tier and horizon are shown with the rest of its reads — anchoring is the accepted cost, and the divergence is recorded on every pick ([trade-opportunities.md §The opportunity](trade-opportunities.md#the-opportunity)).
Part 2 asks for one document covering: the directional thesis, firm and specific, and whether this is an early-detection or a continuation idea; the leading operating metric and its trend; why now; the key drivers; the bear, base and bull scenarios, each with the conditions that produce it and the model's probability; the bear case; the falsifiers and triggers in words — each stating a concrete measure, level and period; what the current price already assumes; the risk tier and the horizon, argued from the payoff timing and the measurable risk; the expected share price at each horizon and the conviction, argued in the text; the entry consideration; on a carried name the status — still valid or invalidated — with what changed since the prior document and how the prior read held up, drawing on the review; and the summary paragraph — within the thesis document's length band ([portfolio-analysis.md §Starting parameters](portfolio-analysis.md#starting-parameters-calibratable)).

**Returns.**
The **thesis document** as prose, read as text and validated by nothing, persisted on the opportunity record.

#### Local-model call — The typed appendix (Qwen3.5-122B, non-thinking)

**Prompt — input.**

**Returns.**

### Step 5h: Deterministic Risk-Tier, Gate Validation & Checkpoint

**Type:** Computed (app layer).
No model.

This step is an **app-layer validator and tier-assigner**, not just a recorder:
- the **engine arm's risk tier and horizon**, assigned by rule at Step 5c ([§Step 5c](#step-5c-deterministic-analysis-archetype-weighted-engine)), enter here as the gate's shared legs and the record's baseline pair.
  The **cell reads the model arm's tier × horizon** from the appendix, enum-checked at the transcription, never derived and never bounded — with the engine's pair persisting beside it as the baseline ([trade-opportunities.md §The opportunity space](trade-opportunities.md#the-opportunity-space)).
  Where the model's tier or horizon disagrees with the engine's, the divergence is recorded here — never a validation failure, and never a reason to re-run the call — and rides the card's tag; the prior and current archetype labels are recorded the same way;
- the **entry-asymmetry gate is recomputed and enforced here, deterministically, over the Step-5c engine tier and horizon basis** ([trade-opportunities.md §Starting parameters](trade-opportunities.md#starting-parameters-calibratable) — the thesis document's price-asymmetry discipline is prompt-side framing of this same gate, never its enforcement seam), **run once per arm**: for the engine arm over its **structured twelve-month base target**, and for the model arm over its **appendix's twelve-month expected price**, with every other leg — tier, haircut band, **H** — engine-derived and shared, so the arms differ only in the price each brings.
  The model's authored tier and horizon place the card, never the hurdle, so the model cannot lower its own admission bar.
  **A candidate clearing *either* arm's gate is admitted**, stamped `admitted_by` (`engine-and-model` / `engine-only` / `model-only`), and **both arms' gate legs persist on the run audit** whatever the outcome ([trade-opportunities.md §The opportunity](trade-opportunities.md#the-opportunity) — the either-arm rule).
  The legs: the **tier-scaled base leg** (the run-level `DGS2` plus the engine tier's premium, tested against the post-haircut base-case forward return), the **shape leg** (bear-case downside may not exceed base-case upside — the engine arm's bands alone, the model arm stating no bear price), the **liquidity leg** (the Step-5c banded haircut — unflagged 0 / flagged −3pts / severely flagged −6pts — with the pre-haircut return recorded beside it, so the haircut's own counterfactual stays answerable), and — emerging-economics track only — the **double-over-horizon leg** (required twelve-month base-case return ≥ 2^(12 ⁄ H) − 1, H in months from the engine horizon's derived basis), **the strictest binding**.
  A **debut no arm clears** is **held out as a `gate-reject`**: its thesis document and appendix persist on the audit, Step 7 opens its episode under that class with both arms' prices and adds the name to the watchlist, where the next run's review decides its fate ([trade-opportunities.md §Outcome learning](trade-opportunities.md#outcome-learning-calibration)).
  A **carried** name no arm clears takes the **upside-exhaustion attention warning** instead — never a 5h archive — so Step 6's every-gate-clearer-appears premise is literally true, under the either-arm reading, for debuts and carries alike;
- the **hard triggers** are enforced in the app, not left to the model, and bind absolutely on both arms ([trade-opportunities.md §Evidence floor](trade-opportunities.md#evidence-floor)).
  A **restatement or auditor change** — the item-classified filing kinds from the Step-5c sweep, never a bare model assertion — **excludes a debut outright on both arms** (held out as `excluded`, its episode opened under that class at Step 7) and, on a carried name, **app-forces the status to `invalidated`** — the archival path below, the model's conflicting status persisting as the typed **status-override divergence** `{ model-proposed status, app-forced status, matched hard trigger, filing }` ([trade-opportunities.md §Starting parameters](trade-opportunities.md#starting-parameters-calibratable)), **never the transition's control**.
  **Anchorless `hype`** — the narrative-vs-reality read at `hype` with the archetype's structured metric family measurable and not inflecting — is the second hard trigger on a **carried** name, forcing `invalidated` the same way; a debut with that family read never reaches this step, held out at Step 5c as a story stock before research.
  The soft forensic flags and a `hype` read with an inflecting anchor are annotations the thesis document already weighed; they clamp nothing here.
  A model-only admission cannot carry a name past a hard trigger or the floor;
- a **carried-forward candidate** (an existing opportunity deep-re-evaluated this run — a rotation-slice pick or re-surfacer, or an ATO Deep Audit selection) whose **effective status out of this step** is **`invalidated`** — the appendix's status, or the **app-forced override on a hard trigger** — is **held out of the matrix and flagged for archival** here, so an invalidated carried name never reaches Step-6 assembly; Step 7 then moves it to the archive (this deep pass is the only archival path — [trade-opportunities.md §Archived opportunities](trade-opportunities.md#archived-opportunities));
- the **model arm is checked on type alone**: the appendix's enums, its finite positive prices, its origin-constrained status — the mechanism Portfolio's contract uses ([portfolio-analysis.md §The holding verdict](portfolio-analysis.md#the-holding-verdict)); no engine-relative bound, band, ceiling, or clamp applies to its tier, horizon, conviction, or prices, and the thesis document is persisted exactly as written and validated by nothing;
- there are **no numeric echoes to validate**: engine-owned values (the targets at three horizons, the composite and sub-scores, the tier and horizon, the narrative-vs-reality and implied-expectations reads, the forensic state) are **app-stamped directly onto the record**, and the model returns only its own arm ([local-models.md §Context-memory discipline](local-models.md#context-memory-discipline));
- the surviving candidate's record is persisted — the engine arm app-stamped, the model arm as written and transcribed, the admission provenance, the divergences — with its audit record: the write-ups as written, the distillation shape and call count, the analysis, the review, the page roster, the research gaps, the engine's computed reads, the prior and current archetype, the model ids and the prompt stamp ([storage.md §Local Analysis Suite Storage](storage.md#local-analysis-suite-storage)); and the candidate is **checkpointed** so the run can resume here.

## Step 6: Matrix Assembly

**Type:** Computed (app layer).
No model.

Each survivor's **cell is already fixed** — the model arm's tier × horizon from its appendix, enum-checked at Step 5g — so this step chooses neither *which* opportunities appear nor where; it orders them.
Within a cell the order is deterministic: by **conviction level** (high before medium before low), then by the **model arm's twelve-month upside** — its appendix's twelve-month expected price against the live quote — descending, then by ticker for a stable order.
**Every Step-5h survivor appears in its cell** — a name either arm admitted is listed, and nothing collapses two names into one: names that express the same discovery hypothesis are **linked** through their hypothesis node and shown as such on their cards ([trade-opportunities.md §Discovery memory](trade-opportunities.md#discovery-memory-the-opportunity-graph)), never merged, so breadth and auditability survive and completeness holds by construction rather than by validation.
**This assembly covers this run's survivor set only — the matrix is final only after Step 7**, which inserts the still-valid carried opportunities the cheap sweep refreshed into the same order ([§Step 7](#step-7-continuity-check--carry-forward)).
There is **no per-cell output cap**: the gates set a cell's count, not a quota, so a cell holds as many or as few validated ideas as qualify.
**A cell may be empty** when nothing qualified — honest, not a failure — and the matrix never pads itself to fill them ([trade-opportunities.md §The pipeline](trade-opportunities.md#the-pipeline)); equally, a rich cell that genuinely earned many anchored ideas is never trimmed to a fixed number.

## Step 7: Continuity Check & Carry-Forward

**Type:** Computed + API retrieval (cheap-sweep re-pulls) — an **app-layer validator**, not just a recorder.
No model: the rotation picks' and re-surfacers' deep passes already ran in the Step-5 loop, so this step only reconciles their verdicts, cheap-sweeps the rest, archives, and opens this run's episodes.

Prior opportunities (from the Step-2 prior run) are reconciled with this run's matrix at the opportunity-list level.
DTO splits the carried matrix **by cost**, and the dividing rule is that **only a deep pass can archive** ([trade-opportunities.md §Archived opportunities](trade-opportunities.md#archived-opportunities)):
- every opportunity carried forward keeps its identity and gets an **updated status** — a debut enters app-stamped `new`, while a carried name's deep pass states `still-valid` or `invalidated` in its appendix (the origin-constrained enum, Step 5g), what changed argued in its thesis document.
  There is **no "target met" exit** — an opportunity persists while it still clears re-evaluation, however far its price has run; only a **deep** re-evaluation that judges it no longer an opportunity ends it (it then leaves the matrix for the **archive** — [trade-opportunities.md §Archived opportunities](trade-opportunities.md#archived-opportunities));
- **the rotation picks and re-surfacers were already deep-re-evaluated in Step 5.**
  An existing opportunity that won a deep pass this run — a **rotation-slice pick** (maintenance-priority, Step 4) or a re-surfacer that won leftover deep-research budget (Step 4) — ran the **full Step-5 loop as a carried-forward candidate** (its prior record carried in deterministically, Step 5b), so its fresh verdict is already in hand here — Step 7 does **not** re-invoke the loop.
  That Step-5 deep pass is the **only path in DTO that can judge a name `invalidated` → archive** (a qualitative erosion the cheap read can't see, or a deterministic exhausted-upside / continuation-failure finding *confirmed* under fresh research).
  A still-valid result reconciles into the matrix; an `invalidated` one was **held out at Step 5h** and is **moved to the archive here**; an **inconclusive** one (the deep re-read fell below the evidence floor at Step 5c — [§Step 5c](#step-5c-deterministic-analysis-archetype-weighted-engine)) reconciles on its **prior verdict** with its typed refresh gap, treated by this step exactly like a cheap-swept carry — its freshness never advanced, so it stays rotation-eligible ([trade-opportunities.md §Evidence floor](trade-opportunities.md#evidence-floor)).
  Every such ticker is in the **run-scoped deep-research set**, so the cheap sweep skips it;
- **every other live opportunity gets the cheap re-derivation, which never archives.**
  For each carried opportunity **not** in the deep-research set the engine (off-budget, no model) re-pulls price + estimates — and, on the **filing-cadence rider**, a fresh filing's statement-derived rows ([data-sources.md §Trade Opportunities — endpoint surface](data-sources.md#trade-opportunities--endpoint-surface)).
  It **re-derives the scenario targets** (Step 5c) from structured data, **re-runs the full entry-asymmetry gate on both arms** against the live price, every recomputable leg live — the refreshed engine tier, fresh `DGS2`, the banded liquidity haircut from live tradability inputs, the emerging leg's H re-read from the persisted horizon basis (a transaction close's months-to-date remeasured).
  The model arm needs **no model call here**: its twelve-month expected price is a frozen number from the last deep pass, so the engine re-measures the live price against it exactly as it does its own — and it **does not decay**, since a dated judgment is not a stale prop (its age is carried by the `Research stale` badge).
  It then **re-derives the engine risk tier** (a gate leg and the card's baseline read — never the cell, which is the model's frozen placement), refreshes the engine metric family's continuation state where the family is structured or filing class, and refreshes the since-flagged read — but it **never archives, never re-rates a survivor, and never re-places a card**.
  The model-authored fields — the thesis document, the placement, the conviction, the expected prices, the detection mode, the leading metric, the status — hold their last deep-pass values.
  When it detects **exhausted upside** (**neither arm's** re-derived base case still clears the entry gate — while either does, the divergence is recorded and no warning fires, mirroring the either-arm admission rule) or a **tripwire** (a forensic flag newly tripping, a **continuation-failure signal** — estimate revisions rolling over, a beat-and-raise streak breaking, shipments diverging below sell-through — a since-flagged gain diverging hard from the engine family's continuation, the narrative-vs-reality read crossing into `hype`, a margin-of-safety compression near the exhaustion line, or a drawdown breach — [trade-opportunities.md §The opportunity](trade-opportunities.md#the-opportunity)), it raises the deliberately **high-bar attention warning** on the card — *consider a Deep Audit* — rather than acting.
  The next **floor-clearing** deep pass (a rotation-slice pick, a later re-surface, or an ATO Deep Audit) clears it; an inconclusive below-floor re-read leaves it standing ([trade-opportunities.md §Evidence floor](trade-opportunities.md#evidence-floor)).
  Both readings are **fail-soft**: a *missing* input holds the opportunity on its last verdict, never an escalation; only an *affirmative* signal **confirmed under a deep pass** ends an opportunity;
- **final matrix assembly happens here, over the union.**
  Step 6 assembled this run's survivor set only ([§Step 6](#step-6-matrix-assembly)); this step completes the matrix by **inserting each still-valid carried opportunity in its held cell** — the model arm's frozen tier × horizon; only a deep pass re-places — in the same deterministic order (conviction level, then the model's twelve-month upside against the live quote, then ticker), computed-only, no model re-orders anything.
  The refreshed engine tier persists beside the placement as the baseline; a newly disagreeing pair surfaces through the divergence tag, never a moved card.
  Every Step-5h survivor is in its cell and every still-valid carry is in its held cell by construction — there is no model step that could have dropped one;
- the pass then **opens this run's episodes** in the **episode store** ([trade-opportunities.md §Outcome learning](trade-opportunities.md#outcome-learning-calibration)): one for every candidate whose appendix carried prices this run and that has none, or whose latest episode is a month or more old (Portfolio's cadence — [portfolio-analysis.md §Starting parameters](portfolio-analysis.md#starting-parameters-calibratable)) — a pick under `picked`, a debut no arm admitted under `gate-reject`, a debut a hard trigger excluded under `excluded` — recording the symbol and lifecycle, the decision class, the creation date, the spot that day and the anchor close that bridges the record across a later split, the model's expected price at three months, twelve months and three years, and the engine's base value at the same horizons.
  An `insufficient-evidence` or story-stock hold-out has no prices and opens none, a carried name's inconclusive re-read opens none, and a watchlist node opens none.
  The checks on the episodes already in the store ran at [§Step 2](#step-2-load-shared-context), before discovery, so this run's reviews read them.
  Episodes are never updated otherwise and never deleted, and the store persists independently of run retention, the archive and matrix presence; the accuracy scores derived at Step 2 persist with the opportunity, render on its card, and ride the self-review alone ([§Step 5f](#step-5f-self-review));
- the **since-flagged read** is refreshed for every carried-forward opportunity — its price-derived parts (running return since `became_opportunity_at`, absolute and vs sector / market, and maximum drawdown) from the same daily-bar reconstruction, the engine metric family's continuation state from its structured or filing path — **live from the idea's first subsequent run** (its first continuity pass after being added — a debut pick has no elapsed window yet), so the matrix display ([trade-opportunities.md §Storage and display](trade-opportunities.md#storage-and-display)) and the self-review of a carried-forward name read the same numbers;
- the **opportunity graph is reconciled in the same pass** — this run's picks link to their matrix entry, this run's hypotheses decided `watchlist` (and `promote` without a slot) are added or refreshed as **watchlist** nodes with their document sections and appendix fields, and every ordinary `gate-reject` debut — researched, no arm's gate admitting it, no hard trigger and no floor hold-out — is added or refreshed as a watchlist node too, carrying its thesis document as its text and its appendix's leading metric and class, the next run's review deciding whether it stays (its forecast scored separately on its `gate-reject` episode), nodes the watchlist review retired or whose carry horizon elapsed are **retired** (Step 3c), and a deeply invalidated pick's node moves to **`departed`** in the same pass as its archival — a terminal tombstone, visible in route context as a dead thesis but never a discovery feeder and never re-promotable in place; a genuine re-entry opens a new node under a new lifecycle ([trade-opportunities.md §Discovery memory](trade-opportunities.md#discovery-memory-the-opportunity-graph)) — so the discovery memory stays current and bounded alongside the validated matrix.

Output stays **firm and does not churn** between runs absent hard data ([thesis-continuity.md](thesis-continuity.md)) — an idea persists with an updated status rather than silently reappearing or vanishing.

An `invalidated` opportunity is **moved to the archive** rather than dropped — the job's price-tracked record of departed picks, bounded to the most recent 100 ([trade-opportunities.md §Archived opportunities](trade-opportunities.md#archived-opportunities)).
The archive is **distinct from the opportunity-graph `retired` nodes** above: the graph retires *upstream discovery hypotheses* (worthy-but-unpicked watchlist names), while the archive holds *downstream validated picks* that left the matrix — whose own graph nodes take the terminal **`departed`** status in the same pass ([trade-opportunities.md §Discovery memory](trade-opportunities.md#discovery-memory-the-opportunity-graph)).
An archived pick keeps only the **price-derived part** of the since-flagged read refreshed each run — return vs sector / market and drawdown, **not** the metric family's continuation (which would need a structured re-pull) — the same stateless reconstruction, no deep research, no model call; its episodes keep maturing in the episode store, scored by the Step-2 checks at their horizons; if a later run **independently re-discovers** it, it is a **fresh** opportunity (new `became_opportunity_at`, a new lifecycle, removed from the archive) and none of the archived record influences the new one.

## Step 8: Holdings Cross-Reference

**Type:** Computed (app layer) + API retrieval (the fresh Schwab holdings pull, fail-soft) — a deterministic post-step.
No model.

After selection and continuity, the application flags any opportunity that **overlaps the user's current holdings** (owned / not-owned), reading only a holdings list **pulled fresh at this step** — the run's sole holdings consumer, so the tags are current rather than hours stale by the end of a long run — and **never** Portfolio Analysis's stores.
The pull is **fail-soft** (the cross-reference is display-only): a failed pull falls back to the most recent persisted holdings snapshot, the tags labeled with its captured-at date, or — with no snapshot — omits the owned-tags as a typed gap; it never fails the run ([schwab-integration.md §Failure posture](schwab-integration.md#failure-posture)).
Crucially this runs *after* discovery and selection, so holdings **never influence which opportunities are found or chosen** ([trade-opportunities.md §Holdings cross-reference](trade-opportunities.md#holdings-cross-reference)); the job stays genuinely independent of the account, surfacing an already-held idea as such only for the user's awareness.

## Step 9: Persist Run and Audit

**Type:** Computed (persist the matrix and audit record).
No model: the job writes nothing to vector memory, a carried name's continuity being the deterministic load of its own prior documents ([local-models.md §Run history and continuity](local-models.md#run-history-and-continuity)).

The application persists the run: the **3×3 matrix** of opportunities, and the **run audit record** that makes the run traceable.
The audit record carries sources and retrieval timestamps; the discovery and screening inputs — the route plan with its coverage-rotation selections and completions, each route's hypothesis document and appendix with the route's write-ups and page roster, the watchlist review and its decisions, and the refresh write-up where the lane ran; and, per candidate, the write-ups as written, the distillation shape and call count, the analysis, the review, the page roster, the research gaps, the engine's computed reads with their provenance flags, the thesis document and the appendix values, the admission provenance with both arms' gate legs, the recorded **divergences** (the prior and current archetype, the tier / horizon pair) and any status-override divergence, the floor's hold-out reasons and freshness states, the cheap sweep's warnings, model ids and quantizations, and the prompt stamp.
The field set is specified once in [storage.md §Local Analysis Suite Storage](storage.md#local-analysis-suite-storage).
The **opportunity graph** (the discovery memory — hypothesis nodes with their documents and appendix fields, and company nodes with their status, leading metric, refresh timestamps and hypothesis link) and the separate **discovery-coverage ledger** are persisted alongside, carried into the next run's Step 2.
The **archive of departed picks** is the persisted fourth store — after the matrix, graph, and coverage ledger — the most recent 100 opportunities a `failed-reevaluation` removed from the matrix, each a frozen verdict snapshot, with the since-flagged read recomputed statelessly rather than stored ([trade-opportunities.md §Archived opportunities](trade-opportunities.md#archived-opportunities)).
The **episode store** completes the **five persisted structures**, independent of run retention ([storage.md §Local Analysis Suite Storage](storage.md#local-analysis-suite-storage)).
Retention keeps the last N runs ([storage.md](storage.md)).

## Step 10: Generate Trade Opportunities Page and Update UI

**Type:** Computed (frontend).
No model.

The **Trade Opportunities page** renders the 3×3 matrix — high-, medium-, and low-risk sections, each containing short-, mid-, and long-term ideas — every card placed by the **model arm's** tier × horizon, the engine's pair riding the expand view as the baseline.
Each cell lists its opportunities with archetype, the thesis document's summary, leading metric, detection mode, conviction, and the **expected price at twelve months beside the engine's base target** (the three-month and three-year pairs on expand).
The **model arm's** conviction and twelve-month price headline the card, with a quiet **divergence tag** where the arms materially disagree, the paired engine / model view on expand — the three price pairs, the engine's bands and provenance flags, its tier and horizon, and the **accuracy scores** for both arms — and the `admitted_by` tag making an either-arm admission legible ([trade-opportunities.md §Storage and display](trade-opportunities.md#storage-and-display)).
The card also carries the narrative-vs-reality read, status, the hypothesis it expresses (linking the names that share one), its **`became_opportunity_at` and `last_deep_researched_at` dates**, the **since-flagged performance read** for carried-forward ideas (return since it became an opportunity, vs sector / market, with a compact running curve and maximum drawdown), and the owned/not-owned flag, with empty cells shown as empty.
A separate **Archived opportunities** view lists departed picks with their frozen record, departure date, and live since-flagged return — price-only, **no forward prediction** ([trade-opportunities.md §Archived opportunities](trade-opportunities.md#archived-opportunities)) ([interface.md](interface.md)).
The page also carries the **two jobs' controls** — a **Discover** button (DTO) and a selection-gated **Audit** button forking to **Quick Audit** / **Deep Audit** (with a confirmation on a large Deep-Audit selection) — and renders each card's lifecycle affordances: the **selection control** (plus select-all / deselect-all), an amber **Consider Deep Audit** badge when the attention warning is set, a green **Deep-researched today** badge when `last_deep_researched_at` is the current local-timezone day, and a quiet **Research stale** badge when the last deep pass is older than the ~4-week freshness window.
The page also carries a **Matrix / List view toggle**: the 3×3 matrix is the default and canonical view, while **List** flattens all nine cells into one sortable `.ana-grid` ranking (each row keeping its placed model-arm risk tier and horizon, selection control, and badges), sortable by **forward % upside to target** (default, descending — the model arm's twelve-month expected price against the cached close, matching the card's headline, with the engine's riding its own sortable column) or **realized since-flagged return** (the alternate; a debut pick with no since-flagged read sorts last), and carrying engine-target / model-target / divergence columns where the pairing is native — a display-only reordering ([trade-opportunities.md §Storage and display](trade-opportunities.md#storage-and-display)).
The **price-derived** since-flagged read on each card is **re-derived at render** from the **per-ticker daily-bar cache** (lazy, fail-soft refresh per the shared cache's rule — [storage.md §Local Analysis Suite Storage](storage.md#local-analysis-suite-storage); no per-render fetch — the daily refresh is the cache's own FMP dated-EOD request) as a freshness floor, so a card's performance number is current even when no job has run since the last matrix write ([trade-opportunities.md §Storage and display](trade-opportunities.md#storage-and-display)); the engine family's continuation state and the live FMP-quote-based gate read refresh only when a job runs.
While a job ran, the run tracker replaced the page (latest-run-only); on completion the page shows the persisted matrix.
A **run is never a report**: the matrix appears only on persisted success, so a cancel or failure removes nothing ([run-tracking.md](run-tracking.md)).

## ATO: the audit flow

**Audit Trade Opportunities** is the user-directed maintenance job ([trade-opportunities.md §The two jobs](trade-opportunities.md#the-two-jobs)).
It has no discovery: the user selects one or more **existing** matrix opportunities and chooses **Quick Audit** or **Deep Audit**; the job re-evaluates exactly that selection, reusing DTO's stages, and re-renders.
It holds the **same single global run slot** and clears the **same presence gate** as the other local jobs ([§Step 1](#step-1-job-start-and-gate)).
The fork differs only at the **run-gate connectivity** layer: **Deep Audit** clears the full Step-1 gate (daemon reachable + the reasoner pulled, since it makes model calls), while **Quick Audit** is engine-only and **skips the daemon-connectivity check**, so it runs even when the daemon is configured-but-down; its cheap re-derivation reads no Schwab data (the options signal is held out of the grade), though the Schwab connection stays a presence precondition (see step 2).

1. **Gate, load & the accuracy checks (Steps 1–2, reused).**
   The execution gate is uniform on **presence** and fork-aware only on **run-gate connectivity** (above); the **Step-2 shared-context load** runs as in DTO (house view, run-level FRED / FMP-commodity / CFTC / CBOE, the prior matrix and opportunity graph — Quick Audit loads only the subset its engine pass needs — the FRED rate anchors (the `DGS2` entry-threshold print and the `DGS10` the v2 scenario multiples re-anchor on, both under the quick-path cached-print rule — [trade-opportunities.md §Failure posture](trade-opportunities.md#failure-posture)) and, **conditionally, the once-per-run FINRA consolidated short-interest file** when a selected name's engine metric family reads short interest, a failed file fetch typing that read `unknown` ([data-sources.md §Trade Opportunities — endpoint surface](data-sources.md#trade-opportunities--endpoint-surface))).
   The **accuracy checks** run in both modes over every due episode in the store — not only the selected names — since they are engine-only ([§Step 2](#step-2-load-shared-context)).
   The selection is the work-list; **no discovery feeders run**.
2. **Quick Audit — the engine-only cheap re-derivation (no model).**
   For each selected opportunity the engine runs the **same cheap re-derivation Step 7 applies to the DTO matrix tail**.
   It re-pulls price + estimates and re-derives the scenario targets: the v2 multiples re-anchored closed-form on the fresh `DGS10` against the stored anchor-window percentiles and drivers — the same quick-path basis as Portfolio's quick check ([portfolio-analysis.md §The quick check](portfolio-analysis.md#the-quick-check-engine-only)) — from structured data alone.
   It **re-runs the full entry-asymmetry gate on both arms** — the engine's live targets and the model's frozen twelve-month expected price, which needs no model call to re-measure against the current price.
   It refreshes the engine metric family's continuation state and the since-flagged read.
   As an engine-only quick path it holds the suite's rate-anchor quick-path rule: a failed FRED retrieval **fail-softs to the last cached print with its as-of date, eligible only within the shared rate-cache max age** — older, or no cache, types the rate-dependent reads `unknown` rather than computing off a stale anchor ([portfolio-analysis.md §Starting parameters](portfolio-analysis.md#starting-parameters-calibratable)).
   It **never archives** — an exhausted-upside or tripwire reading (a continuation-failure signal among the tripwires) raises the **attention warning** ([trade-opportunities.md §The opportunity](trade-opportunities.md#the-opportunity)) on that card.
   It never re-places a card either: the cell is the model arm's frozen tier × horizon, and the refreshed engine tier updates only the baseline read beside it.
   This path makes **no model call**, so it cannot fail on research and it is fast — and because it needs no model at runtime, it **skips the run-gate daemon-connectivity check**, so a Quick Audit runs even when the Ollama daemon is **configured-but-down** (the uniform presence gate still applies — [§Step 1](#step-1-job-start-and-gate)).
   Its cheap re-derivation reads no Schwab data (the **options-activity signal is held out of the grade** and isn't an input), needing only FMP / FRED — plus the stage-1 **conditional FINRA short-interest file** where a selection's metric family requires it — at runtime **for the analytical pass**; the run's one Schwab touch is the closing Step-8 holdings cross-reference, a fail-soft, display-only pull outside the re-derivation ([§Step 8](#step-8-holdings-cross-reference)).
   (If the options signal is ever calibrated *into* the grade, that's a deep-pass input regardless, so this stays correct.)
3. **Deep Audit — the full Step-5 loop.**
   For each selected opportunity the job runs the **Step-5 per-candidate validation loop** (5a archetype → 5b dossier, the prior record loaded by lifecycle → 5c engine and floor → 5d research → 5e consolidation → 5f self-review → 5g interpretation → 5h validate).
   It rewrites the model-authored fields — placement included: a freshly written thesis document and appendix re-place the card — stamps `last_deep_researched_at`, and **clears any attention warning** — all contingent on the pass **completing past the engine floor**: a selected name whose re-read fails the floor at Step 5c holds its last verdict under the evidence floor's carried-name rule before any research is spent ([trade-opportunities.md §Evidence floor](trade-opportunities.md#evidence-floor)) — no stamp, no warning clear.
   It is the **only** ATO path that can judge a selected name `invalidated` → archive.
   A **large selection prompts a confirmation first**, since it runs the loop per name (potentially long), in the spirit of the SearXNG pre-run consent ([web-research.md](web-research.md)).
4. **Continuity, persist & render (Steps 7–10, reduced).**
   The audited records are reconciled into the matrix in the deterministic order; an `invalidated` Deep-Audit result moves the name to the **archive**, and that archival write **atomically takes the touched picked node to `departed` under the same lifecycle id** — the same-pass transition every deep-invalidation archival carries, status semantics canonical in [trade-opportunities.md §Discovery memory](trade-opportunities.md#discovery-memory-the-opportunity-graph).
   A Deep Audit **opens episodes** for the names it touched under Step 7's cadence — a pick whose latest episode is a month or more old, or which has none — with the prices its new appendix carries; a Quick Audit opens none, its model fields unchanged.
   The opportunity graph sees **no discovery-wide rebuild** (no discovery ran — no watchlist adds, no review retirements): the touched picked nodes' lifecycle transition above is its only mutation; the holdings cross-reference (Step 8) re-runs only over the touched names, the run + audit record persist (Step 9), and the page re-renders (Step 10) as for DTO.
   ATO's depth is bounded by the **user's selection**, not the DTO deep-research budget.
