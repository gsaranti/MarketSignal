# Trade Opportunities

Trade Opportunities is a **local feature on a single page, driven by two on-demand jobs**: **Discover Trade Opportunities (DTO)** finds brand-new investment ideas through deep web research and hard data analysis, organizing them across a fixed risk-by-horizon matrix grounded in the current Market Signal house view; **Audit Trade Opportunities (ATO)** re-evaluates the existing matrix opportunities the user selects.
Like Portfolio Analysis both run entirely on local models (see [local-models.md](local-models.md)) and are **prescriptive and firm**; unlike it, neither is **tied to current holdings** — the purpose is to discover and maintain new opportunities.
Both **require a connected Schwab account**, whose option chains supply the per-candidate options-activity signal (see [schwab-integration.md](schwab-integration.md)).

One invariant frames the whole lifecycle and is worth stating up front: **only a deep re-evaluation can archive an opportunity.**
The cheap re-derivation — engine-only, run on every live opportunity DTO doesn't deep-research, and offered on demand in ATO — refreshes the quant read and *flags* a name for attention, but it can **never** archive one; deep research is the sole destructive path.
This is what lets the cheap pass run liberally over the whole matrix while the consequential action stays gated (see [§Archived opportunities](#archived-opportunities)).

## What the job hunts

The goal is profit: ideally **finding a name before it moves**, but also **catching a move early enough that even a "late" entry compounds** (a memory-cycle or AI-infrastructure name six months into its run still returned multiples).
These are two distinct detection problems, and the job runs **both modes**:

- **Early detection** — a *leading operating metric inflecting before the income statement and before the multiple re-rates*, while a live bear narrative still suppresses the price (e.g. a high-margin segment re-accelerating at a depressed multiple; a free-cash-flow turn while the market prices bankruptcy; a first surprise profit into a crowded short).
- **Continuation** — *demand-visibility signals* that license buying a move already underway: an estimate-revision and beat-and-raise streak, a guidance step-change far above consensus, rising backlog / book-to-bill, corroborating customer (hyperscaler) capex, or a commodity contract-price turn with supply still constrained.

The discipline that separates a real opportunity from a chased story is **the leading-metric anchor**: a candidate's narrative must be tied to a *countable, dated, third-party-verifiable* number that is moving — not the story alone.
A narrative with no inflecting operating metric behind it is a story stock, and is rejected.
This is the same data-honesty stance as the report's evidence floor and the suite's compute-don't-guess rule ([local-models.md §Context-memory discipline](local-models.md#context-memory-discipline)), applied to discovery.

## The two jobs

Both jobs are **manual**, run in the run tracker, and share the **single global run slot** with the report and Portfolio Analysis — only one runs at a time across the app (see [local-models.md §Failure posture](local-models.md#failure-posture), [run-tracking.md](run-tracking.md)).
They run under one **`trade_opportunities` job identity** — each run record carries its **mode** (`discover` / `audit-quick` / `audit-deep`) — so run history and retention are one pool, and the page footer's last-run stamp reports the latest run of either job, mode-labeled ([scheduling.md §Job Status Visibility](scheduling.md#job-status-visibility)).
They share one page (the 3×3 matrix and the archive) and split the lifecycle by purpose:

- **Discover Trade Opportunities (DTO)** — the generative job, triggered by a single **Discover** button, with per-cell progress in the run tracker.
  It runs the full discovery funnel ([§The pipeline](#the-pipeline)) and **deep-researches the discovered candidates** under one compute budget.
  A **small reserved rotation slice** goes first (configurable, default ~20% of the budget, never rounding below one slot), spent on live opportunities in **maintenance-priority order**: warning-bearing names first (a tripwire or continuation break shouldn't queue behind an uneventful stale name), then proximity to the next earnings date, then names near the entry threshold, then stalest by `last_deep_researched_at`.
  A **max-age service level** backstops that order, force-promoting any live name whose research age exceeds the configured bound, whether or not it re-surfaced — an overdue overflow forming a stalest-first backlog drained through the slice's **reserved overdue sub-slot** (at least one slot per run), its count and oldest age surfaced ([trade-opportunities-workflow.md §Step 4](trade-opportunities-workflow.md#step-4-candidate-consolidation)), so no name's research ages indefinitely (the matrix's self-refresh).
  **New names** come first in the remainder, with any **leftover budget** spent on existing opportunities that re-surfaced through discovery (oldest-deep-researched first).
  It then **cheap re-derives every other live opportunity** so the whole matrix is refreshed each run.
  Deep research is the only path that archives; the cheap sweep only raises warnings.
  A candidate that resolves to a name **already live** in the matrix is reconciled against the existing record rather than re-discovered blind (the re-surface either earns a leftover-budget deep pass or falls to the cheap sweep); a candidate matching a **departed (archived)** ticker is a fresh re-entry ([§Archived opportunities](#archived-opportunities)).
- **Audit Trade Opportunities (ATO)** — the maintenance job, **user-directed**.
  The user **selects one or more existing opportunities** on the matrix (per-card selection plus select-all / deselect-all), which enables the **Audit** button; clicking it opens a two-option fork — **Quick Audit** (the cheap re-derivation) or **Deep Audit** (the full deep re-evaluation).
  Quick Audit refreshes the quant read and may raise a warning but never archives; Deep Audit is the manual route to a fresh deep pass and can archive.
  A large Deep-Audit selection prompts a confirmation first (it runs the per-candidate loop on every selected name — potentially long), in the same spirit as the SearXNG pre-run consent ([web-research.md](web-research.md)).

The **cheap re-derivation** and the **deep re-evaluation** are the same two engine/model paths in both jobs — DTO invokes them automatically (cheap on the matrix tail, deep on discovered candidates), ATO on the user's selection.
Within a single DTO run a ticker is deep-researched **at most once**: a name deep-researched as a discovered candidate is never also cheap-swept, and a re-surfaced name that won a deep pass is not re-derived again.

## The opportunity space

Output is organized as a **3×3 matrix**: three **risk tiers** (high / medium / low) × three **horizons** (short / mid / long term) = nine cells, each holding **however many opportunities clear the gates, ordered by conviction** — or none, when nothing qualifies.
The gates set a cell's count, not a quota: a cell is as full or as empty as the evidence earns.
The user sees high-, medium-, and low-risk sections, each containing short-, mid-, and long-term ideas.
**Placement reads the model arm**: the cell is the model's own risk tier × horizon, argued in its thesis document and transcribed into the typed appendix ([§The opportunity](#the-opportunity)).
The **engine's rule-derived tier** — from measurable inputs (profitability, market cap, liquidity, volatility, leverage, drawdown, and event exposure), never a model label — is computed on every pass: it scales the entry gate's required return on **both** arms and renders beside the placement as the baseline, a disagreeing pair carrying the divergence tag ([§The opportunity](#the-opportunity)).
The **engine's horizon** follows a drafted rule over the archetype and the dated transaction events the feeds carry, persists beside the placement as the baseline, and sets the gate's **H** on both arms ([§Starting parameters](#starting-parameters-calibratable)).
Run-to-run placement stability is therefore the model's continuity discipline rather than a rule guarantee: placement freezes between deep passes, and a deep pass re-places the card only through a freshly written thesis document that reads the prior one ([trade-opportunities-workflow.md §Step 7](trade-opportunities-workflow.md#step-7-continuity-check--carry-forward)).
The fixed matrix is what makes the output comparable across runs and forces breadth — the job must consider every risk/horizon combination rather than clustering on whatever is topical.

## Archetype — the lens that decides which signals matter

Risk×horizon *places* an opportunity; **archetype decides how to find and judge it.**
The same signal means opposite things in different kinds of business — a low trailing P/E is a *buy* tell for a steady compounder and a *top-of-cycle sell* tell for a commodity cyclical — so the job classifies each candidate into one of five archetypes, and that classification selects the **signal weighting and the valuation lens** for the rest of the pipeline.
Archetype is a first-class dimension (deterministic features, model-confirmed) — a judgment lens that sits beside the engine's measurable risk-tier rule, never an input to it ([§Starting parameters](#starting-parameters-calibratable)):

| Archetype | The leading tell to detect | Valuation lens | "Late but still works" continuation tell |
|---|---|---|---|
| **Secular compounder** | a high-margin recurring/platform engine accelerating *inside* a mispriced business | PEG; estimate-revisions-vs-multiple | margin/segment reveal + base breakout |
| **AI / secular-cyclical infra** | segment-revenue YoY acceleration; estimate-revision velocity | forward P/E *against* the revision rate | beat-and-raise streak, guidance step-change, customer-capex corroboration, backlog/book-to-bill |
| **Commodity cyclical** | supply discipline + spot/contract-price turn at washed-out sentiment, *while still loss-making* | **P/B, P/NAV, mid-cycle EPS — trailing P/E suppressed** | contract-price up-quarter with supply still cut; a new demand kicker |
| **Category disruptor** | a leading operating metric (reservations, subscriber net-adds, trial efficacy, scanner share) + a hard demand>supply proxy + a strategic-incumbent stake | track the leading metric, not EPS | net-add / guidance beats — *and the inverse as the exit* |
| **Quality compounder** | operating income decoupling upward from revenue; durability-under-stress (e.g. renewal rate holding through price hikes) | valuation is a **risk gate, not an entry** | margin stair-steps; recurring profit pool growing toward a third of profit |

Archetype also informs the engine's horizon rule (its long branch has a genuine compounder-archetype leg — [§Starting parameters](#starting-parameters-calibratable)); the engine's deterministic risk-tier takes **no archetype term** — archetypes *correlate* with tier through the measurable inputs themselves (a commodity cyclical at its buy point is typically still loss-making and high-vol, tripping the High legs; a quality compounder characteristically lands the Low conjunction), but the correlation is emergent, never a rule input.
For a **carried-forward name** the confirm call receives the prior label beside the current classification features and affirms or overturns it in its rationale; the prior and current labels both persist on the record, so a lens that churns between passes on a borderline name is visible on the card and the audit rather than policed ([trade-opportunities-workflow.md §Step 5a](trade-opportunities-workflow.md#step-5a-archetype-classification)).

## The research method

The job's edge is not a screen — it is a **way of researching**.
Most screens find what is already cheap or already moving; this job tries to find what the world is *about to* reward, by first building a view of **how the world is evolving** — where industries are heading, which hard problems are being solved, where durable value is being created — and only then combining that worldview with the hard numbers and the live news to choose.
The discipline is to think like several different researchers at once and require that they agree: a quant, an economist, a fundamental business analyst, and a market historian each interrogate a candidate through their own lens, and an opportunity earns a place only when the **conjunction** holds — never a single signal (base rates are brutal: most stocks underperform Treasuries over their life, and the traits of the winners recur in the losers).

### The worldview comes first

Before any name is judged, the job grounds itself in a **forward worldview**, in two layers:

- the **macro / regime backbone** is inherited from the Market Signal house view — the report already commits to a `market_cycle` (late-cycle / recessionary / recovery) and a `risk_posture` (risk-on / off / mixed) ([storage.md](storage.md)), a compact growth × inflation regime read that says which sectors carry a tailwind in this phase of the cycle.
  The job does **not** recompute it; it reuses it (subject to the one-week freshness gate — [trade-opportunities-workflow.md §Step 2](trade-opportunities-workflow.md#step-2-load-shared-context)).
- the **forward thematic map** is the job's own work: the active secular themes (AI compute, electrification, reshoring, GLP-1 / obesity, the energy transition, aging demographics, …), each placed on its **adoption S-curve** — durable and compounding when penetration is still low and the **unit-cost curve is falling** (a falling cost expands the addressable market irreversibly — the Wright's-Law engine that turns a niche into a mass market), but merely speculative when it is a story with no cost or penetration anchor.
  Each theme is then traced down its **value chain** to the specific beneficiaries — **economically, not just by exposure**: at each node the tracing asks *who actually captures the margin* (where the chain's economic-profit pool sits, not merely who touches the theme), *who holds the bargaining power* (supplier- vs buyer-concentration — a node that can dictate price versus one squeezed between a strong supplier and a strong customer), *where capacity is constrained* (the bottleneck that confers durable pricing power — a sold-out fab, a permitted mine, a single-source component), and *which enabler therefore has real pricing power* rather than only revenue exposure — deliberately *past* the crowded pure-plays to the **picks-and-shovels enablers** (suppliers, infrastructure, cost-reducers) sitting at those margin-capturing, constrained nodes, whose fortunes rise with the adoption curve but whose names the consensus hasn't yet bid up.
  Exposure without margin capture — a commoditized supplier into a powerful buyer — is a thematic trap, not an opportunity.
  This is where breadth across market caps pays off: the enabler is frequently a mid- or small-cap.

The worldview is what lets the job answer "what *will* be valuable," not only "what *is* cheap."
It is a bias, never a verdict: a theme still has to produce a name with a moving number behind it.

### The lenses

Each candidate is interrogated through five lenses.
The first two are **engine-computed** (numbers the engine derives, never invented by the model — [local-models.md §Context-memory discipline](local-models.md#context-memory-discipline)); the last three are built by the **research loop** over the open web, and meet those numbers in the thesis document.

- **Quant lens (engine).**
  An integrated **composite** — each factor normalized against sector-adjusted absolute bands and the name's own history ([trade-opportunities-workflow.md §Step 5c](trade-opportunities-workflow.md#step-5c-deterministic-analysis-archetype-weighted-engine)) — over the factors that survive out-of-sample — **value** (earnings / FCF / EBIT-to-EV), **momentum** (12-month-minus-1 price *and* the name's own time-series trend), **quality** anchored on **gross profitability** (revenue − COGS over assets, the least-polluted quality metric) plus profitability / growth / safety, **low beta**, and **conservative investment** (low asset growth) — scored as *one* composite rather than separate sleeves, so a value tilt isn't secretly short momentum.
  On top sit the **event / flow signals**: **estimate-revision breadth** ((up − down) / total), **earnings surprise (SUE)** and its post-announcement drift, **insider cluster buys** (open-market, multiple insiders — strongest in small caps), **institutional accumulation**, and **short interest** (a **bearish factor by default** — heavily-shorted names underperform on average, since short sellers are informed — flipping to a *squeeze* long only as a narrow **conditional** setup: an inflecting leading metric **and** a near-term catalyst **and** evidence the bear thesis is breaking, never high short interest alone).
  Breadth across **all market caps** is the point (a modest signal applied to many names beats a strong signal on a few) — but with the universe's `*-bulk` pre-scoring off-plan and the screener carrying no fundamental field to rank a universe on, the composite is computed **per candidate on the narrowed set** ([trade-opportunities-workflow.md §Step 5c](trade-opportunities-workflow.md#step-5c-deterministic-analysis-archetype-weighted-engine)), so breadth is protected **structurally** — by the cap-band-stratified discovery selection that feeds the composite ([trade-opportunities-workflow.md §Step 4](trade-opportunities-workflow.md#step-4-candidate-consolidation)) — rather than by scoring the whole cross-section.
  The composite keeps faith with that breadth: **size used only within quality** (small-*and*-high-quality, never raw small-cap) and a **tradability flag** (illiquidity / days-to-cover) attached rather than excluding small names outright.
- **Value-creation lens (engine).**
  Whether the business actually *creates* value rather than just growing: **ROIC above its cost of capital** by a real spread (growth funded below the cost of capital destroys value however fast revenue grows), with **R&D capitalized** so research-heavy leaders aren't mis-scored as unprofitable; the **reinvestment runway** (g ≈ ROIC × reinvestment rate); **owner earnings**; and the **moat** that protects the returns — classified by source (intangibles, switching costs, network effects, cost advantage, efficient scale) and weighted by how often each actually sustains a durable advantage.
  High returns with no moat mean-revert; the moat is the reason the future cash flows survive.
- **Macro / thematic-fit lens (research).**
  How the candidate sits in the worldview above: which theme it rides, where that theme is on its S-curve, whether it is a crowded pure-play or an **un-priced enabler at a margin-capturing, capacity-constrained node** (exposure alone is not the tell — pricing power is), and whether the **TAM** holds up when sized **bottom-up** (units × price) and not only top-down (the gap between the two methods is itself a narrative tell).
  The leading indicators an economist watches that front-run the income statement — PMIs, capex commentary, book-to-bill, freight, the semiconductor cycle, commodity supply / demand — are gathered here, since no structured feed carries most of them.
- **Investor-judgment lens (research).**
  The qualitative read the great stock-pickers built by **scuttlebutt**: management quality and capital-allocation behavior (insider buying, buybacks, guidance *delivered* vs *promised*, candor in bad quarters), the durability of the growth, and the **pre-consensus** tells that mark an early edge — thin analyst coverage, low institutional ownership, a thesis that diverges from what the price already reflects (a *variant perception*).
- **Pattern / case-study lens (research).**
  The candidate is checked against the **case library** — how the historical winners actually started, and the look-alikes that failed.
  The library is a **curated, versioned data asset shipped with the app** — structured cases (name, period, archetype, the tell's actual dated metric series, how it resolved), not prompt prose — supplied to the lens by **retrieval, never model recall**: a local reasoner recalling historical specifics unaided will fabricate them confidently.
  The same asset doubles as the **gate regression harness** ([§Starting parameters](#starting-parameters-calibratable)), and to keep that second use honest it ships in **three partitions**: a *grounding* set (the memorable canon this lens retrieves), a *development* set (the only cases gate constants may be shaped against), and a **locked holdout** — ordinary failures, near misses, and randomly sampled base-rate names, not memorable cases — never tuned against.
  The recurring early tells: a **high-margin segment compounding inside a lower-margin whole** before the market re-rates it (AWS inside Amazon, Services inside Apple, Azure inside Microsoft); an **oligopoly with supply discipline turning** (memory ASPs up, inventories down, backlog rising — Micron); a **usage / engagement metric inflecting ahead of revenue** (Netflix streaming hours); a **platform shift the incumbent is mispricing**; **new management + a credible guidance step-change** (Nadella's Azure); **forward customer commitments** (long-term supply agreements); and **replicable single-unit economics with a long whitespace runway** (Walmart, Costco — both small-caps when the tell was visible).
  The inverse is the red-flag set the selection discipline enforces (see [§The pipeline](#the-pipeline)): a multiple outrunning estimates (Cisco 2000), peak-cycle margins extrapolated (memory tops, Peloton over-build), demand pull-forward mistaken for trend (Peloton / Zoom 2021), a narrative with no leading metric (dot-coms), a deteriorating leading metric behind still-strong share (Nokia / BlackBerry), or earnings-quality games (GE Capital).

### The two non-negotiables

Across every lens, two rules are load-bearing because they are the cleanest dividers between the winners and the failures:

1. **A present, inflecting leading operating metric is mandatory.**
   Every historical winner had a *countable, dated, third-party-verifiable* number already moving — segment revenue accelerating, ASPs turning, renewal rates holding, net-adds rising — before the price did; every failure either lacked one or had one quietly rolling over.
   A narrative with no inflecting metric behind it is a story stock and is rejected ([§What the job hunts](#what-the-job-hunts)).
   This is the anti-narrative gate, and it applies equally to early-detection and continuation ideas.
   *Inflecting* is **shaped by the metric's family, not one curve** — acceleration for growth metrics, a turn-that-holds for cyclical prices, stability-under-stress or a widening decouple for durability metrics — with the archetype mapping to the family its tell lives in, deltas taken seasonally comparable (YoY for quarterly series), steady post-inflection strength sufficing for a continuation idea, and a noise floor scaled to the series' own variability; the operative rule is drafted in [§Starting parameters](#starting-parameters-calibratable).
   The engine applies that rule to the archetype's metric family where the family reads from structured or filing-cadence data: the evidence floor tests that the family is measurable and fresh, and a measurable family that is not inflecting is the engine's affirmative read — a debut is held out as a story stock before research, a carried name proceeds with the annotation ([§Evidence floor](#evidence-floor)); an app-eligible new listing or separation has no measurable post-event series, so the leg is waived there; and where the tell lives only in research — product ASPs, channel checks, net-adds a feed never carries — the leading-metric topic's write-up states the dated observations with their sources and the thesis document judges the inflection in prose.
2. **Valuation-vs-forward-estimate trajectory is the primary red-flag.**
   A move that is mostly **multiple expansion** — price and multiple outrunning flat or declining estimates — is the signature of nearly every late-stage blow-up, so the **narrative-vs-reality ratio** (revision pace vs multiple change) reads such a name as `hype` rather than promoting it, even when the company is excellent ([§Starting parameters](#starting-parameters-calibratable)).
   For **thinly-covered small- and mid-caps** — frequently the very enabler names breadth prizes — analyst estimates are absent or stale, so the ratio falls back to an **operating-reality-vs-price** read: the hard operating momentum the company itself *reports* (segment revenue, gross profit, the archetype's structured leading metric — the operating rows the evidence floor reads in place of GAAP statements for emerging-economics archetypes — [§Evidence floor](#evidence-floor)) measured against the move in price and multiple, in place of the street's revisions.
   The question is unchanged — is the move underwritten by improving economics, or is it multiple expansion *ahead* of them? — only the numerator shifts from analyst revisions to the firm's own operating series when coverage is too thin to read.

### Reconciling the lenses (the contradiction check)

Requiring the lenses to *agree* — the conjunction rule this section opens with — only bites if their disagreement is actually surfaced, and the per-topic research design deliberately keeps the lenses **isolated in separate clean contexts** until they are consolidated, precisely so the local model is never handed a sprawling prompt.
The consolidation is therefore the first **adjudication**, among the research lenses: the **analysis** that consolidates the topics' write-ups states *where the research lenses disagree with each other* (a strong thematic story over a weak management or unit-economics read in the pages), *what the evidence leaves unanswered*, and *whether any source is stale or conflicted* ([trade-opportunities-workflow.md §Step 5e](trade-opportunities-workflow.md#step-5e-consolidation)) — it sees the write-ups and the fetched values, never the engine's reads.
The engine lenses join at the **thesis document**, whose prompt carries the engine's composite and value-creation read beside the analysis: there the model must *resolve or discount* a research story the engine's numbers don't support — a quant composite that likes a name whose unit economics don't, a thematic narrative over a failing value-creation read — rather than average it away, and states the thesis's **key falsifiers** in words — each a concrete measure, level and period ([trade-opportunities-workflow.md §Step 5g](trade-opportunities-workflow.md#step-5g-interpretation)); on a carried name the self-review judges those falsifiers against the realized data before the next document is written ([trade-opportunities-workflow.md §Step 5f](trade-opportunities-workflow.md#step-5f-self-review)).
This is **folded into the existing calls — no extra model call**.
The point is to stop a single loud lens, usually the narrative, from carrying a name the other four don't support.
The app reads none of it: the contradiction and the falsifiers are the model's own discipline, auditable in the documents it writes and tested by its own later review, never a typed field the app evaluates ([§The opportunity](#the-opportunity)).

### Balancing the revolutionary against the proven

The job hunts both the *revolutionary* company and the one with simply *excellent numbers* — and these are not opposites but the **same equation calibrated to different points on the compounding curve**: every durable winner is roughly *(high or credibly-emerging returns on capital) × (a long reinvestment runway) × (a moat) × (a price that still leaves asymmetry)*.
The difference is only **where the return is proven**.
The *proven-economics* track (Buffett / Greenblatt / Marks) requires it already visible in trailing financials and demands a margin of safety; the *emerging-economics* track (Fisher, Lynch's fast growers, disruptive-innovation and crossover-growth investing) underwrites it in a forward TAM × penetration × margin model and substitutes a **return hurdle** (the idea must be able to roughly double over its horizon — executable as the entry-asymmetry row's annualized-equivalent formula, [§Starting parameters](#starting-parameters-calibratable)) for trailing cheapness.
The **archetype** ([§Archetype](#archetype--the-lens-that-decides-which-signals-matter)) routes a candidate onto the right track and sets the weights — a commodity cyclical judged on mid-cycle earnings and supply discipline, a secular compounder on its margin / segment engine and runway — but **both tracks pass through the same moat / management / price-asymmetry gate**.
A company with strong numbers need not be revolutionary to be a real opportunity; a revolutionary one must still clear the price gate and show the inflecting metric.
Holding that balance — not collapsing into either pure momentum-chasing or pure deep-value — is the job's stance.

The two tracks differ in **how the forward case is argued**, but not in whether genuinely independent research may move the verdict — the job's expression of the suite's **four-part model** (the backward anchor — quant composite + value-creation read · the **forward outlook** — the engine's scenario targets beside the model's expected prices, and the thematic fit · **conviction**, the synthesis · the matrix placement that follows), each judgment carried in **two arms** ([§The opportunity](#the-opportunity) — the two-arm contract).
On either track research moves the model's arm **directly**: the reasoner writes its thesis document with the engine's values in the prompt as evidence, and states its conviction, its expected prices and its placement in the text, so a sourced finding the structured feeds never carried changes what the job believes without needing a typed permission slip.
The **proven-economics track keeps its margin-of-safety discipline** because the **engine arm's** deterministic price gate admits on its own terms; the model's read changes the job's belief, never the price the engine required to enter.
**Conviction is the model's own and bidirectional, with no permission gate on raising it** — the same stance Portfolio's verdict holds ([portfolio-analysis.md §The holding verdict](portfolio-analysis.md#the-holding-verdict)).
The **since-flagged read's cap-only stance is prompt-side discipline rather than enforcement** — price may not be laundered into conviction, the rule lives in the thesis-document task and the audit record, and no machinery detects a violation; the accuracy record measures each arm's prices against what happened, never why a value was chosen ([§Outcome learning](#outcome-learning-calibration)).

### The event-impact / value-chain repricing lens

A discrete **technology, product, or standard announcement** — a new chip, a process node, a regulatory standard, a reference design — reprices a whole value chain at once, and the market's first reaction is routinely wrong in *both* directions: it oversells names whose real exposure is narrow and overbuys names whose benefit is thin.
The job treats such an event as a first-class, **two-sided** research trigger rather than letting it enter only as ambient news.
The lens is deliberately named for **repricing, not "disruption"** — the central question the research must *derive*, never assume, is whether the new technology **substitutes for, complements, or merely shifts the mix of** each affected business; disruption is only one of those answers (the same tech can complement an incumbent, shift its mix, change capex timing, create a supplier bottleneck, or simply be misread).

When the materiality gate (below) fires, the route maps the chain three ways:

- **beneficiaries** — who captures the new margin: the bottleneck, the hardware / systems, the suppliers and service layers the shift creates (the same picks-and-shovels-enabler tracing as the worldview lane, aimed at a specific event — e.g. the firms that build the hardware for the large closed-loop cooling systems a new chip's thermal design now requires);
- **feared losers** — the names that sold off: *what revenue / profit pool is actually exposed*, whether the technology substitutes / complements / touches only a narrow segment, and over what deployment timeline — so a panic sell-off with limited real exposure surfaces as an **early-detection** candidate (a live bear narrative suppressing the price — [§What the job hunts](#what-the-job-hunts)), while a genuinely impaired one is correctly left alone;
- **latent names** — companies that did **not** move but should be affected if the technical read is right (a cheap output of the value-chain trace: the chain is already enumerated, so the lens just asks which nodes the market hasn't repriced yet).

The same read governs the **upside**: a name that *rose* on the announcement but whose benefit is overstated is the mirror case and is **capped through this lens**, not waved through — the narrative-vs-reality ratio is a revisions-vs-multiple discipline and does not by itself read the technology and size the real exposure ([§The two non-negotiables](#the-two-non-negotiables)).

**The materiality gate** keeps this from chasing every product headline: the trigger is a material technology / product / standard announcement **plus** at least one corroborating condition — meaningful group repricing, credible primary-source documentation, a customer-adoption signal, or clear value-chain exposure.
The gate is research-derived, so it is **checked at card formation, never at route selection**: the route may be chosen speculatively, and an event-impact hypothesis enters the typed appendix only with the announcement and a corroborating condition named — an entry that leaves them blank is dropped and logged, the check being presence on type, never a reading of the evidence ([trade-opportunities-workflow.md §Step 3b](trade-opportunities-workflow.md#step-3b-model-led-hypothesis-research)).
Absent the gate the route stays dormant, so a normal run behaves exactly as before.

**The "actual technology read" is sized in the hypothesis document, never left to narrative.**
For each affected name the document states the technical claim, the deployment timeline, whether the technology substitutes for, complements or shifts the mix of the business, the affected workload or use case, the exposed revenue / profit estimate, the adoption constraints, the switching costs, the margin-capturing node, its confidence in the sources and the leading metric to monitor — so the panic-vs-real (or euphoria-vs-real) verdict is *sized*, anchored, and auditable rather than a vibe (e.g. "the new cooling addresses only the liquid-to-chip segment; the incumbent earns ~80% from air-side units that are unaffected").
The read rides the hypothesis document, and each name's side — beneficiary / feared loser / latent — rides the typed appendix beside it, so it flows through the adversarial passes and promotion unchanged ([trade-opportunities-workflow.md §Step 3b](trade-opportunities-workflow.md#step-3b-model-led-hypothesis-research)).
The feared-loser side adds **one symmetric adversarial pass** to the lane's existing set — *is the impairment real or panic, and what is the actually-exposed pool?* — the mirror of the beneficiary-side "why is the obvious beneficiary wrong?".

This is **one signal among many**: every name the lens surfaces still clears the leading-metric anchor, the narrative-vs-reality and forensic reads, and the per-cell validation like any other candidate.
The lens decides *what to interrogate when an event repriced a chain* — not *what to buy*.

### Why the funnel and the discipline gates

Because the richest lenses are research (expensive, and the model's context is finite) and the base rates are unforgiving, the job is a **funnel**: cheap quant and thematic screens narrow the universe, and only the survivors get the full five-lens treatment.
Three discipline gates run before any candidate is promoted ([§The pipeline](#the-pipeline)): the **forensic gate** (accruals quality, Altman Z, Piotroski F, and manipulation-style flags — the soft quality flags persist as engine annotations the thesis document weighs, and only the enumerated hard events — a restatement or an auditor change, the filing-classified kinds — exclude a debut outright (a carried pick they archive via its deep pass); the trigger→outcome split is single-homed at [§Starting parameters](#starting-parameters-calibratable)); a **reflexivity check** (a thesis that depends on a self-reinforcing price → sentiment → fundamentals loop continuing is flagged, because it reverses violently when the loop breaks); and the **base-rate conjunction** rule (score the agreement of independent lenses, never one signal, starting from the outside view of how often this *kind* of setup has actually worked).
Factor *timing* is deliberately avoided — the evidence that it works is weak — so the lens weights are archetype-conditioned but otherwise stable run to run, not regime-switched.

## The pipeline

The job runs as a **funnel**: broad, cheap discovery narrows to a small candidate set, then each candidate gets expensive per-name validation — the condense-as-you-go discipline the rest of the suite uses, and the shape the data budget requires (the richest signals are rate-limited, so they are spent only on the narrowed set).

1. **Hypothesis & candidate discovery (research generates candidates).**
   Three converging feeders — the hypothesis lane always research-active, the carried-forward watchlist conditionally so for its selected `research`-class refresh lane, the structured screens deterministic — this is where ideas are *found*, not merely vetted:
   - **Model-led hypothesis research** — the 122B reasoner, primed with the house view, **plans research routes** (policy / supply-chain / technical-bottleneck / procurement-capex / customer-capex / industry-history / failure-analogue / event-impact value-chain-repricing) under an app-owned **coverage rotation** that reserves the next route slot for the oldest overdue route-class + broad-industry / active-theme subject.
     It then runs the **keyless SearXNG web tool** over the FMP Articles and structured-news leads and the macro-release calendar (**no GDELT, no Tavily** — see [trade-opportunities-workflow.md §Step 3b](trade-opportunities-workflow.md#step-3b-model-led-hypothesis-research)) to form **investable hypotheses**: *world-change → mechanism → who captures the margin → leading metric → public-company expressions → bear case → falsifiers*, each route's research consolidated into a **hypothesis document** whose typed appendix names the expressions, the leading metric with its re-check class, and the decision — promote, watchlist, or none.
     Only then does it **reason its way to specific names**, tracing each hypothesis down its value chain to the margin-capturing operators and surfacing under-covered / early-inflection names no structured feed carries — each grounded in the pages it read and verified before it earns budget.
     Hypotheses are **decided before any ticker** (so names come from strong hypotheses, not loud narratives) and vetted by **adversarial passes** (*why already priced? · why is the obvious beneficiary wrong? · who captures the margin instead?*) over a disconfirming fetch pass; one route each run is a mandatory **graph-blind outside-view** so the discovery memory aids without anchoring, while the calendar-time coverage ledger prevents the discretionary slots from repeatedly circling only the currently loud themes.
     This is the **early-detection** lane and the job's edge: names that aren't yet loud in the data.
   - **Bottom-up structured** — cheap, broad, deterministic.
     The **company screener** slices the eligible universe by market-cap band / sector / liquidity (coarse fields only — no valuation or growth filter, and the `*-bulk` universe-scoring endpoints are off-plan, so it **stratifies rather than pre-scores** — [data-sources.md §FMP — current paid-plan tier audit](data-sources.md#fmp--current-paid-plan-tier-audit)).
     **Commodity-price turns** (FRED / FMP) feed the cyclical sleeve.
     **Event / positioning feeds** supply insider-buy clusters (FMP), short-interest extremes (FINRA), and M&A / 8-K / movers / earnings-calendar / IPO catalysts — the activist-stake and congressional feeds are **symbol-keyed** on the current plan, with no market-wide read, so they enter per-candidate at validation, never as discovery feeders ([data-sources.md §Trade Opportunities — endpoint surface](data-sources.md#trade-opportunities--endpoint-surface)).
     A **post-earnings surprise screen** reads the paid earnings calendar *backward* over the trailing weeks (it carries consensus + actuals), surfacing **standardized** positive surprises — scaled by the name's own surprise history, SUE-style, not raw %, and prioritized where the **revenue surprise agrees with the EPS surprise**, where post-earnings drift is markedly stronger — and building beat-and-raise-streak candidates.
     It is the one structured feeder aimed squarely at **continuation** mode, whose tells (revision streaks, surprise momentum) are otherwise computed only per-candidate, after something else has already surfaced the name.
     These surface names **already visible in the data**; the multi-factor composite and forensic reads that judge them are computed **per candidate** after narrowing ([trade-opportunities-workflow.md §Step 5c](trade-opportunities-workflow.md#step-5c-deterministic-analysis-archetype-weighted-engine)), not across the universe.
   - **Carried-forward watchlist** — the persisted **opportunity graph** ([§Discovery memory](#discovery-memory-the-opportunity-graph)) re-surfaces every worthy-but-unpicked name from prior runs whose hypothesis the **watchlist review** judges confirming on its refreshed prints, with `research`-class nodes eligible for a small, targeted current-search refresh lane instead of waiting solely for theme-level rediscovery, so a deferred idea that quietly starts compounding is caught rather than lost to chance.

   The combined set is deduped, sanity-filtered for tradability, tagged with the signals that surfaced it, and **narrowed to the per-candidate research budget** — a generous, **user-configurable** compute ceiling on how many names get the expensive validation per run, *not* a quality cap.
   Nothing is validated yet at this point, so an un-picked name is **not rejected, only deferred**.
   A genuinely worthy deferral is **remembered**: written to the persisted opportunity graph as a watchlist node and re-read every later run, its leading metric refreshed where a feed carries it, so silent compounding can't slip away — the discovery-memory carry-forward, upstream of and distinct from the persisted *validated* matrix's carry-forward ([configuration.md §Local Analysis Suite Configuration](configuration.md#local-analysis-suite-configuration)).
   The narrowing runs **under deliberate diversity guardrails** — quotas and floors by market-cap band (a mid / small-cap floor and a mega-cap ceiling), feeder, archetype, and sector / theme — so the funnel stays broad rather than collapsing onto mega-cap momentum, the most-covered AI names, or one crowded macro theme (the breadth across market caps that is the job's edge; the consolidation spec is [trade-opportunities-workflow.md §Step 4](trade-opportunities-workflow.md#step-4-candidate-consolidation)).
   (This is the load-bearing fix to the old ordering: "names surfaced by research" is a *discovery* feeder that runs **here**, before candidate selection — research is no longer only a downstream validation step.)
2. **Archetype classification.**
   Each candidate is tagged with its archetype (deterministic features + model confirmation), selecting the signal weights and valuation lens for the steps below.
3. **Deterministic analysis (the engine computes every financial output), and the evidence floor.**
   Per candidate, the Rust financial-analysis engine (shared with Portfolio Analysis — see [portfolio-analysis.md](portfolio-analysis.md)) computes the archetype-appropriate quantitative picture: the leading-metric series (revision velocity, segment acceleration from the annual segment rows, commodity-price turn, margin decoupling), the earnings surprise / SUE, positioning (insider net, short interest, COT for cyclicals, the Schwab options signal), scenario price targets at three months, twelve months and three years, and a **price-action confirmation read** (relative strength vs the market / sector and proximity to a multi-year base breakout, from equity price history).
   It also computes **three derived reads the interpretation leans on**.
   The **narrative-vs-reality ratio** is estimate-revision pace vs multiple change: *justified-expensive* when estimates outrun the multiple, *hype* when the multiple outruns flat/declining estimates.
   The **forensic flags** are margin compression while revenue accelerates, net-income-vs-operating-cash-flow divergence, receivable/inventory build outpacing sales, and restatement / auditor-change history.
   The **implied-expectations read** is the growth / revision trajectory the current price *already assumes*, solved by inverting the engine's scenario math at the live price under the archetype's valuation lens and expressed as a **range under stated assumptions** — a price is consistent with many growth × margin × discount combinations, so a single solved number would be false precision.
   So "what must be true to justify today's price" is a computed, bounded read the priced-in / crowding judgment anchors on rather than a vibe.
   The **evidence floor** runs here too, over the same structured data, so a debut that cannot earn a place — missing or stale evidence, or a structured metric family that is measurable and not inflecting — is held out before any research is spent ([§Evidence floor](#evidence-floor)).
   These are the **engine arm** — the deterministic baseline the model reads as evidence, with its methodology exposed, and against which the model authors its own arm of the same judgment ([§The opportunity](#the-opportunity) — the two-arm contract; the suite-level rule at [local-models.md §Context-memory discipline](local-models.md#context-memory-discipline)).
   Facts and their arithmetic stay single-valued; judgments about the future are carried twice.
4. **Deep web research** — the 122B reasoner (thinking mode) plus the web tool, running the bounded per-topic research loop per candidate ([web-research.md](web-research.md)), fail-soft, each pass ending in a **synthesis write-up**.
   This is where the three research lenses of [§The research method](#the-research-method) are worked, each as its own clean-context topic so the local model is never overwhelmed.
   The **macro / thematic-fit** read covers which theme, where on the S-curve, pure-play vs enabler, bottom-up TAM, and the economist's leading indicators.
   The **investor-judgment** read covers the **driving narrative and market sentiment** — how much of the price reflects emotion about *what might come* versus present fundamentals — plus management / capital-allocation quality and the pre-consensus tells.
   The **pattern / case-study** read runs against the case library.
   Alongside them comes the external corroboration the structured feeds can't give: customer / hyperscaler capex commentary, supply discipline, transcript backlog / TAM targets / inflection language, and **DRAM/NAND ASP direction** — the one cyclical price with no free structured feed.
   And, **mandatory, the contemporaneous bear case** — the job must state why a name might fail, because the winning traits also appeared in the famous failures (Cisco, Intel, GE rode the same surface signals down).
   The research brief carries the fetched values as the providers return them, never the engine's reads, so research fills the gaps the numbers leave rather than substituting a story for them; the engine's reads and the research meet at the thesis document ([trade-opportunities-workflow.md §Step 5d](trade-opportunities-workflow.md#step-5d-bounded-web-research)).
5. **Consolidation** — the write-ups are distilled only when the analysis prompt is over its budget (the reasoner in non-thinking mode — the same resident 122B by default; the fast 35B tier is a benchmark-gated option — see [local-models.md §The model roster and per-task routing](local-models.md#the-model-roster-and-per-task-routing)), then the reasoner writes the candidate's **analysis**: one document consolidating what this run's research established, each figure dated and sourced, the research lenses' disagreements among the pages and what stays unanswered stated — the only research artifact a later pass reads ([trade-opportunities-workflow.md §Step 5e](trade-opportunities-workflow.md#step-5e-consolidation)).
6. **Self-review (carried names).**
   On a carried name the reasoner reviews its prior thesis document and placement against this run's analysis, the realized price path since the prior pass and the accuracy record, in prose, before it writes again ([trade-opportunities-workflow.md §Step 5f](trade-opportunities-workflow.md#step-5f-self-review)).
7. **Interpretation & gating.**
   The 122B reasoner interprets the computed analysis and the analysis into the candidate's **thesis document**, under explicit discipline: **score the conjunction, never a single signal** (base rates are brutal — most stocks underperform Treasuries over their life, and the winner traits recur in losers); **require the leading-metric anchor plus external validation**; **apply the narrative-vs-reality ratio**; treat **price action (relative strength / base breakout) as a confirmation overlay** that adjusts conviction but never substitutes for the leading-metric anchor; **resolve or discount a research story the engine's lenses don't support** rather than averaging it away ([§Reconciling the lenses](#reconciling-the-lenses-the-contradiction-check)); and **weigh the risk / forensic flags** the engine annotated.
   A second, non-thinking message transcribes what the document states into the **typed appendix** — the cell, the conviction, the expected price at three horizons, the detection mode, the leading metric, and on a carried name the status ([§The opportunity](#the-opportunity)).
   The app then runs the **entry-asymmetry gate on both arms** and the **hard triggers** — a restatement or auditor change from the filings, and on a carried name anchorless `hype` — which exclude a debut outright or force a carried name to `invalidated` ([trade-opportunities-workflow.md §Step 5h](trade-opportunities-workflow.md#step-5h-deterministic-risk-tier-gate-validation--checkpoint)).
   Each survivor lands in the matrix cell its appendix names — tier × horizon ([§The opportunity space](#the-opportunity-space)) — and **every survivor that clears *either arm's* entry gate is listed there**, ordered by conviction level and then by the model's twelve-month upside (the either-arm admission rule — [§The opportunity](#the-opportunity)); names expressing one hypothesis are linked on their cards, never merged ([trade-opportunities-workflow.md §Step 6](trade-opportunities-workflow.md#step-6-matrix-assembly)).
   So the per-cell step is a deterministic ordering, not a model gatekeeper that could quietly drop a name.
   **A cell may return no opportunity** when nothing qualifies — empty cells are honest, not failures, and the matrix never pads itself to fill them; a rich cell that genuinely earned many anchored ideas is just as honest, never trimmed to a fixed number.
8. **Continuity & re-evaluation (DTO).**
   Prior opportunities are carried forward with an updated status; a deep pass states what changed in its thesis document, drawing on its review (see [thesis-continuity.md](thesis-continuity.md)).
   DTO splits the carried matrix by cost.
   A live opportunity that **won a deep pass this run — a reserved rotation-slice pick ([§The two jobs](#the-two-jobs)), or a re-surfacer that won leftover deep-research budget — is deep-re-evaluated in the Step-5 validation loop as a carried-forward candidate**, the deep pass being the only path that can flip it to `invalidated` → archive.
   At the continuity step **every other live opportunity gets the engine-only cheap re-derivation**: it re-pulls price + estimates, re-derives the engine's scenario targets, re-runs the entry-asymmetry gate **on both arms** — its own live targets and the model's frozen twelve-month expected price against the current price — and refreshes the since-flagged read.
   But it **never archives**: an exhausted-upside read or a tripwire it detects (a continuation-failure signal — revisions rolling over, a beat-streak breaking, shipments diverging below sell-through — among them) raises a **warning** on the card (*consider a Deep Audit*), not an exit.
   There is **no "target met" exit**; a name leaves the matrix for the **archive** only when a deep re-evaluation — here, or in ATO — judges it `invalidated` ([§Archived opportunities](#archived-opportunities)).
   The pass then opens this run's **episodes** — the price records the accuracy checks at the next job start score at their horizons — and refreshes the **since-flagged read** across the whole matrix ([§Outcome learning](#outcome-learning-calibration)).

## Discovery memory (the opportunity graph)

Discovery is **stateful**: each run persists an **opportunity graph** — the model's worldview reasoning *and* the memory of worthy candidates that didn't make this run's cut.
A **hypothesis node** is the hypothesis document's section on that hypothesis — world-change → mechanism → value-chain node → leading metric → expressions → bear case → falsifiers, as the model wrote it — together with the typed fields its appendix carried: the title, the decision, the candidate symbols, the leading metric with its re-check class, and for an event-impact hypothesis each name's side and the gate fields ([trade-opportunities-workflow.md §Step 3b](trade-opportunities-workflow.md#step-3b-model-led-hypothesis-research)).
The macro / political / structural reasoning behind every name is therefore **auditable and reusable across runs** as the prose the next run's planner and routes read, instead of evaporating.
A hypothesis surfaced by the **event-impact repricing lens** carries its sized technology read inside that prose and the side each name expresses in its appendix fields ([§The event-impact / value-chain repricing lens](#the-event-impact--value-chain-repricing-lens)), so the panic-vs-real read persists with the node and is re-read next run like any other watchlist context.

Company nodes carry a **status**:
- **picked** — became a validated opportunity in this run's matrix (the matrix is the authoritative carry-forward for these; the graph preserves the hypothesis lineage behind the pick);
- **watchlist** — cleared the **discovery-worthiness bar** — the hypothesis document states an economic mechanism and at least one falsifier, its appendix names a leading metric with its re-check class, and the decision reads `watchlist`, or `promote` without a validation slot (budget / diversity) ([trade-opportunities-workflow.md §Step 3b](trade-opportunities-workflow.md#step-3b-model-led-hypothesis-research)) — or was researched but didn't clear a gate while its thesis stays live.
  Carried forward with its hypothesis link, leading metric (tagged by **re-check class** — `structured` / `filing` / `research`), a *why-deferred* reason, the latest gate distance where one exists, and its last successful refresh timestamp, and **re-read every later run by the watchlist review** with its refreshed `structured` / `filing` prints (a **`research`-class** metric has no engine feed, so it refreshes only when discovery re-surfaces it or when the bounded targeted research-watchlist lane selects it — [trade-opportunities-workflow.md §Step 3c](trade-opportunities-workflow.md#step-3c-carried-forward-watchlist-re-check)): a node the review judges **confirming** is promoted as a priority discovery feeder;
- **retired** — the review judged its falsifiers tripped or its thesis invalidated, the leading metric went dead / stale, or the **carry horizon** elapsed (a configurable cap on how long a hypothesis is monitored without confirming — counted in the leading metric's **own reporting periods** (drafted: ~4), never in runs: run cadence is user-chosen, so a run-counted horizon would give a quarterly metric days at daily cadence and years at monthly).
  Retired nodes leave active monitoring but stay in history.
  Retirement is scoped to **upstream hypotheses** — worthy-but-unpicked watchlist names; a pick that leaves the matrix takes the terminal status below, never `retired`;
- **departed** — the terminal status a **picked** node takes in the same reconciliation pass that moves its deeply invalidated opportunity to the archive — DTO's Step 7, or an ATO Deep Audit's reduced continuity pass, the transition riding **every** deep-invalidation archival ([trade-opportunities-workflow.md §Step 7](trade-opportunities-workflow.md#step-7-continuity-check--carry-forward), [§ATO: the audit flow](trade-opportunities-workflow.md#ato-the-audit-flow)): the node and its lineage stay **visible in route context as a terminal dead thesis** — so discovery extends-or-retires rather than re-deriving it blind, the graph's whole purpose — but it is **never a discovery feeder and never re-promotable in place**; its forecasts are already scored on its lifecycle's episodes ([§Outcome learning](#outcome-learning-calibration)).
  A genuine re-entry arrives only through independent fresh discovery and opens a **new node under a new lifecycle** ([§Archived opportunities](#archived-opportunities)); the departed node stays the dead thesis's tombstone.

This directly fixes the failure mode of stateless re-discovery — a deferred name that quietly compounds but never re-trips a feeder, and so is silently lost (there is no promise it re-surfaces).
It is **partially bounded by construction**: a retention cap on the active watchlist — with a **deterministic cap-bind eviction**: the node with the oldest successful refresh first, ticker tiebreak, retired with reason `capacity-evicted` ([trade-opportunities-workflow.md §Step 3c](trade-opportunities-workflow.md#step-3c-carried-forward-watchlist-re-check), constants in [§Starting parameters](#starting-parameters-calibratable)) — plus the self-pruning of falsified / stale / horizon-elapsed nodes, and departed tombstones pruned on the same retention as the archive they mirror ([configuration.md §Local Analysis Suite Configuration](configuration.md#local-analysis-suite-configuration)).
The **live picked nodes carry no cap of their own, deliberately**: they mirror the intentionally uncapped matrix — every gate-clearer is listed, no output quota ([§The opportunity space](#the-opportunity-space), [trade-opportunities-workflow.md §Step 6](trade-opportunities-workflow.md#step-6-matrix-assembly)) — and leave only through the deep-invalidation → `departed` path, so the one unbounded population is the validated live picks themselves, a stated property of the every-gate-clearer output contract rather than a silent scaling guarantee.
Statefulness's opposite risk — **anchoring** to stale theses — is countered by the mandatory **graph-blind outside-view route**, the **calendar-time coverage rotation** over route classes and broad industry / active-theme subjects ([trade-opportunities-workflow.md §Step 3b](trade-opportunities-workflow.md#step-3b-model-led-hypothesis-research)), and the carry horizon, so the memory aids without caging or repeatedly researching only the loudest theme.
The companion **discovery-coverage ledger** is deliberately not a hypothesis store: it records which route classes and coverage subjects were attempted and successfully researched, so a completed search that found nothing still pays down coverage debt while a failed / budget-exhausted route does not; it can force an agenda slot, never a candidate or verdict.
The graph is **distinct from the validated opportunity matrix**: the graph is *upstream* discovery memory (hypotheses + worthy-but-unpicked candidates), the matrix is the *downstream* validated output carried forward for the Step-7 continuity check.
The graph, matrix, and coverage ledger persist in this job's own storage partition ([storage.md §Local Analysis Suite Storage](storage.md#local-analysis-suite-storage)).

## Evidence floor

Discovery decides whether a candidate is *worth* the expensive per-name work; the evidence floor decides whether a candidate has earned the model's time at all — the per-candidate analog of the report's Step-3 coverage floor and Portfolio's holding floor ([portfolio-analysis.md §Evidence floor](portfolio-analysis.md#evidence-floor)).
Below the floor a candidate returns **`insufficient-evidence`** — an explicit abstention held out of the matrix — rather than a low-conviction guess.
The floor is **engine-only** and runs with the engine, before any research is spent ([trade-opportunities-workflow.md §Step 5c](trade-opportunities-workflow.md#step-5c-deterministic-analysis-archetype-weighted-engine)): every leg is a read over structured data and its absence, so a debut that abstains has cost no model call.
The floor splits inputs by criticality, and — unlike Portfolio's single equity floor — it is **archetype-aware**, because an early-stage disruptor legitimately carries thinner financials than a quality compounder:

- **Floor-bearing for every candidate:** a current **quote / price** and **price history** (the engine's momentum / price-action reads); the **engine's leading-metric family** measurable where the archetype's tell lives in a structured or filing-cadence series — revision velocity, the annual segment rows, a commodity price, a statement margin — its minimum history met (the inflecting gate in [§Starting parameters](#starting-parameters-calibratable)), while an archetype whose tell lives only in research has no floor leg for it and the metric's inflection is the thesis document's judgment ([§The two non-negotiables](#the-two-non-negotiables)); and **source freshness** — the floor-bearing inputs must be current, not stale, with *current* computed from the typed **evidence-floor freshness basis** ([§Starting parameters](#starting-parameters-calibratable)), never an ad hoc age judgment.
  The floor tests facts and their absence; what a measurable family *shows* is the affirmative read below.
- **A measurable-but-flat family is an affirmative read, not a floor gap.**
  A debut whose structured family is measurable and not inflecting is held out at the same step as a **story stock** — `no-inflecting-metric`, before any research, no episode — so the leading-metric non-negotiable holds by construction however complete its other data is.
  A carried name with that read is not inconclusive: its deep pass proceeds with the engine's annotation, where anchorless `hype` is a hard trigger that forces `invalidated` and a flat metric without `hype` is a read the review and the thesis document must confront ([§Starting parameters](#starting-parameters-calibratable)).
- **Statement floor, archetype-substituted:** the **financial statements** (FMP / SEC) are floor-bearing for a *proven-economics* archetype (quality / secular compounder, commodity cyclical) — absent, stale (per the freshness basis — [§Starting parameters](#starting-parameters-calibratable)), or carrying conflicting identity ⇒ abstain.
  For an *emerging-economics* archetype (early disruptor, pre-profit ai-infra) where GAAP statements are thin by nature, a defined **substitute** stands in: the structured operating rows the feeds carry — the revenue segments, gross profit and the revision signal — sufficient to anchor the engine's targets; the operating metrics only research carries (backlog / bookings, net-adds, cohort retention) reach the model through the write-ups and are weighed in the thesis document.
  The substitution is explicit and logged; it relaxes the *form* of the supporting financials, never the leading-metric requirement.
- **Limited-history provenance mode, never a looser floor:** the app may mark a candidate `new-listing`, `spin-off-carve-out`, or `new-economic-perimeter` only when objective listing / corporate-identity facts explain why comparable public history is short; an old issuer with a provider gap is ineligible.
  An eligible candidate is floored under the **limited-history branch**: the engine's family test is unmeasurable by construction on a post-event series, so the leading-metric leg is **waived** — the metric's inflection is the thesis document's judgment from the reconstruction write-up, never a story-stock hold-out — and the statement leg counts what the feeds carry since the event ([§Starting parameters](#starting-parameters-calibratable)); the dossier carries the filing identifiers and source plan — the S-1 or Form 10, carved-out or predecessor disclosures, contracts, customer / supplier observations, dated operational milestones — that the reconstruction research topic deep-reads ([trade-opportunities-workflow.md §Step 5d](trade-opportunities-workflow.md#step-5d-bounded-web-research)).
  What research recovers reaches the model in prose — each observation with its period, its source, and whether it is directly comparable, a disclosed recast, or only a proxy — and never enters the engine's series or substitutes for a statement; the thesis document weighs it, and limited history never changes archetype, risk tier, required return, or gate math.
- **Enriching (never forces abstention):** estimates / revisions, positioning, peers, the options signal, analyst opinion, the qualitative narrative read, and the dividend distributions (a failed retrieval; a confirmed nonpayer's clean zero is no gap) — their absence is recorded as a degraded-input flag the thesis document reads, but never on its own floors the candidate.
  One named carve-out: the shared target ladder's **`no-admissible-driver`** case — no positive forward-EPS consensus and no computable forward revenue per share ([portfolio-analysis.md §Starting parameters](portfolio-analysis.md#starting-parameters-calibratable)) — abstains under that reason, because the entry-asymmetry gate cannot price a name with no computable target.

"Firm" means committing when the evidence supports it and abstaining when it doesn't — an empty cell is honest, and `insufficient-evidence` is a real verdict, not a failure ([§The pipeline](#the-pipeline)).

**The floor is arm-independent and binds absolutely.**
The two-arm contract's either-arm admission rule is scoped to the **entry-asymmetry gate alone** ([§The opportunity](#the-opportunity)): a candidate below this floor abstains no matter how conviction-bearing the model's arm would have been, and the same holds for the forensic **hard** triggers and the anchorless `hype` exclusion.
The reason is the division the whole contract rests on — the floor and the hard triggers are reads over *facts and their absence*, not judgments about the future, so there is no second arm for them to have.

The floor's abstention semantics are **debut semantics**.
For a **carried live opportunity** whose deep re-evaluation falls below the floor (a missing quote, stale statements, a provider gap — missing or stale evidence, never the affirmative flat-metric read above), the abstention is an **inconclusive refresh, never a turn-away**: the name **holds its last verdict, conviction, and matrix identity** (the fail-soft last-verdict rule — [§Failure posture](#failure-posture)), a **typed refresh gap** is recorded in the run audit, no research is spent and no episode opens, and the incomplete pass **does not stamp `last_deep_researched_at` or clear an attention warning** — the name stays exactly as stale and as flagged as it was, so the rotation slice keeps prioritizing it.
Whatever engine-only fields the pass *could* compute refresh under the cheap re-derivation's rules ([§The opportunity](#the-opportunity)); only a floor-clearing deep pass rewrites the model-authored fields or archives ([trade-opportunities-workflow.md §Step 5h](trade-opportunities-workflow.md#step-5h-deterministic-risk-tier-gate-validation--checkpoint), [§Step 7](trade-opportunities-workflow.md#step-7-continuity-check--carry-forward)).

## The opportunity

**The two-arm contract.**
Every validated opportunity carries its judgment **twice**, as two arms with distinct provenance — the same contract Portfolio's holding verdict holds ([portfolio-analysis.md §The holding verdict](portfolio-analysis.md#the-holding-verdict)):

- The **engine arm** is the deterministic baseline — a disclosed calculator over primary-source data: the archetype-weighted quant composite and value-creation sub-scores, the v2 rate-anchored bear / base / bull targets at three months, twelve months and three years, the implied-expectations range, the narrative-vs-reality read, the forensic state from the filings, the rule-derived risk tier and horizon, and the since-flagged read.
  Its constants are calibratable; it obeys its own bars by construction, and every value is **app-stamped onto the record directly, never echoed through the model**.
- The **model arm** is the reasoner's own read: the **thesis document** it writes with the engine's values **and their methodology** in the prompt as **evidence, never bounds**, and the **typed appendix** transcribed from it — the risk tier and horizon, the conviction, the expected price at three months, twelve months and three years, the detection mode, the leading metric with its re-check class, and on a carried name the status.
  The app checks the appendix **on type alone** — the enums, each price finite and strictly positive — never against the engine; the document is read as text and validated by nothing ([trade-opportunities-workflow.md §Step 5g](trade-opportunities-workflow.md#step-5g-interpretation)).

Exposed methodology is what makes disagreement intelligent rather than noise — the engine's `TargetMeta` states whether a band is rate-anchored or a current-multiple carry, whether its driver was flat or clamp-flattened, and whether the dispersion floor widened it, so the model can dispute a *derivation* and not merely a number.
**The accepted cost is anchoring**: showing the engine's values pulls the model's toward them, and the engine's own tier and horizon are shown with the rest of its reads — the same trade Portfolio accepts.
The divergence is recorded on every pick — each engine value beside the model's on the card's expand view and the audit — and read there, never pooled into a rate.

Four rules keep the contract honest.
**Model-arm values never alter or bind the engine baseline** — the cheap re-derivation reads engine values and the appendix's prices, and no channel carries a model value into the engine's computations.
**Admission is either-arm**: both arms run the same entry-asymmetry gate, and a candidate clearing **either** enters the matrix, stamped with its **admission provenance** (`engine-and-model` / `engine-only` / `model-only`).
The grant is scoped to that gate alone: the **evidence floor, the forensic hard triggers, and the anchorless `hype` exclusion bind absolutely on both arms** — a model-only admission can never carry a name past the floor or a hard trigger ([§Evidence floor](#evidence-floor), [§Starting parameters](#starting-parameters-calibratable)).
**Facts and their arithmetic stay single-valued** — prices, statements, positioning, short interest, the options signal, Altman Z, Piotroski, the composite's normalization math — because a second version of a fact is fabrication, not judgment; the model's freedom is to weigh or dismiss them in its document.
**The engine keeps score and never plays**: the accuracy checks are engine-computed from the dated-EOD series, and nothing the model writes alters a check or a score ([§Outcome learning](#outcome-learning-calibration)).
*Placement* reads the model arm — its tier and horizon set the cell — while the engine's pair persists beside it as the baseline ([§The opportunity space](#the-opportunity-space)); the **admission yardstick does not move with it**: the gate's tier-scaled required return, haircut, and **H** read the engine legs on both arms, so the model never lowers its own bar ([§Starting parameters](#starting-parameters-calibratable)).

Each opportunity is a record:

- **asset / ticker**, with its **lifecycle id** — the durable, app-assigned identity a re-entry never reuses ([§Archived opportunities](#archived-opportunities))
- **archetype** — secular-compounder / ai-infra / commodity-cyclical / disruptor / quality-compounder (the lens that judged it); on a carried name the prior label persists beside the current one
- **detection mode** — early or continuation, transcribed from the thesis document
- **thesis document** — the model arm's prose, persisted as written and validated by nothing: the directional thesis, firm and specific; the detection mode in words; the leading operating metric and its trend; why now; the key drivers; the bear, base and bull scenarios, each with the conditions that produce it and the model's probability; the **bear case** (mandatory — the contemporaneous reason it might fail); the **key falsifiers** and triggers in words, each stating a concrete measure, level and period; the implied-expectations read in words; the risk and payoff-timing argument that sets the placement; the expected price at each horizon and the conviction, argued in the text; the entry consideration; and on a carried name what changed since the prior document and how the prior read held up, drawing on the review — within the thesis document's length band ([§Starting parameters](#starting-parameters-calibratable))
- **leading operating metric** — the countable, dated anchor by name and its **re-check class** (`structured` / `filing` / `research` — [trade-opportunities-workflow.md §Step 3c](trade-opportunities-workflow.md#step-3c-carried-forward-watchlist-re-check)), transcribed from the document; the engine's archetype metric family and its continuation state ride beside it as the baseline read
- **risk tier** — high / medium / low, **both arms**: the model's own tier is the cell's row, while the engine's rule-derived tier persists beside it as the baseline and alone scales the entry gate's required return on both arms.
  A disagreeing pair records as a divergence and carries the card's tag
- **horizon** — short / mid / long, **both arms**: the model's own horizon is the cell's column, while the engine's follows the drafted rule over the archetype and the dated transaction events the feeds carry ([§Starting parameters](#starting-parameters-calibratable)), persists beside it as the baseline, and sets the gate's **H** on both arms.
  A disagreeing pair records as a divergence and carries the card's tag
- **conviction** — the model's own, high / medium / low, transcribed from the document and never clamped
- **expected prices** *(user-facing)* — **both arms** at three months, twelve months and three years: the **model arm's expected prices** headline the card and drive the List view's default sort, while the **engine's bear / base / bull bands at the same horizons** are the disclosed baseline — visible on card expand and in the List view's paired columns ([§Storage and display](#storage-and-display)).
  The engine's bands are the shared v2 rate-anchored scenario-target function under the archetype's driver override ([§Starting parameters](#starting-parameters-calibratable)), re-derived on every cheap pass from structured data alone; the model's prices are a **dated judgment** authored whole at the deep pass — they never move with the engine's skeleton, and their age is carried by the `Research stale` badge, not by a silent revert.
  The twelve-month pair is **distinct from the matrix horizon**, which reflects payoff timing, not the target window.
  This is the *forward* read, surfaced **distinct from the backward anchor** (the quant composite + value-creation read) so a name that screens poorly on trailing numbers but carries a strong forward setup is shown as such, not buried ([§Balancing the revolutionary against the proven](#balancing-the-revolutionary-against-the-proven))
- **narrative-vs-reality read** — whether the move is fundamentally underwritten or multiple-expansion, from the estimate-revisions-vs-multiple ratio (an engine read; the model weighs it in its document rather than recomputing it)
- **implied-expectations read** — what the current price already assumes, as the engine's computed range under stated assumptions; the model's own read of the same question lives in the document (the anchor for the priced-in / crowding judgment and the adversarial *why is this already priced?* discipline)
- **quality / valuation read** — the engine's archetype-weighted quant composite and value-creation sub-scores, with their provenance flags; the document weighs them and authors no sub-scores of its own
- **hypothesis lineage** — the discovery hypothesis this name expresses (world-change → mechanism → margin-capturing value-chain node → leading metric), a link to its node in the **discovery memory** ([§Discovery memory](#discovery-memory-the-opportunity-graph)) whose prose carries the worldview reasoning behind the pick and whose fields recover the name's pre-validation history (first-surfaced run, prior watchlist time); names in the matrix that express one hypothesis are linked through it on their cards
- **admission provenance** (`admitted_by`) — which arm's entry-asymmetry gate let the name in: `engine-and-model`, `engine-only`, or `model-only`, the either-arm rule above; both arms' gate legs — each leg's required value, actual value, and signed distance — persist on the run audit as engine evidence
- **status** — `new`, `still-valid`, or `invalidated`, for carry-forward across runs, **origin-constrained at the appendix** (a debut's status is app-stamped `new`, never model-proposed; a carried name's appendix offers only `still-valid` / `invalidated`); an `invalidated` opportunity leaves the matrix for the **archive** ([§Archived opportunities](#archived-opportunities)), and **only a deep re-evaluation can set `invalidated`** (the cheap re-derivation never does) — the model's decision, or app-forced by a validated hard trigger with the model's proposal persisting as a status-override divergence ([§Starting parameters](#starting-parameters-calibratable)).
  There is **no "target met" exit** — an opportunity persists while it still clears re-evaluation, however far its price has run
- **attention warning** *(engine-set, cleared by the next floor-clearing deep pass)* — a non-destructive flag the cheap re-derivation raises when a live opportunity warrants a fresh deep look, surfaced on the card as **Consider Deep Audit**.
  It fires on any of three deterministic, deliberately **high-bar** triggers.
  A **tripwire** is an engine read crossing a drafted line: a forensic flag newly tripping, a **continuation-failure signal** (estimate revisions rolling over, a beat-and-raise streak breaking, or shipments diverging below sell-through), a since-flagged gain diverging hard from the engine metric family's continuation, the narrative-vs-reality read crossing into `hype`, the margin of safety compressed near the upside-exhaustion line, or a drawdown breach ([§Starting parameters](#starting-parameters-calibratable)).
  An **upside-exhaustion** read is **no arm's** re-derived base case still clearing the entry gate — the engine's live targets, and the model's frozen twelve-month expected price re-measured against the live price; while either arm still clears, the divergence is recorded and no warning fires, mirroring the either-arm admission rule.
  A **re-surfacing** is the name re-appearing in DTO discovery without earning a leftover-budget deep pass.
  Decay alone does **not** raise it — research staleness is surfaced separately by the quiet **Research stale** badge (see `last_deep_researched_at` below), so the amber warning stays reserved for an actual problem and can't blanket the matrix on a timer.
  The warning never changes the verdict or archives the name — it only prompts a Deep Audit, and the next **floor-clearing** deep pass (DTO or ATO) clears it; an inconclusive below-floor re-read leaves it standing ([§Evidence floor](#evidence-floor))
- **became-an-opportunity date** (`became_opportunity_at`) — the run it first entered the matrix; the anchor for its since-flagged return and shown on both the live card and (after departure) the archive.
  A name re-discovered *out of the archive* starts fresh, so this resets; a name that merely re-surfaces while still live keeps it
- **last deep-research date** (`last_deep_researched_at`) — when its qualitative deep research (Step 5) was last refreshed.
  The cheap re-derivation runs on the matrix tail each DTO run, but a deep pass happens only on a rotation-slice pick or a leftover-budget re-surface (DTO) or a user-chosen **Deep Audit** (ATO), so this marks how fresh the qualitative read is (the quant read is always current).
  It drives two things: an opportunity deep-researched **earlier today** (the current calendar day in the user's local timezone) shows a green **Deep-researched today** confirmation; one whose last deep pass is older than the **~4-week** research-freshness window shows a quiet, informational **Research stale** badge (distinct from the amber attention warning, which it never raises on its own)
- **since-flagged performance** *(engine-attached, present once the idea has a prior run — i.e. carried-forward)* — the running return since it became an opportunity (`became_opportunity_at`; absolute and vs sector / market), the maximum drawdown over that window, and the continuation state of the engine's archetype metric family, reconstructed from price history each run ([§Outcome learning](#outcome-learning-calibration))
- **accuracy scores** — at each horizon, for the model's prices and for the engine's base values, derived from the lifecycle's episodes and their checks ([§Outcome learning](#outcome-learning-calibration)); rendered on the card and read by the model in its self-review alone
- **owned / not-owned** — the holdings cross-reference's display-only flag ([§Holdings cross-reference](#holdings-cross-reference))

The fixed archetype / risk / horizon / status vocabularies keep the matrix stable and the list evolving rather than churning — an idea persists with an updated status instead of silently reappearing or vanishing.

**What each re-evaluation path refreshes.**
The record is touched by two paths of different reach and different power — the dividing line is that **only the deep path can archive** ([trade-opportunities-workflow.md §Step 7](trade-opportunities-workflow.md#step-7-continuity-check--carry-forward), [§Step 5](trade-opportunities-workflow.md#step-5-per-candidate-validation-loop)):

- The **cheap re-derivation** (engine-only — run on the matrix tail every DTO run, and on demand as ATO's **Quick Audit**) refreshes the **engine-computed fields**: the since-flagged performance, the engine metric family's continuation state (for a `structured`- or `filing`-class family; a `research`-class anchor has no engine feed and holds its last read), the narrative-vs-reality ratio, the forensic computations, the engine's deterministic risk tier, and the re-derived scenario targets.
  **A refreshed engine tier never re-places the card**: the cell is the model arm's frozen tier × horizon, the refreshed engine read updates the baseline beside it, and a newly disagreeing pair surfaces through the divergence tag ([trade-opportunities-workflow.md §Step 7](trade-opportunities-workflow.md#step-7-continuity-check--carry-forward)).
  It **never re-rates a survivor and never archives** — an exhausted-upside or tripwire signal it detects raises the non-destructive **attention warning** above instead of an exit.
  The **model-authored fields freeze between deep passes**: the thesis document, the conviction, the expected prices, the tier / horizon (the card's placement), the detection mode, the leading metric and the status all hold their last deep-pass values.
  Frozen is not inert: the model's twelve-month expected price is a **number, so the engine re-measures it against the live price and re-runs the model arm's entry gate on every cheap pass** — no model call, exactly as it re-runs its own (the either-arm rule; the warning fires only when neither arm clears).
- The **deep re-evaluation** (the full Step-5 loop — run on a DTO rotation-slice pick (the maintenance-priority queue), a re-surfaced name that won leftover DTO budget, or a user-chosen ATO **Deep Audit**) re-interprets everything against fresh research, rewriting **both** kinds (when it *completes* — a re-read that falls below the evidence floor rewrites nothing: an inconclusive refresh holds the last verdict — [§Evidence floor](#evidence-floor)), writing a fresh thesis document and appendix, and is the **sole path that can judge a name `invalidated`** ([§Archived opportunities](#archived-opportunities)).
  It is **time-aware about the prior record** without a weighting knob: the prior thesis document and the prior analysis ride the prompts verbatim, each with its date, and the self-review judges them against the realized price path and the accuracy record before the new document is written ([trade-opportunities-workflow.md §Step 5f](trade-opportunities-workflow.md#step-5f-self-review)); every engine number is recomputed fresh regardless, and the anti-anchoring guards (the cap-only since-flagged read, the graph-blind discovery route) are untouched.

The job's signals are tiered by how they're sourced, mapping onto the engine / research split (full catalog in [data-sources.md](data-sources.md)).
**The Market Signal Report's data-source logic is unaffected** — these are additive, suite-only feeds.
**All FMP requests (the report and both local jobs) use one shared credential, now upgraded to the paid tier**; the report's existing calls behave identically on it (see [data-sources.md §Local analysis suite — shared sourcing](data-sources.md#local-analysis-suite--shared-sourcing)).

- **Already built** — commodity positioning (CFTC COT) and per-stock options activity (Schwab chains).
- **FMP paid tier — the broad working & discovery feed (deterministic engine):**
  - *Fundamentals, valuation & growth:* financial statements, ratios, revenue **segments**, owner earnings, DCF, and **multi-year growth** (`financial-growth` — per-share revenue / EPS / FCF CAGRs feeding the value-creation read, and the **operating-reality-vs-price** fallback when analyst coverage is too thin to read revisions — [§The two non-negotiables](#the-two-non-negotiables)).
  - *The revision signal:* analyst estimate consensus (snapshotted run-to-run for velocity) plus the analyst-action flow — the rating-distribution time series (`grades-historical`), price-target trend (`price-target-summary` / `-consensus`), and upgrades / downgrades; and earnings surprises.
  - *Forensic gate:* `financial-scores` — **Altman Z-Score + Piotroski** — a drop-in for the quality / forensic gate, alongside the margin-vs-revenue and cash-flow-vs-income divergences computed from the statements.
  - *Positioning (all symbol-keyed):* insider buys / sells + per-symbol statistics, **SC 13D / 13G activist / large-stake filings**, and **Senate / House congressional trading**.
    (FMP **13F institutional ownership — including the holder-level analytics — is off-plan**; institutional flow falls back to SEC EDGAR 13F or is omitted, and is held out of the grade until calibrated regardless — [data-sources.md §FMP — current paid-plan tier audit](data-sources.md#fmp--current-paid-plan-tier-audit).)
  - *Discovery:* the **company screener** (coarse universe slicing + tradability gate — no fundamental field), **stock peers** and **industry classification** (theme → exposed-name expansion), and **market-wide event feeds** (newest **insider buys**, **M&A**, **8-K** material events, movers, IPOs).
    **The `*-bulk` endpoints are off-plan** ([data-sources.md §FMP — current paid-plan tier audit](data-sources.md#fmp--current-paid-plan-tier-audit)), so the universe is **not** pre-scored: the multi-factor composite and forensic reads are computed **per candidate** on the budget-narrowed set, the **per-symbol rate discipline binds** (the discovery-breadth budget exists to ration it), and names are also *generated* by the model-led research lane ([§The pipeline](#the-pipeline)), not only by these feeds.
- **FMP structured news (paid key):** ticker-tagged, dated headline / snippet / source-URL feeds — market-wide (`news/general-latest`, `news/stock-latest`) orienting the top-down theme scan, and symbol-scoped (**Search Stock News** `news/stock`) for a candidate's narrative / sentiment / catalyst read.
  The **press-release feeds (`news/press-releases-latest` / `news/press-releases`) are off-plan** — primary-source disclosures come from `sec-filings-8k` + the web loop instead ([data-sources.md §FMP — current paid-plan tier audit](data-sources.md#fmp--current-paid-plan-tier-audit)).
  This is a **structured surfacing layer**, not a replacement for the web loop: the feed surfaces the story, the keyless web tool deep-reads the article URL.
  The headlines ride the gathering brief as **leads** — what to pursue, never evidence a write-up may rest on ([web-research.md §The research loop and context management](web-research.md#the-research-loop-and-context-management)).
- **Keyless feeds:** **short interest** from FINRA (consolidated biweekly — FMP has no short-interest endpoint); **commodity spot / contract prices** from FRED (daily energy + monthly IMF metals incl. uranium) and FMP's daily commodity series (copper `HGUSD`, gold `GCUSD`, silver `SIUSD` — the identity table in [data-sources.md §Financial Modeling Prep](data-sources.md#financial-modeling-prep)); **CFTC COT** (already built).
- **Engine-computed price-action confirmation:** relative strength (vs the market / sector) and multi-year base-breakout proximity, derived from equity price history (the FMP dated-EOD deep history, reusing the portfolio engine's momentum / volatility computations).
  A cross-archetype **confirmer, not a trigger** — it adjusts conviction, never substitutes for the leading-metric anchor (the overlay the historical winners consistently showed: a multi-year base → high-relative-strength breakout).
- **SEC EDGAR — authoritative primary-source cross-check:** the numbers that drive final grades / targets are reconciled against EDGAR filings + XBRL (the compute-don't-guess, primary-source stance), with FMP as the broad working feed; for an app-eligible new listing / separation, S-1 / Form 10 history is the source set the reconstruction research topic reads ([§Evidence floor](#evidence-floor)).
  Because the FMP fundamental and positioning feeds are symbol-keyed, **ticker→CIK resolution is a non-blocking enhancement** (needed only to extend the SEC cross-check to an arbitrary name), not a hard prerequisite.
- **Web-research lane (the bounded loop):** the signals with no structured feed — **DRAM/NAND ASP direction** (TrendForce is paid), **supply discipline** (capex cuts / curtailments, which live in transcripts and news), customer-capex corroboration, the **economist's leading indicators** (PMIs, book-to-bill, freight, the cycle), and the qualitative narrative read — plus the **deep read** of the article URLs the FMP news feeds and screens surface ([web-research.md](web-research.md)); Step 3c's targeted research-watchlist refresh (drafted one node per DTO run) uses the same current-search infrastructure inside the discovery budget, without opening the full per-candidate loop.

## Holdings cross-reference

After selection, a **deterministic post-step** flags any opportunity that overlaps the user's current holdings (owned / not-owned), so the two features cohere — an idea you already hold is surfaced as such.
Crucially this runs *after* candidate discovery and selection, so holdings never influence which opportunities are found or chosen; it reads only the holdings list, never Portfolio Analysis's stores.
Trade Opportunities therefore stays genuinely independent of the account.

## Continuity and isolation

The job retains its most recent N runs and feeds the prior run into the next.
A carried name's continuity is the **deterministic load of its lifecycle's own prior documents** — the thesis document, the analysis and the appendix values — by lifecycle id, never a semantic recall, and the job writes nothing to vector memory ([local-models.md §Run history and continuity](local-models.md#run-history-and-continuity)).
A fresh re-entry of a departed ticker is a new lifecycle and loads nothing from the prior one ([§Archived opportunities](#archived-opportunities)).
Output is firm and does not churn between runs absent hard data.

## Outcome learning (calibration)

The job's model arm is a forecast — an expected price at three horizons — and so is the engine's base value beside it; outcome learning is the engine-computed record of how those forecasts resolved, kept so the model reads its own track record and the baseline's before it writes again.
It shares Portfolio's record and mechanics ([portfolio-analysis.md §Outcome learning](portfolio-analysis.md#outcome-learning-calibration)) with one addition: the job has no book, so the names it turned away can be recorded beside the names it picked, and each episode carries its **decision class**.
The record scores prices, not decisions — no per-decision verdict is ever assigned, and nothing is derived beyond the scores.

**The episode store.**
An **episode** is a price record: the symbol and its lifecycle id, the decision class — `picked`, `gate-reject` or `excluded` — the creation date, the spot that day and the anchor close that bridges the record across a later split, the model's expected price at three months, twelve months and three years, and the engine's base value at the same horizons — nothing else, the engine's bear and bull edges staying on the run record.
The continuity pass opens one, after the per-candidate loop, for every candidate whose appendix carried prices this run and that has none, or whose latest episode is a month or more old (the cadence is Portfolio's — [portfolio-analysis.md §Starting parameters](portfolio-analysis.md#starting-parameters-calibratable)): a pick on its debut and on each later deep pass past that cadence; a debut no arm's gate admitted, as `gate-reject`; a debut a hard trigger excluded, as `excluded` ([trade-opportunities-workflow.md §Step 7](trade-opportunities-workflow.md#step-7-continuity-check--carry-forward)).
An `insufficient-evidence` abstention has no prices and opens none — the floor runs before interpretation ([§Evidence floor](#evidence-floor)) — a watchlist node that is never promoted leaves none, and a carried name's inconclusive re-read opens none.
The store is **append-only**: an episode is never updated or deleted, the checks below are written onto it once each, and it persists independently of the run retention window, the archive and matrix presence — a departed lifecycle's episodes keep maturing on the same clock, and a re-entry opens episodes under its new lifecycle while the old ones run to their horizons ([§Archived opportunities](#archived-opportunities)).
Which episode is a lifecycle's latest is **insertion order**, matching run identity across the suite; the creation date is data, never identity.

**The checks.**
An episode's horizon dates are its creation date plus three, twelve and thirty-six calendar months.
A horizon is **due** when its date is on or before the run's ET session date and nothing has been written for it — one query over the store, so nothing is ever re-scored and a horizon is scored by the first run on or after its date, however many runs later that is.
The checks run **at job start, before discovery, in every mode** — Discover, Deep Audit, and the engine-only Quick Audit alike, since they need no model — so this run's self-reviews read every check that has come due by its session and a resumed run never re-scores a written horizon ([trade-opportunities-workflow.md §Step 2](trade-opportunities-workflow.md#step-2-load-shared-context)).
For every due horizon the pass reads the **close on the horizon date, or the last session at or before it within the drafted proximity**, from the symbol's dated-EOD series, refreshed through the shared price-bar cache for every symbol with a due horizon — a live pick, a departed one and a turned-away name alike, since the record measures the forecast.
The episode's prices first cross the **split-adjustment bridge** where the series was re-based since the episode was created ([portfolio-analysis.md §Starting parameters](portfolio-analysis.md#starting-parameters-calibratable)).
The pass then writes the **check** onto the episode — the horizon, the check date, the close read, and for the model's price and for the engine's base value the expected price and the **per-check score**, one hundred times one minus the absolute error over the close, floored at zero.
A horizon whose refresh **failed** stays **pending** and is due again next run.
A horizon whose refresh **succeeded but served no close inside the proximity** — a delisting, an acquisition, a ticker change, a symbol the source never covered — or whose episode's anchor bar the served series no longer carries, is written **unscorable** at once with its cause: it leaves the due query, counts in no score, and the symbol spends no further pull.
The proximity, the score formula and the aggregation are Portfolio's drafted constants and are not restated here ([portfolio-analysis.md §Starting parameters](portfolio-analysis.md#starting-parameters-calibratable)); the episode is the log, and every check and every unscorable state is readable on it.

**The accuracy scores.**
From the checks the pass derives each lifecycle's **accuracy scores**: at each horizon, the mean per-check score over the lifecycle's checks at that horizon, for the model and for the engine separately, 0 to 100, with "no score yet" before the first check, and beside each score the date of the last check that moved it and whether the prior analysis read it.
A pick's scores persist with the opportunity and render on its card ([§Storage and display](#storage-and-display)).
They reach the model in the **self-review alone**, as the realized block's accuracy record — the six scores each with its last-moved date and whether the prior analysis read it, the individual checks written since the prior analysis up to the drafted count, and the fixed sentence when none landed ([trade-opportunities-workflow.md §Step 5f](trade-opportunities-workflow.md#step-5f-self-review)); the thesis-document message carries no accuracy section and draws on the review.
A turned-away name's checks and scores sit in the store with their decision class and reach no prompt and no card: what the model argued for and the gates refused, and what the price then did, is readable there, and whether that record gets a display surface is a deferred decision — the same deferral Portfolio's record carries.

**The since-flagged read.**
Beside the episodes the engine keeps a **continuous since-flagged read** for every carried opportunity, in two parts.
Its **price-derived parts** are the running **absolute return, return vs sector and vs market, and running maximum drawdown**, measured from the **first daily close after `became_opportunity_at`** — a consistent evaluation anchor, deliberately not called an executable price: daily-bar opens are the least reliable field in the feed, and the same-day bar the decision could not have traded is never used — to the **latest cached daily close**, split-adjusted and price-only (total return carried supplementary where dividend data exists), reconstructed purely from the cached **FMP dated-EOD bars**.
The sector leg reads the record's **entry-stamped sector identity** — the sector label in hand when the record was created plus its resolved SPDR benchmark symbol per the label→ETF mapping in [data-sources.md §Financial Modeling Prep](data-sources.md#financial-modeling-prep), refreshed at each deep pass, never a render-time classification call — and a record with no valid mapping carries the typed `sector-unscorable` state for that leg while the absolute and market legs compute.
They are refreshed on each run *and* **re-derived at render as a zero-job freshness floor**: a local recompute over the per-ticker daily-bar cache ([§Storage and display](#storage-and-display)), never a fetch on every open, so the displayed performance stays current even between runs.
The read's other part is the **continuation state of the engine's archetype metric family** — persisted, stalled or reversed, under the inflecting gate's family rules ([§Starting parameters](#starting-parameters-calibratable)) — which needs a structured re-pull and so refreshes only on a cheap re-derivation or a deep pass, never at render, and only where the family reads from structured or filing-cadence data.
The read is live from the **first run after the idea was added** (a brand-new pick carries none on its debut run — there is no elapsed window yet), and because each run reconstructs the full daily series from the first-surfaced date, the curve carries every day's point regardless of run cadence.
It is **one engine primitive with three readers**: the **matrix display** (the since-flagged curve and its current numbers, rendered inline beside each carried-forward idea — [§Storage and display](#storage-and-display)), the **cheap sweep's tripwires** ([§The opportunity](#the-opportunity)), and — for a carried name under deep re-evaluation — the **self-review and the thesis document as reflexivity-disciplined context**: a since-flagged gain unmatched by metric progress reads as building multiple-unwind risk and **caps** conviction, a drawdown with the metric intact reads as improved asymmetry rather than a reason to abandon, and a gain *matched* by metric progress is held **neutral, never boosted**, since the metric is already in the engine's composite and crediting the price gain too would double-count it.
That cap-only stance is **prompt-side discipline** the task states and the audit record preserves for inspection, not an app clamp, and no machinery detects a violation.

Three disciplines keep the record honest.
**The engine keeps score and never plays**: every check is engine-computed from the dated-EOD series, the model's self-assessment is prose the review persists, and nothing the model writes alters a check or a score.
**The record scores the forecast, not the decision**: a pick, a gate reject and an exclusion score alike, the decision class is a tag, and no verdict on the turn-away is derived from it.
And **nothing is derived beyond the scores**: no cohort reads, no spreads, no calibration proposals — the learning rides the review's own answer to what should change in how a name is analyzed, and the engine's drafted constants move only on the user's reading of the record.

## Archived opportunities

When an opportunity leaves the matrix it is **archived, not dropped** — a price-tracked record of the job's departed picks, so "what happened to the ideas you showed me" is answerable rather than silently lost.
The archive holds the **most recent 100** departed opportunities (oldest evicted first).

**One way out, and it is always a failed deep re-evaluation.**
An opportunity stays an opportunity until a **deep** re-evaluation judges it is no longer one — there is **no "target met" / "didn't meet target" exit**, and hitting the expected price with upside still remaining keeps it live.
The single archive trigger, `failed-reevaluation`, fires **only from a deep pass** that judges the name `invalidated` ([trade-opportunities-workflow.md §Step 7](trade-opportunities-workflow.md#step-7-continuity-check--carry-forward)) — and a deep pass reaches a live name three ways:

- **inside DTO, by the reserved rotation slice** — each run spends a small configured share of the deep budget (floored at one slot) on live opportunities in **maintenance-priority order** (warning-bearing names first — a tripwire or continuation break never queues behind an uneventful stale name — then proximity to the next earnings date, then threshold-near, then stalest), backstopped by a **max-age service level** and its reserved overdue sub-slot, so every live name is eventually re-deep-researched — a stalest-first drain guaranteed at one or more overdue names per run ([trade-opportunities-workflow.md §Step 4](trade-opportunities-workflow.md#step-4-candidate-consolidation)) — without depending on chance re-surfacing or user diligence;
- **inside DTO**, when the name **re-surfaces through discovery and wins leftover deep-research budget** into the Step-5 loop (the oldest-deep-researched re-surfacers first); or
- **inside ATO**, when the user **selects it for a Deep Audit**.

The deep pass is where a *qualitative* erosion the cheap read can't see (a competitive threat surfaced in research) retires a name, and equally where a deterministic exhausted-upside or continuation-failure finding is *confirmed* under fresh research rather than acted on blind — and where a validated **hard forensic trigger** ends a carried name deterministically: the app forces `invalidated` regardless of the model's proposed status, the divergence recorded ([§Starting parameters](#starting-parameters-calibratable)).
The **cheap re-derivation never archives**: when it detects exhausted upside or a tripwire (a continuation-failure signal among them), it raises the non-destructive **attention warning** ([§The opportunity](#the-opportunity)) so the user can choose a Deep Audit — turning what was an automatic exit into a prompt.
The deep pass is **fail-soft**: a missing input is a gap that holds the opportunity on its last verdict, never an archival — only an affirmative failing signal under deep research archives.
The cost is deliberate but bounded: the matrix is **self-flagging and slowly self-refreshing, not self-cleaning** — a name the user never re-audits and that never re-surfaces lingers (cheap-refreshed, aging, and warning-badged) only until the rotation slice reaches it — a warning pulls it to the front of the maintenance queue, and the max-age service level queues even the uneventful case — drained through the reserved overdue sub-slot with the backlog surfaced, never a wall-clock promise ([trade-opportunities-workflow.md §Step 4](trade-opportunities-workflow.md#step-4-candidate-consolidation)).
Staleness alone never archives a name — but it no longer accumulates unbounded either.

**Only the price is tracked afterward — nothing else.**
An archived pick gets **no further analysis, no deep research, no model call**.
Each run refreshes only the **price-derived components** of the since-flagged read — running return since it became an opportunity (absolute and **vs sector / market** — the benchmark from the frozen record's stamped sector identity, [§Outcome learning](#outcome-learning-calibration)) and maximum drawdown, **not** the engine metric family's continuation state (that needs a structured re-pull the archive deliberately skips) — the same stateless daily-bar reconstruction the live matrix uses ([§Outcome learning](#outcome-learning-calibration)), its per-symbol bar request budgeted as the endpoint surface's **archive-price maintenance population** ([data-sources.md §Trade Opportunities — endpoint surface](data-sources.md#trade-opportunities--endpoint-surface)), so the running performance stays current at ~zero marginal cost while the rest of the record sits frozen.
Its episodes keep maturing in the episode store independently of the archive, scored by the same checks at their horizons ([§Outcome learning](#outcome-learning-calibration)).

**What the archive card shows is retrospective, never forward-looking.**
It carries the descriptive record that *can't go stale* — the thesis document with its bear case, the archetype, the leading metric — frozen as of departure, plus `became_opportunity_at`, the departure date, the failing signal that retired it, its **admission provenance** (`admitted_by` alone — both arms' gate legs live on the run audit, never the archive row), and **conviction at exit** — the model arm's value (a record of where it ended, not a live call).
The **expected prices are deliberately not shown**: a frozen target beside a live price reads as a current call it no longer is.
The one live element is the since-flagged return.
The archive is therefore a **price-tracking record, not an outcome-graded scorecard** — the accuracy scores stay with the episode store ([§Outcome learning](#outcome-learning-calibration)) and never surface here.

**Re-entry is a fresh start, and the archive never promotes itself.**
If a later run independently re-discovers an archived name as an opportunity, it is **removed from the archive** and enters as a **new** opportunity with a new `became_opportunity_at`; **none of the archived record influences the new one** — the [anti-reflexivity / no-double-count invariant](trade-opportunities-workflow.md#step-5g-interpretation) the whole suite holds: the new verdict is re-derived from current fundamentals and research, and a re-entry is a **debut**, so it carries **no since-flagged read at all at its first interpretation** (the cap-only discipline resumes only once the new lifecycle is itself carried forward — the old lifecycle's price path never enters the new call).
**Re-entry is matched by ticker**, deliberately — the *fresh* re-entry carries no thesis-lineage identity to match on, so the dedup key is the bare ticker, giving a clean invariant: a ticker is in exactly one state — **live** (matrix), **departed** (archive), or neither, never both; a ticker that becomes a live opportunity again vacates any archived entry for it.
The one accepted edge is a **same-ticker-new-thesis** re-entry, which simply retires the prior tombstone early (the archive holds at most one slot per ticker — the most recent departure); the lost record is low-stakes price history, not a correctness break, and the prior lifecycle's episodes are untouched.
Critically the archive is **passive**: a large archived gain never pulls a name back into analysis — that would be momentum-chasing — re-entry happens **only** through independent fresh discovery.

The archive is distinct from the other carried stores: the **coverage ledger** remembers agenda coverage, the **opportunity graph** holds *upstream* discovery memory (watchlist hypotheses re-read each run — [§Discovery memory](#discovery-memory-the-opportunity-graph)), the **validated matrix** holds *current* picks, and the archive holds *departed* picks tracked on price alone.
The **episode store** ([§Outcome learning](#outcome-learning-calibration)) sits outside this group — it never feeds a run and never carries an idea forward; it only remembers what each arm expected so the forecasts can be scored.

## Starting parameters (calibratable)

Trade Opportunities is not yet built; the deterministic rules and thresholds below are the **starting calibration surface** the shared engine and the discovery funnel will run on — codeable now, **shape-tested immediately against the case library**.
The pattern-lens's shipped, versioned set of dated historical metric series ([§The lenses](#the-lenses)) doubles as a regression harness: each drafted gate runs over the library's cases as a **functional test of its shape** (a turn rule that rejects the canonical turn of its own archetype is broken).
That runs under the discipline that guards against hindsight-fitting — **constants are shaped only against the development partition, the locked holdout (ordinary failures, near misses, base-rate names) is never tuned against, and library performance is never cited as evidence the gates *work***.
The constants then move only on the user's reading of the accuracy record ([§Outcome learning](#outcome-learning-calibration)) — no realized outcome proposes or applies a change.
They mirror Portfolio's calibration surface ([portfolio-analysis.md §Starting parameters](portfolio-analysis.md#starting-parameters-calibratable)); the **forensic trips are the same drafted constants** that doc sets out, since both jobs share one engine.
The **narrative-vs-reality trips are drafted separately, one per job**: Portfolio reads a cap when multiple expansion outruns revisions by more than ~1.5×, while this job reads `hype` when multiple expansion exceeds 70% of the price move (the row below) — two job-specific trip rules over the same engine-computed read, not one shared constant.

| **Upside-exhausted gate** ([§Archived opportunities](#archived-opportunities)) | The upside re-derivation flags **exhausted upside** when **neither arm** clears the full entry-asymmetry gate above — the post-haircut base-case forward return against the tier-scaled bar, with the shape and emerging-track legs re-tested per that row, run on the engine's live targets and the model's frozen twelve-month expected price alike — i.e. the name would no longer clear the gate that admitted it, on any arm that could have admitted it. Same gate, re-run against the live price; fail-soft on missing inputs (gap holds). |
| **Evidence-floor freshness basis** ([§Evidence floor](#evidence-floor)) | Typed per input, computed with the engine at Step 5c from timestamps + cadence into **fresh / stale / freshness-unscorable** (an input whose as-of the source doesn't carry) with named gap reasons: **quote / price bars** — current through the latest completed session (the job-time fetch self-satisfies); **structured / filing metrics and financial statements** — an observation for the latest *expected* reporting period, with a drafted **~45-day filing grace** past period end (data older than one full period + grace is stale). Deliberately distinct from source-quality recency, which only weights (`freshnessSlaDays` / `recencyScore` — [web-research.md §Source quality and evidence weighting](web-research.md#source-quality-and-evidence-weighting)): this narrow floor is the suite's one deliberate gate on age, and `freshness-unscorable` reads as a degraded input, not an automatic abstention, unless the input is itself floor-bearing. |
| **Research cache (cross-run)** ([§Failure posture](#failure-posture)) | **Document-level only** — fetched / extracted pages keyed by normalized URL, the original retrieval time the immutable vintage, reusable within the shared **~4-week** window; searches always run live, and the reused-vs-fresh split is logged per pass. The full contract is in [§Failure posture](#failure-posture). |
| **Watchlist cap eviction** ([§Discovery memory](#discovery-memory-the-opportunity-graph)) | When the retention cap binds at a watchlist add ([trade-opportunities-workflow.md §Step 3c](trade-opportunities-workflow.md#step-3c-carried-forward-watchlist-re-check)): retire the node with the **oldest successful refresh** first, tie-broken by ticker; persisted reason **`capacity-evicted`**, graph history retained; no episode opens, since a watchlist node carries no prices. |
| **Archive retention** ([§Archived opportunities](#archived-opportunities)) | Most recent **100** departed opportunities, oldest evicted first. |
| **Episodes & accuracy checks** ([§Outcome learning](#outcome-learning-calibration)) | The episode cadence (a month since the lifecycle's latest), the horizon dates (three, twelve and thirty-six calendar months), the few-session proximity, the per-check score and the mean aggregation are Portfolio's drafted constants and are not restated here ([portfolio-analysis.md §Starting parameters](portfolio-analysis.md#starting-parameters-calibratable)); this job adds only the decision-class tag. The store carries no cap: it is append-only and bounded by one open horizon set per episode, each closing by thirty-six months plus the proximity. |
| **Length bands** | The write-up, distillation, analysis, review and thesis-document bands are the shared ones at [portfolio-analysis.md §Starting parameters](portfolio-analysis.md#starting-parameters-calibratable); this job adds bands for the hypothesis document, the watchlist review and the refresh write-up, drafted at plan time. |

The **configurable settings** distinct from these engine constants take their **defaults at plan-time** as user-tunable knobs ([configuration.md §Local Analysis Suite Configuration](configuration.md#local-analysis-suite-configuration)), not here.
The first is the **DTO deep-research budget** — the single candidate-validation compute knob: how many names DTO deep-researches per run, a reserved **rotation slice** for live opportunities in maintenance-priority order first (its share and max-age service level configurable), then **new names**, then leftover on re-surfaced existing opportunities oldest-deep-researched first; ATO's depth is bounded by the user's selection, not a setting.
The rest are the **discovery coverage window**, the small **research-watchlist refresh cap**, the watchlist retention cap and carry horizon, and the research context-management budget — the analysis prompt's input budget that decides whether the write-ups are distilled ([configuration.md §Research Context Management](configuration.md#research-context-management-hierarchical-distillation)).

## Storage and display

Each run persists its matrix of opportunities together with an **audit record** that makes the run traceable: sources and retrieval timestamps; the discovery and screening inputs — the route plan with its coverage-rotation selections and completions, each route's hypothesis document and appendix, the watchlist review and its decisions, and the refresh write-up where the lane ran; and, per candidate, the write-ups as written, the distillation shape and call count, the analysis, the review, the page roster, the research gaps, the engine's computed reads with their provenance flags, the thesis document and the appendix values, the admission provenance with both arms' gate legs, the recorded **divergences** (the prior and current archetype, the tier / horizon pair) and any status-override divergence, model ids and quantizations, and the prompt stamp.
The field set is specified once in [storage.md §Local Analysis Suite Storage](storage.md#local-analysis-suite-storage).
The **opportunity graph** (the carried-forward discovery memory — hypothesis nodes with their documents and appendix fields, and company nodes with their status, leading metric, refresh timestamps and hypothesis link — [§Discovery memory](#discovery-memory-the-opportunity-graph)) and the separate **discovery-coverage ledger** persist **alongside the audit record as carried stores**, reloaded at the next run's Step 2, never as audit-record fields; retention keeps the last N runs ([storage.md](storage.md)).
The **archive** of departed picks ([§Archived opportunities](#archived-opportunities)) persists separately — the most recent 100, each a frozen verdict snapshot (the thesis document + conviction-at-exit + the departure date and failing signal) plus `became_opportunity_at`, with the since-flagged read recomputed statelessly each run rather than stored ([storage.md](storage.md)).
The **episode store** persists independently of the matrix, the archive and run retention ([§Outcome learning](#outcome-learning-calibration)).
The **Trade Opportunities page** renders the 3×3 matrix, each cell listing its opportunities with archetype, the thesis document's summary, leading metric, detection mode, conviction, the **expected price at twelve months beside the engine's base target** (the three-month and three-year pairs on expand, shown distinct from the backward anchor), status, **its `became_opportunity_at` and `last_deep_researched_at` dates**, its **accuracy scores** for both arms, the hypothesis it expresses (linking the names that share one), and — for a carried-forward idea — its **since-flagged performance** (return since it became an opportunity, absolute and vs sector / market, with the running curve and maximum drawdown); a separate **Archived opportunities** view lists the departed picks with their frozen record, departure date, and live since-flagged return — **no forward prediction** (see [interface.md](interface.md)).

**How the two arms render: progressive disclosure, not paired columns in the matrix.**
Portfolio's card can afford a paired grid because it renders one card per holding down a page; a TO cell holds several cards and the whole point of the 3×3 is scanning nine cells at once, so the arms are disclosed in three stages.
On the **matrix card** the **model arm headlines** — its conviction and its twelve-month expected price are the numbers shown, and the cell itself is the model arm's tier × horizon — with a quiet **divergence tag** in the existing badge family when the arms materially disagree (conviction level, the twelve-month prices' gap, or a tier / horizon divergence — the engine's derived pair against the model's placement), and the tag is the affordance rather than a second column.
On **card expand** the paired engine / model view appears in full — the three price pairs, the engine's bands and provenance flags, the engine's tier and horizon, and the accuracy scores — reusing the measured-reveal idiom rather than a new component.
In **List view** the pairing is native — the `.ana-grid` gains engine-target, model-target, and divergence columns, since comparison is the task there.
One honesty requirement rides the card: because membership is an **either-arm gate fact** ([§The opportunity](#the-opportunity)) while the headline number is the model's, **both single-arm states are tagged explicitly** — and the more misleading of the two is `engine-only`.
An **`engine-only`** card shows a model price that **did not itself clear the gate**: the name is in the matrix on the engine's read, so without the tag the headline reads as the admitting number when it is the refused one.
A **`model-only`** card is the inverse and needs saying for the opposite reason — the headline number *is* what admitted it, with the deterministic baseline dissenting — so the reader knows the name rests on the model's judgment alone.
`engine-and-model` needs no tag: the arms agree, and an untagged card is the consensus case.

The page carries **both jobs' controls**: a **Discover** button (DTO) and, gated on selection, an **Audit** button (ATO) that forks to **Quick Audit** / **Deep Audit** (a large Deep-Audit selection confirms first).
Each opportunity card carries a **selection control** (with select-all / deselect-all on the matrix) and three lifecycle affordances: an amber, *actionable* **Consider Deep Audit** warning when the attention flag is set ([§The opportunity](#the-opportunity)); a green **Deep-researched today** confirmation when `last_deep_researched_at` falls on the current local-timezone day; and a quiet, *informational* **Research stale** badge (a muted, non-alarming treatment, never the amber action color) when the last deep pass is older than the ~4-week research-freshness window — the visual counterpart of an aging thesis document, computed at render from `last_deep_researched_at`, no data pull.

**Matrix / List views.**
The 3×3 card matrix is the page's **default and canonical** view — its risk×horizon structure is load-bearing ([§The opportunity space](#the-opportunity-space)).
A **Matrix / List toggle** adds a second lens over the *same* opportunities: **List** flattens all nine cells into one ranked, sortable table (the `.ana-grid` dense-data-grid, whose sortable column headers the design system already styles), each row carrying its placed (model-arm) **risk tier and horizon** as columns — the engine's derived pair riding the paired-view columns — so the matrix dimensions survive as metadata rather than spatial position.
Sorting lives **only in the List view** (the matrix stays spatially ordered) and offers two keys, since an opportunity is **not an owned position** — there is no cost basis and no dollar gain: **forward % upside to target** (the **model arm's** twelve-month expected price against the current cached daily close, matching the headline number the card shows — the engine's rides its own column and is sortable there) and **realized since-flagged return** (the running return since `became_opportunity_at` — [§Outcome learning](#outcome-learning-calibration) — absent on a debut pick, which therefore sorts last under this key).
The **default sort is forward % upside, descending**, deliberately: it ranks by *remaining asymmetry* rather than by what has already run up, keeping faith with the suite's **cap-only, anti-momentum** stance ([§Outcome learning](#outcome-learning-calibration)) — the since-flagged key is offered but is never the default.
List rows keep the same per-card **selection control and lifecycle badges** the matrix cards carry, so an ATO Audit ([§The two jobs](#the-two-jobs)) can be driven from either view.
The **Archived opportunities** view — already a flat list — gains the same sort affordance (since-flagged return / maximum drawdown; default departure-date descending).
The toggle and sort are **display-only** — they reorder already-computed, already-persisted fields and touch no engine, schema, or workflow — and follow frontend-craft requirements (keyboard-operable sortable headers with `aria-sort`, a stable sort, a reduced-motion reflow, and the empty-list / all-debut-pick states).
The view toggle is a small **design-system extension** — a minimal tracked-caps ghost-text control (≤ 2px radius, never a pill segmented control — [interface.md](interface.md)).

The card's **price reads share one basis: the latest cached daily close** (FMP dated EOD).
The **since-flagged performance** is re-derived at render as a **zero-job freshness floor** — a local recompute over the shared **per-ticker daily-bar cache**, whose lazy, fail-soft refresh rule — after-hours-only, at most once a day, both constants calibratable — is specified once in [storage.md §Local Analysis Suite Storage](storage.md#local-analysis-suite-storage), so opening the page costs no fetch once the day's bar is cached (note the cache's ET refresh basis is distinct from the user-local day the *Deep-researched today* badge uses).
The displayed **% upside to target** is likewise recomputed against that same cached close, so one consistent current price drives every price read on the card.
The live **FMP `quote`** is **not** a render dependency and not a persisted current-price field — it is a **job-time engine input** (it sets the target *level* and runs the entry gate when a cheap re-derivation or deep pass runs, logged in the audit record); the only seam is that the gate decides against the job-time FMP price while the display uses the cached daily close, which can differ by the intraday-vs-close gap at the exact threshold margin (immaterial for a thesis tool).

## Failure posture

The execution gate's **presence** preconditions are uniform across the suite — the local model daemon + roster configured ([local-models.md](local-models.md)), a connected Schwab account ([schwab-integration.md](schwab-integration.md)), and the shared FMP / FRED credentials present ([portfolio-workflow.md §Step 1](portfolio-workflow.md#step-1-job-start-and-gate)) — so missing config or a lapsed connection blocks **every** local job, Quick Audit included.
One fork-aware relaxation sits at the **run-gate connectivity** layer: **ATO Quick Audit** is engine-only (no model call), so it **skips the daemon-connectivity check** and runs even when the daemon is **configured-but-down** — a lightweight refresh of an existing matrix.
Its cheap re-derivation reads **no Schwab data** (the options-activity signal is held out of the grade), though the Schwab *connection* stays a presence precondition like everywhere else.
**DTO and Deep Audit** take the full gate (presence + connectivity + Schwab).
Web research within a run is fail-soft (thinner evidence, lower conviction), while a hard model or persistence failure fails the run ([scheduling.md](scheduling.md)).
A user cancellation stops the whole run at the next safe checkpoint and produces no result, exactly as it does anywhere else ([run-tracking.md §Cancellation](run-tracking.md#cancellation)).
A **run-level rate-anchor load failure is likewise hard**: the Step-2 FRED `DGS10` / `DGS2` retrieval still failing after the shared bounded retries fails the run **before any per-candidate work** — the suite's canonical rate-anchor rule, homed at [portfolio-analysis.md §Failure posture](portfolio-analysis.md#failure-posture); the engine-only **ATO Quick Audit** instead fail-softs to the last cached print under the shared rate-cache max age ([portfolio-analysis.md §Starting parameters](portfolio-analysis.md#starting-parameters-calibratable)), typed `unknown` beyond it.
A discovery feeder that fails (a screen, a positioning scan, a theme sweep) degrades to fewer candidates rather than failing the run — this applies to **DTO**, which alone runs discovery; **ATO** has no discovery phase, operating only on the user-selected existing opportunities, and its **Quick Audit** is engine-only (no model call to fail), while a **Deep Audit** reuses the same fail-soft per-candidate research loop DTO does.
The accuracy checks at job start are fail-soft per horizon — a failed refresh leaves the horizon pending, never a failed run ([§Outcome learning](#outcome-learning-calibration)).

**Per-candidate checkpoint / resume.**
The Step-5 loop checkpoints per candidate ([trade-opportunities-workflow.md §Step 5h](trade-opportunities-workflow.md#step-5h-deterministic-risk-tier-gate-validation--checkpoint)), and **resume is its own entry path, distinct from a new run** — the checkpoint contract is only coherent against one discovery snapshot, so a resumed run **reopens the interrupted run's ID and pins everything upstream of the loop**: the Step-2 shared context (the prior matrix, the opportunity graph, and the run-level FRED / FMP-commodity / CFTC / CBOE pulls), the Step-3 feeder outputs, the watchlist review's decisions and the route plan, the Step-4 consolidated candidate slate with its budget / slot allocation and rotation backlog, every source's as-of timestamps, and the model / prompt versions — no re-discovery, no re-allocation.
Resume is offered from a failed / cancelled run's tracker state only while an eligible checkpoint trail exists and the pinned snapshot is younger than the drafted **~48-hour resume window** — the same shared constant as Portfolio's ([portfolio-analysis.md §Starting parameters](portfolio-analysis.md#starting-parameters-calibratable)); past it, Discover starts a new run.
A **new Discover run discards any interrupted run's checkpoints** — one coherent matrix per discovery snapshot, since candidates judged against two different slates would corrupt completeness and episode attribution — while the **document cache survives independently** under its own ~4-week freshness window.
That surviving cache is the suite's shared **document-level** cache: its unit is the fetched, readability-extracted page, keyed by the **normalized requested URL** with post-redirect final-URL provenance retained separately, and carrying its **original retrieval timestamp** — the vintage is never rewritten on reuse — so what a discarded run's spend buys the next run is the *fetches*, never the judgment over them.
Every deep pass, every Step-3b discovery lane, and every targeted Step-3c research-watchlist refresh still **executes its own current searches** (the cache satisfies only the re-fetch of an unchanged URL a current search re-surfaces); a deep pass stamps `last_deep_researched_at`, clears an attention warning or archives only when it **completes past the engine floor** — an inconclusive re-read does none of these ([§Evidence floor](#evidence-floor)); and each pass records its **reused-vs-freshly-fetched split** in the run audit ([storage.md §Local Analysis Suite Storage](storage.md#local-analysis-suite-storage)).
An **ATO Deep Audit resumes under the same contract** over its smaller pinned set (the user-selected names and the run's shared context); a **Quick Audit never checkpoints** — engine-only and fast, it simply re-runs.
