# Portfolio Analysis

Portfolio Analysis is a **local, on-demand job** that analyzes every gradable holding in the user's portfolio and recommends an action for each.
For a priceable vehicle class it writes a **thesis document** — the holding's thesis, drivers, scenarios, falsifiers and triggers argued in prose — with the model's **conviction** and its **expected share price at three months, twelve months and three years**, beside the engine's deterministic grade and scenario bands; for an unpriceable class it writes a typed role / risk read instead ([§Asset eligibility](#asset-eligibility)).
Each is grounded in the holding's fundamentals, fresh web research and the current Market Signal house view.
It runs entirely on local models (see [local-models.md](local-models.md)) and sources holdings — and the per-stock options signal — from a **connected Charles Schwab account, which is required to run the job** (manual import supplements the holdings but does not replace the connection; see [schwab-integration.md](schwab-integration.md)).

The job is built as a **research instrument**: it tests whether a local reasoner, given primary-source data and the open web, can author a defensible thesis for a held position and price it.
So the model's prose is the product under test, the engine's values are the control arm beside it, and the app checks the model's output on type alone — a price finite and positive, a rung on the ladder — never on its content ([§The holding verdict](#the-holding-verdict)).
Its results are the experiment's record, not investment guidance.

It is deliberately **prescriptive** — it issues buy/trim/hold/sell-style actions and, on priced verdicts, explicit expected prices — which is the opposite of the Market Signal Report's no-buy/sell stance ([report-structure.md](report-structure.md)).
The report forms the *house view*; this job applies that view to the specific positions the user holds.

## Triggering

The job is manual, with three independent controls rather than a sequenced flow:

- **Run analysis** is **one-touch and always starts from a fresh holdings pull**: it retrieves holdings from the connected Schwab account as its first step and runs against that pull ([portfolio-workflow.md §Step 2](portfolio-workflow.md#step-2-load-holdings)) — never a prior standalone pull (**a resumed run is the one exception**: it reopens its own interrupted run's pinned pull rather than re-pulling — [§Failure posture](#failure-posture)).
  Every holding that enters the full per-holding loop recomputes its engine reads and researches afresh; the holding's prior **analysis** rides every research prompt, dated, whatever its age, as the research's memory ([§The per-holding pipeline](#the-per-holding-pipeline) stage 3).
  With no cards selected it runs the whole book; with a **selection** active (per-card, with select-all / deselect-all — the same selection-gated pattern as Trade Opportunities' Audit) it becomes a **selective re-analysis of strictly the selected holdings**.
  Holdings left outside the selection carry their prior intrinsic verdict forward **vintage-stamped**, and the roll-up re-runs over the mixed-vintage verdicts at current weights ([portfolio-workflow.md §Step 6](portfolio-workflow.md#step-6-per-holding-analysis-loop)) — so a handful of selected holdings can be re-analyzed in minutes rather than committing to the hours-long full run.
  A held position with **no prior verdict to carry** (new since the last run, or otherwise never analyzed) is left **not analyzed** in a selective run rather than pulled in — it renders as a placeholder "run to grade" card, selectable so the next selective run can grade it; a full run still grades the whole book.
  A selective request with no readable prior run runs the whole book — there is nothing to carry, and the page cannot offer a selection without a rendered run.
  Mixed vintages are made safe **without force-including the tail**: a selective run never expands its work-list, and every concern the engine-only sweep raises surfaces as a **non-blocking card badge** on the carried holding instead, so an urgent single-holding run is never blocked by the rest of the book.
  The selective run still runs the **quick check over its unselected carried tail** (engine-only, cheap — [§The quick check](#the-quick-check-engine-only)), but only to **badge** it: an **attention flag** it raises, an **`unknown`** family it couldn't vouch for (the degraded-sweep note — [§The quick check](#the-quick-check-engine-only)), and an **unexamined evidence event** since the holding's last full pass (the deterministic **evidence-event list** — [§Starting parameters](#starting-parameters-calibratable)) each ride the card as a badge, none re-analyzing the holding.
  A carried long-side verdict that **now sits on a net-short position** is marked **`side_reversed`** — a directional verdict is only ever authored for a long, so its thesis is now for the opposite position — and badged accordingly ([§Asset eligibility](#asset-eligibility)); the stale, wrong-direction advice stays visible rather than silently trusted, and a full run (or selecting the holding) re-enters it as what it now is.
  Every unselected holding **carries its prior action as-is** — no stage re-authors a carried action — with one deterministic exception at the roll-up.
  An **over-age** unselected holding whose last full pass is older than the drafted **vintage over-age bound** (~4 weeks — [§Starting parameters](#starting-parameters-calibratable)) and whose carried action is **add-family** is **rule-demoted to *hold***, a labeled rule-based weaken stamped **`action_source: rule-demoted`**, so the card and the next run's prior-action read show it as set by rule rather than as an analytical hold ([§Portfolio action](#portfolio-action)).
  An over-age **exit-family action (*trim* / *sell all*)** and an over-age **hold** both **stand as-is**, behind the card's **stale-vintage badge**: a stale exit is directionally coherent, and the badge makes its age visible, so re-analysis is a choice the user makes rather than a forced one.
  Vintage ages — the over-age boundary here and the card's carried / stale stamp alike — count **whole ET session days** (the vintage instant's US/Eastern calendar day against today's, one date-diff shared by the engine rule and the card), so an evening-ET vintage ages from the session it belongs to and the badge can never disagree with the demotion rule it mirrors.
- **Quick check** is **engine-only** — no model call, no web research, no Schwab call: it re-prices the last run's book, re-reads each priced holding's price against the engine's bands and re-derives the capital-efficiency hurdle, raising per-card **attention flags** without reading or rewriting any model-authored content ([§The quick check](#the-quick-check-engine-only)).
  Because it makes no model call it runs even when the daemon is configured-but-down — the same run-gate relaxation as Trade Opportunities' Quick Audit ([trade-opportunities.md §Failure posture](trade-opportunities.md#failure-posture)).
- **Pull holdings** is **view-only**: it fetches the current positions, persists them as the latest holdings snapshot, and displays them — it never triggers analysis, and it **never becomes the holdings-diff baseline** (the diff always compares the run-time pull against the prior *run's* snapshot — [§Holdings change tracking](#holdings-change-tracking) — so pulling twice between runs can't eat the what-did-the-user-do delta).
  Because it makes no model call, it gates only on the Schwab connection, not on the local-model configuration — the one Portfolio control usable before local models are set up.

Only one run happens at a time across the whole app — a single global run slot serializes the report, both local jobs, the quick check, and the pull (see [scheduling.md §Concurrent Job Protection](scheduling.md#concurrent-job-protection)).
While the analysis runs it streams into the run tracker with **per-holding progress**, the same observability seam the report uses ([run-tracking.md](run-tracking.md)).

## Asset eligibility

A Schwab portfolio holds more than equities — ETFs, mutual funds, options, fixed income, and cash.
The equity-centric pipeline (FMP fundamentals, company financials) applies cleanly only to individual stocks, and in reduced form to funds.
Each position is classified by asset type before analysis:

- **Stocks** — the full pipeline and verdict, **behind a deterministic listing-resolution guard** (built 2026-08-05): Schwab's asset type alone says *equity*, not *US-listed equity* — an account can hold foreign ordinaries and other non-US listings — while the suite's data plan is US-only ([data-sources.md §FMP — current paid-plan tier audit](data-sources.md#fmp--current-paid-plan-tier-audit)).
  So at dossier assembly ([portfolio-workflow.md §Step 6a](portfolio-workflow.md#step-6a-dossier-assembly)) the position's Schwab instrument identity (symbol and description — no CUSIP is mapped off the wire today) must resolve through the per-stock FMP `profile` read (the Schwab symbol looked up **verbatim** — no symbol-notation mapping exists) to an identity (issuer name, exchange) that cross-checks against Schwab's — a loop-time refinement for the same reason the fund strategy classification is one (Step 3 has only Schwab's own instrument identity).
  Listing and unit guards run before single-company pricing.
  A **resolved, matching US listing** takes the full pipeline subject to the financial-unit guards below; the venue test is the **exchange allowlist**, never the profile's HQ country ([§Starting parameters](#starting-parameters-calibratable)).
  A depositary receipt identified by the Schwab description or FMP `isAdr`, or a profile whose quote currency is explicitly non-USD, is **not-rated — unsupported financial units**: the engine has no verified ordinary-share-to-ADS conversion or FX conversion.
  Quarterly income, cash-flow and balance-sheet responses must carry `reportedCurrency: USD` on every served row.
  Foreign, mixed or missing currencies make the whole affected surface unusable and cause **insufficient-evidence** before stock grading or targets, even if an unrelated SEC or consensus fallback exists.
  Empty or unavailable statement responses remain ordinary gaps and retain the existing USD-only SEC fallback; they are distinct from a served response with unverified denomination.
  A symbol with **no FMP resolution or a non-US primary listing** (a foreign ordinary held at Schwab, or any OTC/PNK quote under the allowlist rule) re-classifies to **not-rated — unsupported listing, with that reason**: a structural can't-grade, the guard itself deterministically re-derived from the one profile call each fresh pass, never cached ([§Starting parameters](#starting-parameters-calibratable)) — but the outcome is *typed* not-rated rather than an evidence-floor abstention, so no research or floor budget is ever re-spent rediscovering it.
  A symbol that **resolves but whose identity conflicts** (the FMP profile disagreeing with Schwab's issuer identity — an OTC ticker collision) is the evidence floor's **conflicting-identity leg made concrete** → `insufficient-evidence` with the floor exit's full semantics, routed at the guard itself before the engine stage (a data problem, possibly transient — [§Evidence floor](#evidence-floor)), so a wrong-issuer mapping can never grade the wrong company's financials.
  A guard-terminal outcome (unsupported listing, unsupported units or conflict) **skips the holding's remaining per-symbol retrieval** — no statement, SEC, holding history, sector-benchmark history, or chain pull is spent on a holding the guard already routed — while a guard the run **cannot verify** (an FMP profile gap, or nothing to compare — [§Starting parameters](#starting-parameters-calibratable)) proceeds with a recorded degraded input, never a terminal outcome, so an FMP outage can never mass-not-rate a book.
  Only a definitive empty FMP body reads "no resolution"; a gate, transport failure, or unreadable body is the unverified case above.
  Manual-import positions ride the same guard — they populate the same holdings model.
- **ETFs / funds** — a reduced verdict (no single-company financials; graded on strategy / **exposure**, valuation, and the house view).
  On the current FMP plan ([data-sources.md §FMP — current paid-plan tier audit](data-sources.md#fmp--current-paid-plan-tier-audit)) **`etf/holdings`, `etf/asset-exposure`, and the `funds/disclosure*` filings are off-plan**, so constituent-level look-through is lost.
  ETFs are sourced from the **on-plan** `etf/info` (expense ratio, AUM, NAV, asset class, mandate) + `etf/sector-weightings` / `etf/country-weightings` — an **exposure-tilt** read (sector / country, not single names).
  Single-name **concentration** and direct-vs-fund **overlap** degrade to that exposure level unless reconstructed from **SEC N-PORT** (keyless but heavy, ~60-day lag — an optional enhancement, never floor-bearing).
  A future **issuer-holdings adapter** — major ETF sponsors publish current constituent files fresher than N-PORT's lag, at the cost of per-issuer, messier parsing — is the practical way to buy back single-name look-through without a higher FMP tier; it is **planned, not built**, and like N-PORT would only enrich the fund path, never gate it.
  **Mutual funds degrade hardest**: FMP's `etf/info` and country-allocation contracts include mutual funds, but the sector / country weighting coverage required for the exposure-priced valuation is not guaranteed for a given fund; a mutual fund without that usable weighting set is not lettered at all — it takes the typed **`role_risk_only`** verdict on **quote / NAV + available profile / allocation data + the house view** (the classification below) unless SEC N-PORT supplies the missing exposure detail.
  `etf/asset-exposure` (reverse "which ETFs hold this name" lookup) is off-plan and dropped — it was only an optional per-direct-equity cross-check.
- **Options, fixed income, cash, and unsupported types** — marked **not rated**, with a short reason, and excluded from grading.
  Cash still feeds the roll-up's descriptive cash read, and a not-rated position simply carries no per-position grade or action.
  Weighing a material not-rated sleeve's **risk and exposure** against the rated book is whole-book work, retired from this job with the construction stage and deferred to the future portfolio planner ([§Portfolio roll-up](#portfolio-roll-up)).
  An option position **on a held underlying** links into that holding's dossier by the deterministic OCC symbol decode, so the equity's own verdict sees its overlay — built ([§The per-holding pipeline](#the-per-holding-pipeline) stage 1).

A not-rated position never receives a fabricated grade; the eligibility decision is explicit and shown in the UI.

**Net-short equity positions are not rated.**
The normalized holdings snapshot carries one signed net **book-level** quantity per symbol — same-symbol rows across accounts and manual supplements net at snapshot assembly ([schwab-integration.md §What is pulled](schwab-integration.md#what-is-pulled)) — and a position held net short is a direction the prescriptive layer doesn't model: the ladder's verbs and the outcome labels all read long ([§Portfolio action](#portfolio-action), [§Outcome learning](#outcome-learning-calibration)).
Rather than grade a short with long-side semantics, a net-short equity takes the **not-rated treatment with a short-position reason** — no grade, no ladder action, no outcome episode.
Weighing its signed exposure against the book is whole-book work, the future portfolio planner's ([§Portfolio roll-up](#portfolio-roll-up)).
A **long↔short reversal** is thesis-changing by construction — the diff never reads it as `unchanged` ([§Holdings change tracking](#holdings-change-tracking)) — so a long-side verdict is never valid across a reversal.
In a selective run since the 2026-08-16 badge ruling the carried long-side verdict now sitting net-short is **marked `side_reversed` and badged** rather than force-included, so the stale opposite-side advice stays visible; a full run (or selecting the holding) **re-enters it as what it now is** — a not-rated short after a long→short flip, a fresh full-pipeline candidate after a short→long flip ([§Triggering](#triggering)).

For a **fund** holding the engine runs a **reduced computation** in place of the equity pipeline: **expense drag** (the expense ratio as an annual return headwind), **exposure tilt** (sector / country from `etf/sector-weightings` / `etf/country-weightings`), and a **fund-level valuation**.
With constituent look-through off-plan, valuation is an **exposure-priced read** computed as an **exposure-weighted earnings yield**, `Σ(weight ÷ sector P/E)` over the per-sector aggregate P/E (`sector-pe-snapshot`, exchange-tagged).
The composite's per-sector read is a **defined blend of the exchange prints**: the NYSE and NASDAQ sector earnings yields averaged per sector, drafted, with the same convention applied to the snapshot and its history so the vs-own-history comparison is apples-to-apples — the level is a proxy, the time-series read is the signal.
It is inverted only for a P/E presentation — displayed as a **proxy composite**, never as the fund's own P/E — with the weight in loss-making or P/E-unavailable sectors **reported separately, never averaged in**, since P/E is nonlinear and a weighted-average P/E is not a sound aggregate (the harmonic form is how index-level multiples are actually built).
The composite is computed **over the covered weight only and renormalized by it** (`Σ(wᵢ ÷ PEᵢ) ÷ Σ(wᵢ)` across the sectors with a usable P/E), so uncovered weight neither silently reads as zero earnings nor lets a small priced slice extrapolate across the whole fund.
A usable P/E and a usable weighting are the adapter's terms (ruled 2026-08-29 off the review's Codex I7 and I9).
The exchange-identity, plausible-band, and weight-range rules are canonical at [data-sources.md §Financial Modeling Prep](data-sources.md#financial-modeling-prep).
It runs under a **minimum-coverage guard** — drafted **≥ 70% of fund weight in P/E-usable sectors** ([§Starting parameters](#starting-parameters-calibratable)) — below which the valuation is **recorded as a gap rather than lettered off a sliver**, dropping the fund below the evidence floor's two-real-sub-scores bar into `insufficient-evidence` (genuinely deficient data, not an unpriceable class — [§Evidence floor](#evidence-floor)), with the same renormalization-and-coverage convention applied to the snapshot and its history so the vs-own-history read compares like to like.
The composite is read against its own trailing history (`historical-sector-pe`): *what the fund's sector mix costs now versus what it has cost* — a **constant-current-mix read** (today's weights over the historical sector multiples; the mix is held constant because historical fund weights aren't sourced), never a constituent P/E the plan can't see ([data-sources.md §Portfolio Analysis — endpoint surface](data-sources.md#portfolio-analysis--endpoint-surface)).
Each quarterly sample of that history admits only prints dated within its own quarter — after the prior quarter end, on or before its own — so one print backs at most one sample and the ≥ 8-sample floor counts distinct in-quarter observations (ruled 2026-08-28 off the large-scale review's Codex I2).
Under the on-or-before select it replaced, one stale print could back all twelve samples.
A print whose date is missing or does not parse is inadmissible to every sample.
The adapter drops such a row at its shaper and stores every kept date canonical ([data-sources.md §Financial Modeling Prep](data-sources.md#financial-modeling-prep)).
A closed-end fund additionally carries the **price-vs-NAV** read, applied only where the vehicle makes it meaningful — an open-end ETF's create / redeem mechanism keeps its premium small and transient in normal markets, unlike a CEF's structural discount, so the read carries signal only on the closed-end form (the CEF leg is **built**; the classification note below is canonical for its consumption).
A mutual fund without weightings records valuation as a gap, per its degrade above.
All of it is read against the house view.
**Constituent concentration** (top-N weight, Herfindahl) is **off-plan by default** — `etf/holdings` is blocked — so it is computed only when **SEC N-PORT** is available and otherwise omitted (recorded as a degraded-input flag, never a fabricated number).
These feed a **reduced sub-score set** — **valuation** plus a **risk** score driven by exposure (and concentration where N-PORT supplies it), with **no company-quality score** (there is no single issuer to grade) — for an **equity** fund the composite can honestly price; a class it can't returns the typed **`role_risk_only`** verdict instead (the classification below).
On the priced fund path the thesis document, the typed layer, the action and the continuity machinery stay identical to the equity path (a `role_risk_only` fund keeps the continuity machinery but carries the **reduced engine set** and **no conviction or expected prices** — [§Intrinsic verdict](#intrinsic-verdict), [§Portfolio action](#portfolio-action)); the **evidence floor uses the fund analog** above, not the stock floor (see [§Evidence floor](#evidence-floor)).
The **fund-form target methodology is settled** (2026-07-16, the fund slice's plan): a *priced* fund's scenario targets — and therefore its dead-money read and upside / downside — are the **v2 function over the fund's exposure-priced composite**, specified once in [§Starting parameters](#starting-parameters-calibratable) (the fund-form bullet).

**Priced-fund grade contract.**
A priced equity fund supplies two real sub-scores — **valuation** and **risk** — and no company-quality score.
Its letter uses the shared composite's existing missing-sub-score rule ([§Starting parameters](#starting-parameters-calibratable)): the absent quality axis is **neutral-imputed to 50**, the composite keeps the full weight sum, and the card carries the visible low-confidence marker beside the letter.
That neutral placeholder is not presented or persisted as a fund-quality assessment.
The fund evidence floor still requires both real fund sub-scores, so a missing valuation cannot leave the neutral placeholder plus risk to manufacture a grade.
This closes the priced branch without introducing fund-specific weights; the fund-form target methodology is settled in [§Starting parameters](#starting-parameters-calibratable).

**Funds are classified by strategy before the reduced computation runs** — a **loop-time routing decision**, made at dossier / engine time (workflow Steps 6a–6b) once `etf/info` is in hand: Step 3's asset-type eligibility needs only Schwab's own instrument identity, and the strategy class can't be read before its endpoint is retrieved.
The asset class routes the computation because one generic fund valuation cannot grade every vehicle.
Sector weightings may supply the last-resort equity inference only when `etf/info` carries no asset-class value at all; an explicit but unsupported allocation / multi-asset class routes to `role_risk_only`, with any served sector rows retained as exposure context rather than treated as proof of a pure-equity mandate.
**Equity funds** take the full exposure-valuation path above, *when the composite can honestly represent them* — the exposure-priced valuation applies only where the fund's exposure is substantially in the composite's market (drafted: **≥ 70% US** by `etf/country-weightings`), since an exchange-tagged US sector P/E is not an honest read on an international fund merely listed in the US.
The US share the interpretation prompt renders for a priced fund is the guard's own read — every recognized US label summed and capped — never a second read of one label's spelling (ruled 2026-08-29 off the large-scale review's Codex I8).
**Bond and commodity funds** take a further-reduced path — expense drag + exposure / risk + house-view fit, with **valuation recorded as a gap** (the on-plan surface carries no duration, credit-quality, or curve data to price them honestly, and pretending sector P/E applies would fabricate a number).
**Leveraged / inverse and option-overlay vehicles** carry a deterministic **structurally-path-dependent flag** from the profile / name screen, but the reason remains typed: a leveraged / inverse vehicle is a daily-reset path, while an option-overlay vehicle reshapes the return distribution without being described as daily-reset.
Both route to **role/risk only**: sector exposure does not model an option payoff, capped upside or a downside buffer, so an option-overlay fund receives no price targets or capital-efficiency hurdle conclusion.
Trailing distributions therefore cannot be added to an unmodified equity bull scenario for these funds; the ordinary equity-fund flat-driver method remains unchanged.
The ambiguous `short` / `ultra` name screen treats fixed-income `ultra-short` and `ultra short` phrases as duration language, while explicit inverse / leverage markers still win.
And a **closed-end fund** adds the NAV read above — **built** (ruled 2026-08-21), as a **structure marker orthogonal to the strategy class**, the way the overlay flag is: a bond CEF still routes bond.
Detection is deterministic and conjunctive — the per-fund FMP `profile`'s `isFund` flag **and** a closed-end fragment in its description, both required, so a missing or ambiguous profile never guesses a CEF ([data-sources.md §Portfolio Analysis — endpoint surface](data-sources.md#portfolio-analysis--endpoint-surface)).
The read is consumed as **prompt evidence and a card line only — never a score or a rule** — and the premium is computed from the **market price** against the reported NAV, never the engine's NAV-fallback spot (which would fabricate an exact 0% premium precisely when no quote exists).
On the current surface FMP's `etf/info` serves closed-end funds an **empty body** (probe-verified 2026-08-21), so a detected CEF carries no NAV to read: the read renders as the named **price-vs-NAV gap**, and the CEF takes the typed `role_risk_only` verdict below with its card labeled **closed-end fund** rather than abstaining as `insufficient-evidence` every run — the thin surface is structural to the class, not deficient evidence.
Every class the pipeline is **structurally unable to price** — a bond or commodity fund, an explicit unsupported allocation / multi-asset class, an equity fund below the US-exposure guard (the label states the measurement, never an "ex-US" nationality claim — ruled 2026-08-13 off attempt 2's 67%-US near-miss), a leveraged / inverse or option-overlay vehicle, a mutual fund without weightings, a closed-end fund on the empty `etf/info` surface above — returns a typed **`role_risk_only`** intrinsic verdict: **no A–F letter, no scenario bands and no expected prices** (a letter over a single computable sub-score would be a fabricated grade, and `insufficient-evidence` would misname it — the evidence isn't deficient, the vehicle class is unpriceable to this pipeline), while the **per-holding action call still applies** — deciding from the vehicle's own attributes, with the rationale limited to the vehicle's role and risk reads ([§Portfolio action](#portfolio-action)).
The classification is deterministic, shown on the card, and a class the engine can't price honestly degrades — never a fabricated number.

## Evidence floor

Eligibility decides whether a position *can* be graded; the evidence floor decides whether it *should* be — and the engine's inputs split by criticality.
The stock floor requires a **usable current price**, at least **two real (non-imputed) sub-scores** ([§Starting parameters](#starting-parameters-calibratable)), **no resolved identity conflict**, and an **admissible target driver on some ladder rung** (the named **`no-admissible-driver`** gap reason — [§Starting parameters](#starting-parameters-calibratable)); a failure returns **`insufficient-evidence`** — an explicit abstention — rather than a low-conviction grade.
Financial statements are inputs to those sub-scores and drivers, not a separate all-or-nothing presence gate: for example, P/B can supply a real valuation sub-score while volatility plus debt/equity supplies a real risk sub-score even when no income statement resolves.
A price or NAV is **usable** only when it is finite and strictly positive, and the floor tests usability, never mere presence (ruled 2026-08-28 off the large-scale review's Codex I1).
The FMP quote adapter applies the same test at its parse — the one seam every quote consumer rides, the quick check's price refresh and the run-level commodity quote included — so a served zero or negative print lands as a named gap carrying the served value, never as a price.
The dated-EOD parse applies it too — the 180-day and the deep dated pulls alike — so a served zero or negative close drops as an unreadable row, and the outcome labels' price-bar series admits usable closes only, at load and at merge (ruled 2026-08-29 off the review round of Codex I16).
That is a floor-rule change — under the prior rule such a close was admitted and read as a −100% return into volatility, momentum, and drawdown — so it moved the stamp to `evidence-floor-v4` (ruled 2026-08-29 off Codex round 1 of I16).
On the fund analog an unusable market quote falls to a usable NAV rather than masking it.
The floor's rule is versioned — `engine::EVIDENCE_FLOOR_VERSION`, `evidence-floor-v5` for the financial-unit guards and option-overlay role/risk routing, after `evidence-floor-v4` for dated-EOD usability, the `evidence-floor-v3` fund-history floor ([§Asset eligibility](#asset-eligibility)), the `evidence-floor-v2` usability rule and the `evidence-floor-v1` presence baseline — and stamped on the checkpoint header and on every holding's audit record.
A resume refuses a trail stamped under another floor rule, since its completed holdings were floored under a different contract ([§Failure posture](#failure-posture)).
A target the engine cannot finish as a finite number — a feed extreme overflowing a per-share driver — exits the holding the same way, as insufficient evidence, never persisting a non-finite target the store could not read back.
Every other derivation the record carries reads as a gap where its arithmetic does not finish as a finite number — an engine metric absent, an implied-expectations, narrative, or technology-event read unavailable with its reason, a roll-up weight zero, a trailing-TTM dividend proxy zero with its gap — so that finite-target exit is the only floor exit a non-finite number takes.
One further floor arm is **designed, not enforced as-built**: **stale prices** (staleness read from the suite's typed freshness basis — [trade-opportunities.md §Starting parameters](trade-opportunities.md#starting-parameters-calibratable): a price is current only through the latest completed session — the FMP quote carries no as-of date to test, so the arm waits on a dated cross-check).
Statement age is likewise **not an independent floor as-built**: the engine uses the latest resolvable TTM or SEC annual basis, and an old period alone does not abstain if the concrete sub-score and driver requirements above still pass.
That is an accepted pre-confirmation-run boundary, not a claim that old statements are current; adding an age gate waits on a persisted typed statement vintage and a calibrated cadence threshold so a guessed cutoff cannot turn annual reporters or feed lag into false abstentions (ruled 2026-08-30 from Review 2 Q3).
The **conflicting-identity arm is enforced as-built**: its producer is the listing-resolution guard ([§Asset eligibility](#asset-eligibility)), whose conflict outcome abstains with the floor exit's full semantics — prior documents and prior vintage retained — routed at the guard itself before the engine stage runs.
Web-source tiers and extraction quality are **never floor inputs** — they move conviction and degraded-input flags only, with the explicit `deny` list the sole categorical web exclusion ([web-research.md §Source quality and evidence weighting](web-research.md#source-quality-and-evidence-weighting)).
A **fund** holding has no company statements, so it floors on the **fund analog**: a **usable** current **quote / NAV**, `etf/info`, the expense ratio, and — on the **exposure-priced (equity-fund) branch** — enough **sector / country weighting** coverage to read exposure — with the exposure-priced valuation under its own drafted **minimum P/E-coverage guard** (≥ 70% of fund weight in P/E-usable sectors — [§Starting parameters](#starting-parameters-calibratable)); missing those, or coverage below the guard, abstains the fund the same way.
The floor governs **evidence adequacy only**: a vehicle class the pipeline is *structurally* unable to price (a bond or commodity fund, an equity fund below the US-exposure guard, a leveraged / inverse or option-overlay vehicle, a weightless mutual fund, a closed-end fund on the empty `etf/info` surface) is **not** an abstention — it takes the typed **`role_risk_only`** verdict ([§Asset eligibility](#asset-eligibility)), keeping `insufficient-evidence` reserved for genuinely missing or conflicting data.
Constituent **concentration** is **enriching, not floor-bearing** (it needs the off-plan `etf/holdings`, recoverable only via SEC N-PORT), so its absence lowers conviction rather than forcing abstention.
Every **other** input (`financial-scores`, peers, the revision / surprise reads, positioning, dividends, float, beta, and all analyst data) is **enriching**: its absence **lowers conviction** and is recorded as a degraded-input flag, but never on its own forces abstention — with **one named carve-out**: the consensus is the v2 target function's driver source, so a holding offering **no admissible driver on any rung** (no positive forward-EPS consensus and no computable forward revenue per share) hits the floor under `no-admissible-driver` above, the only analyst-data absence that abstains.
"Firm" means committing when the evidence supports it, not manufacturing a verdict when it doesn't — the per-holding analog of the report's Step-3 coverage floor.

**Execution semantics.**
The floor is a **deterministic engine check, evaluated once at the end of the per-holding engine stage** ([portfolio-workflow.md §Step 6b](portfolio-workflow.md#step-6b-deterministic-financial-analysis)) — every floor-bearing input is structured and in hand by then, and research cannot repair a failed price, real-sub-score, target-driver, identity, or fund-weighting gate — so a below-floor holding **exits the loop there**, spending no research, distillation, analysis, review or interpretation call (workflow Steps 6c–6f are skipped).
The exit persists the typed **`insufficient-evidence`** disposition with **named gap reasons** (which floor-bearing inputs were missing, stale, or conflicting) and **checkpoints the holding as completed**, so a resumed run does not redo it ([§Failure posture](#failure-posture)).
What survives the exit: the holding's **prior documents are retained unrewritten** — the prior analysis and the prior thesis document — since only a full pass writes new ones, and the quick check keeps the engine's reads live between runs ([§The quick check](#the-quick-check-engine-only)).
Any **attention flag is retained** — clearing requires the holding's next successful full pass, which an abstention is not.
The **pre-profit overlay record survives too** — engine-only state, so the exit still persists its record: a newly assembled statement-leg read at the engine-stage floor exit, or an eligibility-unscorable read at the guard-routed conflicting-identity exit (the guard-terminal skip fetched no statements) ([§Starting parameters](#starting-parameters-calibratable)).
The holding receives **no per-holding action this run**: acting on an abstention would manufacture a prescription from the very evidence the floor found wanting, so the card shows the abstention and its reasons instead.
And **no new episode opens** — there are no expected prices to record — while the holding's pending checks still run ([§Outcome learning](#outcome-learning-calibration)).

## Holdings change tracking

Each run persists the **holdings snapshot it ran against** (see [§Storage and display](#storage-and-display)), so the next run diffs the current pull against the prior run's snapshot deterministically — in the application layer, before any model stage.
Both sides of the diff are the **normalized book-level rows** — one netted position per symbol across granted accounts and manual supplements ([schwab-integration.md §What is pulled](schwab-integration.md#what-is-pulled)) — so a same-symbol row in a second account can never read as a separate position or silently overwrite the first.
Every current position is classified **by quantity** as **new**, **increased**, **decreased**, or **unchanged** — by *position size*: **absolute quantity for a same-side move, the signed swing on a sign flip** — so a short reads correctly (adding to a short is an increase, buying it back a decrease) and a net long↔short reversal is never mistaken for no change even at equal magnitude (a carried long-side holding now net-short is additionally marked `side_reversed` and badged in a selective run — [§Triggering](#triggering)).
Cost basis is **corroborating context for a quantity move, not a second classification axis** — it is surfaced alongside an **increase** or **decrease** (paid-up vs averaged-down), while a cost-basis-only move at unchanged quantity is a non-trade accounting event (a return-of-capital distribution, a wash-sale adjustment), not something the user did, so it neither retags the position nor surfaces as a change.
That delta reaches the model at the **action call alone**, as the position change since the last pull beside the position's economics, so the rung reasons over what the user actually did — added to, trimmed, or left a position ([§Portfolio action](#portfolio-action)); the thesis document is written without it, like every intrinsic read.
The paid-up-versus-averaged-down read stays on the app's own surfaces.
A symbol present last run but **absent now** is an **exited** position: it earns no per-holding verdict (there is nothing left to grade), but it is surfaced in the portfolio roll-up as closed-since-last-run, so a sold-out name is acknowledged rather than silently vanishing from the run.
The diff is the app's, not the model's — the same compute-don't-guess boundary the rest of the pipeline holds.

## The quick check (engine-only)

A full run is potentially hours long, so between runs the engine's reads would age silently without something cheaper to refresh them.
The **quick check** closes that gap with Trade Opportunities' warn-don't-decide split ([trade-opportunities.md §The two jobs](trade-opportunities.md#the-two-jobs)): a cheap, engine-only pass that keeps the engine's picture live between full runs, whose outputs are deliberately **non-destructive** — the attention flag and the quiet evidence-event badge; never a rewritten verdict or any model-authored content.
It reads the engine arm alone: the thesis document, the conviction and the expected prices are **not evaluated between runs** — the falsifiers and triggers the thesis document names are tested by the self-review at the holding's next full pass, with the realized numbers in front of it ([portfolio-workflow.md §Step 6e](portfolio-workflow.md#step-6e-self-review)).
The accepted cost is that no between-run alert comes from the model's own conditions; a holding whose thesis has broken on a measure only its document names waits for the next full or selective pass.

It runs over the **last run's holdings snapshot and verdicts** — no Schwab pull, since it tests the computed picture, not the book — and retrieves **by asset type**.
It retrieves prices for every holding (the job-time FMP `quote` plus the FMP **dated-EOD** closes — the sweep never reads the shared price cache, so it spends two FMP calls per holding) and the run-level **`DGS2` and `DGS10` prints** (one FRED call each on the **shared FRED credential** — [configuration.md](configuration.md)).
The dated-EOD request may widen past 180 days only far enough to recover an older carried split-bridge anchor.
FRED presence is a precondition of the local-suite gate ([portfolio-workflow.md §Step 1](portfolio-workflow.md#step-1-job-start-and-gate)), so it is always configured where Portfolio runs at all, and a failed call **fail-softs to the freshest cached print** — a prior quick check's own successful print first, else the last run's — with its as-of date, eligible only within the drafted **rate-cache max age** ([§Starting parameters](#starting-parameters-calibratable)); none eligible reads the rate-dependent families `unknown`.
Per **stock** it retrieves the SEC EDGAR filing check (CIK-gated — [data-sources.md §SEC EDGAR](data-sources.md#sec-edgar)), the lightweight **revision preflight** (an `analyst-estimates` snapshot), an **`earnings` re-pull**, and a **statement-and-`dividends` re-pull where the EDGAR check surfaced a new filing** (the income and balance-sheet series plus the dividend record).
There is **no cash-flow re-pull**; the hurdle's payout term is the **dividend** leg alone (buybacks fold into the per-share drivers, not a separate payout leg — [§Starting parameters](#starting-parameters-calibratable)), and it refreshes between full passes on filing cadence.
The dividend leg refreshes on filing cadence because that is where it mostly moves: declarations typically ride quarterly earnings, and a mid-quarter change *often* files as an 8-K — often, not always, since the 8-K item is optional, so a payout change with no accompanying filing waits for the next full pass rather than being guaranteed-fresh here.
These are the calls that make the evidence-event list's legs deterministically detectable — the estimate and earnings series are company-scoped, so those legs are equity legs ([§Starting parameters](#starting-parameters-calibratable)).
Per **fund** it retrieves a light **fund refresh** — **unconditionally: `etf/info` plus both weighting sets for every fund** (the equity-branch gating lives on the **evaluation side**, each comparison independently gated on what it actually derives from; the two extra calls per non-equity fund per sweep are the accepted cost of data-in-hand robustness).
The weightings matter per **equity** fund on either verdict branch — the US-guard crossing flips the branch in **both** directions, since a priced fund can fall below it and a role-only international equity fund can rise above it, and a material sector shift is an evidence event wherever exposure is load-bearing.
Each holding's "since the last full pass" boundary is its effective vintage's **ET session date** — the calendar day the pass belongs to in market (US/Eastern) time, never the UTC date an evening-ET pass has already rolled into — and the boundary day itself is **inclusive** across the filing / earnings legs: date-only feeds cannot place a same-day item before or after the pass, so an item that landed after the pass ran is never permanently hidden.
The accepted cost is the mirror case: a boundary-day item the pass already saw re-raises its badge on every later sweep until the holding's next full pass on a **later** ET day advances the vintage past the boundary (a same-day re-pass re-lands on it), so the noise bound is recurring badges until that pass, not a calendar day.

It then evaluates deterministically, per holding, two **engine monitors** — **priced verdicts only**, since the `role_risk_only` branch carries no band and no hurdle read:

- the **capital-efficiency / dead-money read**, re-derived on a **stated basis**: the fresh price and `DGS2` print, with the v2 scenario multiples **re-anchored closed-form on the fresh `DGS10`** against the **stored** anchor-window percentiles and **stored** drivers from the last full pass (no re-estimation — one extra FRED print, no new heavy retrieval), the dividend leg still refreshed only when a new filing lands (the statement-and-dividends re-pull above — the cadence it actually moves on), the stored drivers held whole until the next full pass (buybacks fold into the per-share drivers — [§Starting parameters](#starting-parameters-calibratable) — so there is no separate buyback leg to refresh), so the read never mixes a fresh short-rate hurdle with a stale long-rate multiple; a holding newly crossing into the hurdle's **fails** state flags (an indeterminate read never flags).
  That flag names the **bull-case total return** against the hurdle because the bull leg is the value that decides `fails`.
  The dividend refresh reads the adapter's typed distinction: a **`None` dividend record with no recorded gap is the adapter's confirmed non-payer** — the leg re-reads zero, so a dividend elimination reaches the hurdle — while a failed pull (a recorded gap) **keeps the stored leg** rather than fabricating an elimination out of an outage;
- the **twelve-month scenario band** — the flag fires on a **change in spot's relationship to the band** (inside / below / above) since the verdict was authored, compared against the **authoring-time relation the app stamps on the engine arm at the checkpoint** ([portfolio-workflow.md §Step 6g](portfolio-workflow.md#step-6g-checkpoint)): a price that leaves the band, re-enters it, or crosses to its other side flags (the scenario read is stale in a way worth a fresh look), while a band **authored with spot already outside it does not re-flag while that relationship stands** — the model wrote its thesis document seeing it, so the standing state is an examined observation, and re-raising it every sweep would be noise, not signal.
  The tested band is the **last full pass's stored twelve-month band, deliberately frozen** — the fresh-`DGS10` re-anchor above serves the hurdle read only and never rewrites the stored bands; the three-month band is not monitored, since a price leaving a quarter's band inside the quarter is the ordinary case, and the three-year band is a declared extrapolation ([§Starting parameters](#starting-parameters-calibratable)).

A flagged holding surfaces an amber, actionable **attention flag** on its card — the Portfolio analog of Trade Opportunities' *Consider Deep Audit* warning — suggesting a selective re-analysis.
The flag (and which monitor raised it) persists with the holding until the next **successful full pass over it** (a full run, or a selective run that includes it — [storage.md §Local Analysis Suite Storage](storage.md#local-analysis-suite-storage)); that pass sees the fresh engine reads in its own prompts and clears the flag on completion.
A full pass therefore **never creates a fresh persisted attention flag from the same engine evaluation it just interpreted**: the read is already part of that pass's authored result.
Separately from the amber flag, the quick check surfaces an **unexamined evidence event** its sweeps see, with no full pass since ([§Starting parameters](#starting-parameters-calibratable) defines the list), as a **quiet, informational badge** in the *Research stale* family, never the amber action color: every holding reports quarterly, so folding this into the attention flag would blanket the book each earnings season and dilute the flag reserved for actual problems.
The quick check **never rewrites a verdict, a grade, or any model-authored content**; its only writes are the flag, the badge and its own refreshed prints.
Every stored price-denominated comparator the sweep reads — the stored-multiple rescale's spot, the hurdle re-anchor's spot, the frozen band — first converts across the **split-adjustment bridge**, so a retroactive re-basis of the price series can never fabricate a band exit or a hurdle flip ([§Starting parameters](#starting-parameters-calibratable) is canonical).

**A failed retrieval is typed, never a silent clear.**
Each holding's sweep concludes in one of three states per required signal family — **`fresh_clear`** (the family was **successfully checked** and nothing fired: a fresh observation evaluated clean, **or a successful retrieval confirming no unseen observation exists** — the routine same-session re-check, weekend, or no-new-filing case, which vouches for the carried verdict), **`flagged`**, or **`unknown`** (the family's retrieval **failed** and the cache held no newer observation, so the sweep could not vouch either way: a fail-soft to already-evaluated cached data produces no new observation, which is a non-detection, not a clear).
The `unknown` state is surfaced on selective runs: the holding is **badged exactly like a flagged one** ([§Triggering](#triggering)) — the sweep's job is to vouch for the carried verdicts, and a verdict it couldn't check is flagged rather than trusted on the sweep's silence — so the card carries a quiet **degraded-sweep note** naming the families that couldn't be checked (the *Research stale* badge family, never the amber action color — [interface.md §Connection status](interface.md#connection-status-local-suite)).
For a stock, the filing family additionally reads `unknown` when the symbol's **CIK is unresolved** ([data-sources.md §SEC EDGAR](data-sources.md#sec-edgar)), so a missing filing feed surfaces as unverifiable rather than reading as no-new-filings.
It holds the single global run slot and runs in the run tracker like any job; because it makes **no model call** it skips the daemon-connectivity check and runs configured-but-down, and because it does **no web research** it triggers no pre-run SearXNG notice ([interface.md §Connection status](interface.md#connection-status-local-suite)).
When the same engine is embedded as a selective run's carried-tail sweep, all badge dates reuse the parent run's pinned instant and ET session; the sweep never reads a second clock that could cross the 8 PM ET rollover inside one run.

## The per-holding pipeline

This section covers the per-holding pipeline's **design**; the full job's **control flow** — every step, its Type (Computed / API retrieval / Local-model call), and each local-model-call contract — is the canonical spec in [portfolio-workflow.md](portfolio-workflow.md) (the per-holding loop is its Step 6; the seven numbered stages below map to workflow sub-steps **6a–6g**).

Each holding is processed through a chain of bounded documents and typed hand-offs (see [local-models.md §Context-memory discipline](local-models.md#context-memory-discipline)):

1. **Dossier assembly (application layer — deterministic).**
   The app — not the model — assembles the holding's evidence packet, holding the pure-stage boundary; no model is touched here (see [portfolio-workflow.md §Step 6a](portfolio-workflow.md#step-6a-dossier-assembly)).
   The packet carries the position and its prior-run **position delta** ([§Holdings change tracking](#holdings-change-tracking)).
   It carries any **same-underlying option positions** from the same Schwab pull, linked deterministically by underlying symbol and carried as a **typed overlay** — `{contract, direction, quantity, strike, expiry, delta, coverage ratio}`, classified **covered-call / protective-put / collar / other** (a naked short call must never read as covered; an unrecognized multi-leg reads `other` with its net delta).
   The overlay changes what the right action is, so the thesis document and the action call both see it.
   It carries the per-symbol **fundamentals / revision / positioning / price** surface (equity holdings draw the full FMP + SEC surface, funds the reduced ETF surface — [§Asset eligibility](#asset-eligibility); every endpoint, by source and cardinality, is in [data-sources.md §Portfolio Analysis — endpoint surface](data-sources.md#portfolio-analysis--endpoint-surface) and [portfolio-workflow.md §Step 6a](portfolio-workflow.md#step-6a-dossier-assembly)), with **SEC EDGAR** the authoritative cross-check behind FMP's working feed (as-built a **fill-only merge** — SEC values fill absent FMP lines; a conflicting-value cross-check is designed, not built).
   It carries the Market Signal **house view**, loaded *deterministically* (the report's own sections + summaries, never vector-searched — [local-models.md §Context-memory discipline](local-models.md#context-memory-discipline)) and **freshness-gated** (dropped past one week — [portfolio-workflow.md §Step 5](portfolio-workflow.md#step-5-load-shared-context)).
   On a continuity run it carries the holding's **prior position** — the prior run's action and rationale, its conviction and its expected prices with their horizon dates — and the holding's own documents: the prior run's **analysis** and the **prior thesis document** ([§The holding verdict](#the-holding-verdict)), loaded by identity, never by vector search ([§Continuity and isolation](#continuity-and-isolation)).
   The overlay leg is **built**: the Step-2 pull's option rows link by the deterministic OCC symbol decode, per-leg delta comes from a targeted per-strike chain fetch ([data-sources.md §Portfolio Analysis — endpoint surface](data-sources.md#portfolio-analysis--endpoint-surface), the chains row), and the typed overlay renders into the thesis-document and action prompts and persists on the audit.
   Because the OCC decode is the sole identity source, an option row whose symbol does not decode to this holding's root **never links at all** — fail-safe absence, never a misclassified leg — and the classifier's unrecognized-leg→`other` posture stands as the defensive backstop should one ever arrive.
   Four market inputs — the **risk-free rate**, **commodity prices**, **CFTC positioning**, and the **FINRA short-interest file** — are fetched **once per run and shared across every holding** rather than re-requested per symbol, the load-relief that keeps the per-holding budget small ([portfolio-workflow.md §Step 5](portfolio-workflow.md#step-5-load-shared-context)).
2. **Deterministic financial analysis (application layer).**
   The shared Rust engine (also Trade Opportunities' — [trade-opportunities.md](trade-opportunities.md)) computes every number in three layers, the load-bearing decision being *which layer touches the grade*.
   **(a) The grade core** — for a stock, fundamentals and valuation multiples → the real **quality / valuation / risk** sub-scores; for a priced equity fund, the reduced engine → real **valuation / risk** plus the neutral-imputed absent quality axis under the [fund-grade contract](#asset-eligibility) — and the scenario **price bands at three months, twelve months and three years** (the rate-anchored v2 scenario-target function, `DGS10`-anchored, its near-horizon form and its declared three-year extrapolation — [§Starting parameters](#starting-parameters-calibratable)).
   **(b) A conviction layer** — the engine's **forensic reads** and the **momentum / market-setup read** (price trend and setup, computed alongside the grade core but held **out of the letter** — context the model weighs, never a grade input).
   Those feed the **narrative-vs-reality ratio** (revision pace vs multiple — *justified-expensive* vs *hype*; falling back to the **operating-reality-vs-price** form where analyst coverage is too thin to read revisions — [trade-opportunities.md §The two non-negotiables](trade-opportunities.md#the-two-non-negotiables)) and the **implied-expectations read** — the growth / margin trajectory the current price *already assumes*, solved by inverting the engine's scenario math at the live price and expressed as a **range under stated assumptions**, never one number (the shared primitive Trade Opportunities computes at Step 5c), the priced-in anchor the trim-a-winner judgment leans on.
   **(c) Positioning context** — insider / congressional / FINRA short interest / the Schwab options signal.
   Layers (b) and (c) are **computed but held *out* of the sub-scores**, so new signals sharpen the model's read of conviction and risk without moving the letter grade — the three-layer engine's whole point.
   As-built, layer (b)'s computed reads are the **momentum / market-setup read**, the **pre-profit overlay**'s statement legs, the **hard forensic state** (the item-classified filing kinds alone), the **narrative-vs-reality ratio** (with its thin-coverage fallback), and the **implied-expectations read**, and layer (c)'s are the **Schwab options signal**, the **FINRA short-interest read**, and — for a commodity / macro fund — the **CFTC underlying-positioning read**; the rating-drift / earnings-surprise series, the soft forensic flags, and the insider / congressional feeds are designed, landing with their data legs ([data-sources.md §Portfolio Analysis — endpoint surface](data-sources.md#portfolio-analysis--endpoint-surface)).
   For a stock meeting the deterministic eligibility rule, layer (b) also carries the **pre-profit execution / financing overlay**'s statement-derived legs: cash runway, gross-margin progression, capital intensity, and split-adjusted dilution; the issuer's operating proof against its guidance has no deterministic producer and reaches the model through the research alone ([§Starting parameters](#starting-parameters-calibratable)).
   The overlay is conviction / risk / action context only — never another grade component and never a license for the model to calculate a number.
   From the bands the engine derives the **capital-efficiency / dead-money read** — the base-case forward **total return** (the v2 function's `TR_base` directly — [§Starting parameters](#starting-parameters-calibratable)) against a DGS2-anchored, risk-tier-scaled hurdle, returning the three-state **clears / indeterminate / fails** verdict (only *fails* is dead money) — also kept out of the grade and fed to the action call's evidence ([§Portfolio action](#portfolio-action)), and its own **action rung** by the drafted rung rule, the engine arm's reading beside the model's.
   On a continuity run it also computes the **realized data** the self-review reads — the price now and its move, every stored engine value then and now, and the holding's accuracy record ([§Outcome learning](#outcome-learning-calibration)) — and the **technology-event pre-flag** (fired when the holding's sector-relative move exceeds the volatility-scaled threshold — [§Starting parameters](#starting-parameters-calibratable)) that decides the conditional research topic ([portfolio-workflow.md §Step 6b](portfolio-workflow.md#step-6b-deterministic-financial-analysis)).
   The dossier's **absolute street opinions** (consensus target *level*, buy / hold / sell rating, FMP's ratings snapshot) are deliberately **not** engine inputs — they would ride into interpretation as *evidence the model weighs against the engine's own read*, never numbers to adopt (designed — the target-consensus / ratings rows are not yet pulled, so as-built the only consensus the prompt carries is the target function's forward-estimates read; [data-sources.md §Portfolio Analysis — endpoint surface](data-sources.md#portfolio-analysis--endpoint-surface)).
   These computed values are the source of every **engine-arm** value in the verdict; the model arm is authored beside them, never altering or binding them (the boundary statement in [§The holding verdict](#the-holding-verdict); [local-models.md §Context-memory discipline](local-models.md#context-memory-discipline)).
3. **Bounded web research** — the 122B reasoner (thinking mode) over the bounded per-topic research loop ([web-research.md](web-research.md)), fail-soft, grounded by the holding's fetched values so research *fills the gaps the numbers leave* rather than substituting a story.
   Its agenda: competitive / business position, recent results and estimate revisions, catalysts and risks; **management quality and capital allocation** (guidance *delivered* vs *promised*, candor in bad quarters, buyback / dividend behavior — the held-name form of Trade Opportunities' investor-judgment lens, [trade-opportunities.md §The lenses](trade-opportunities.md#the-lenses)); the **market narrative and sentiment** as a *sourced qualitative* read (how much of the price reflects emotion about what *might* come versus present fundamentals — distinct from the quantitative options / momentum proxies); and **forward opportunity and thematic fit** (TAM, optionality, theme exposure).
   A stock on the deterministic **pre-profit execution / financing overlay** additionally receives one focused topic over the operating proof its business actually reports — production / deliveries where applicable, bookings / backlog / reservations, guidance ranges and matching actuals, unit economics, gross-margin progress, cash burn / runway, capital spending, and dilution — so an execution break or financing dependency can reach the thesis document before a trailing annual score fully reflects it; the write-up reports what it finds with each figure's date and source, and the engine computes nothing from it ([§Starting parameters](#starting-parameters-calibratable)).
   A **fund** holding's agenda swaps these company-centric topics for fund-flavored ones: mandate / strategy and manager changes, expense and structure versus its category, the exposure profile it actually supplies and what direct or lower-cost vehicles supply the same exposure (the fit against the house view is the thesis document's judgment, which sees the market analysis this loop never does), and, for a closed-end fund, the discount and distribution coverage; the conditional technology-event topic below is an **equity topic** (its pre-flag sizes a single company's exposure, not a wrapper's).
   **Conditionally**, when the engine's **event pre-flag** fired in stage 2 — a sector-relative move exceeding the volatility-scaled threshold — the agenda adds a **technology-event impact assessment** that reads the actual technology and *sizes the holding's real exposure*, which is what separates a **panic drop from a genuine impairment** (and, symmetrically, overstated-benefit euphoria on the upside); the pre-flag is the topic's only trigger, decided when the agenda is assembled, so a follow-up question cannot activate it and an event found only mid-loop may lack a dedicated assessment — a stated coverage tradeoff.
   The symbol-scoped **news leads** are no trigger of their own; they ride the gathering brief as fetch candidates — leads, never evidence ([web-research.md §The research loop and context management](web-research.md#the-research-loop-and-context-management)).
   Each topic is worked in its own gathering conversation, and each pass's **write-up** is authored by a separate synthesis conversation over the gathered pages — prose, read as text and validated by nothing — rewritten whole on a follow-up pass; after the topics a **disconfirming pass** searches for evidence against the run's write-ups and writes its own.
   On a continuity run the holding's **prior analysis** and **prior thesis document** ride every topic's brief as the holding-constant block, dated, whatever their age — the thesis document is where the falsifiers and triggers live, so research knows what to test — and no earlier write-up is ever rendered into a later prompt.
   Research effort is **uniform, not graduated**: every analyzed holding runs the full loop each run.
   Every page shown to the model enters the holding's **page roster** — address, title, publication date, retrieval time and source tier, never page text — the durable provenance on the audit record ([storage.md §Local Analysis Suite Storage](storage.md#local-analysis-suite-storage)).
4. **Consolidation.**
   The orchestrator sizes the analysis prompt — the write-ups, the fetched values and, on a continuity run, the prior analysis — against the call's budget; over it, the write-ups are **distilled** by the reasoner in non-thinking mode in one of two shapes chosen deterministically by size (the merged write-ups, or each write-up first), never the prior analysis ([web-research.md §The research loop and context management](web-research.md#the-research-loop-and-context-management)).
   Then the reasoner in thinking mode writes the holding's **analysis**: one document consolidating what this run's research established, each dated figure with its source, where sources disagree, what stays unanswered, and on a continuity run what the prior analysis said that this run confirms, revises or leaves untouched; a topic with no write-up this run keeps what the prior analysis says about it ([portfolio-workflow.md §Step 6d](portfolio-workflow.md#step-6d-consolidation)).
   The analysis is the **only research artifact the next run reads** — the holding's whole research memory — so its length band and the write-ups' bound the budget check ([§Starting parameters](#starting-parameters-calibratable)); the write-ups persist on the audit record as written, and no typed research field exists.
5. **Self-review — continuity runs only.**
   Before interpretation writes this run's thesis document, the reasoner reviews the prior run's position against what has happened since: the prior position, the prior thesis document, this run's analysis and the engine's realized data — each expected price against the close, each falsifier and trigger the prior document named against the numbers, whether the thesis survives, where the prior read was right or wrong and why, what to revise, and what should change in how this holding is analyzed ([portfolio-workflow.md §Step 6e](portfolio-workflow.md#step-6e-self-review)).
   The **review** is prose, persisted on the audit record, read by the thesis-document message and by nothing app-side; it is where the holding's accuracy record reaches the model ([§Outcome learning](#outcome-learning-calibration)).
   A debut has no prior position and skips the stage; a `role_risk_only` holding reviews its prior action and the prior document's conditions against the fund's realized data.
6. **Interpretation and action.**
   The 122B in thinking mode interprets the engine's computed analysis, the market analysis, this run's analysis and, on a continuity run, the review and the prior thesis document into the **thesis document** — the intrinsic verdict's model arm, with its conviction and expected share prices argued in the text — then transcribes the stated values into the **typed appendix** in a second, non-thinking message ([§The holding verdict](#the-holding-verdict); [portfolio-workflow.md §Step 6f](portfolio-workflow.md#step-6f-interpretation-and-action)); for a `role_risk_only` holding the same conversation authors the union's other branch — the role / risk read as a thesis document with no prices and no appendix ([§Intrinsic verdict](#intrinsic-verdict)).
   The engine's values ride the prompt as evidence, never as bounds, and the investor profile is absent by input isolation.
   A separate **action call** then decides the holding's rung from the finished verdict, the position, the engine's evidence and the profile ([§Portfolio action](#portfolio-action)).
7. **Checkpoint.**
   The app persists the verdict — the engine arm app-stamped, the model arm exactly as authored and type-checked only — the action with its annotations, and the audit record, then checkpoints the holding so a resumed run skips it ([portfolio-workflow.md §Step 6g](portfolio-workflow.md#step-6g-checkpoint); [§Failure posture](#failure-posture)).
   No channel carries a model value into the engine, and no validator reads the documents: the two-arm contract's whole enforcement is the type check on the appendix and the rung ([§The holding verdict](#the-holding-verdict)).

## The holding verdict

Each holding's output is a record that deliberately keeps two things apart — the **intrinsic verdict** (what the holding is worth on its own merits, investor-independent) and the **portfolio action** (what to do about it, decided from that verdict plus the investor profile — still one holding at a time).
The action is deliberately **tunnel-vision**: the job never weighs one holding against another, and the whole-book reconciliation — "trim the A-grade because it is oversized, crowded, or duplicative" — belongs to the future **portfolio-planner** job, which will read this job's report beside the market report and Trade Opportunities.
Separating verdict from action — and auditing each on its own — is what keeps an "A-grade" from silently becoming "add aggressively."

Inside a **`priced`** intrinsic verdict, two reads are likewise kept **orthogonal** — the **grade** (a *backward / current* quality anchor, computed deterministically from the trailing financials and valuation) and the **thesis document's forward read** (the scenarios, the expected prices and the conviction, argued from the research).
They answer different questions: *what the business is* versus *what the market is likely to pay for it next*.
A low grade with a strong forward read is a **legitimate, first-class state, not a contradiction** — the market routinely prices the future, so a C- or D-graded business mid-inflection can carry a constructive thesis; the card shows the two side by side and never collapses the forward read into the letter (or the letter into the forward read).

**The two-arm contract.**
The priced verdict carries the judgment **twice**, as two arms with distinct provenance:

- The **engine arm** is the deterministic baseline — a disclosed calculator over primary-source data: the sub-scores and composite letter; the bear / base / bull **bands at three months, twelve months and three years**; the **risk tier**; the capital-efficiency **hurdle read**; the **hard-forensic state** from the item-classified filings; and the engine's own **action rung** by the drafted rung rule ([§Starting parameters](#starting-parameters-calibratable)).
  Every value is app-stamped directly, never echoed through the model, and the engine authors no conviction, no outlook and no expected price of its own — its base value at each horizon is the point its band is scored by ([§Outcome learning](#outcome-learning-calibration)).
- The **model arm** is the model's own read, authored with the engine's values in the prompt as **evidence, never bounds**: the **thesis document** — the thesis; the key drivers; the bear, base and bull scenarios, each with the conditions that produce it and the model's probability; the falsifiers and triggers in words, each stating a concrete measure, level and period, a trigger stating the direction of the position change; the expected share price at each horizon and the conviction, argued in the text; and a summary paragraph — plus the **typed appendix** transcribed from it (`conviction` as `high` / `medium` / `low`, `expected_price_3m`, `expected_price_12m`, `expected_price_3y`, each field `null` where the document states no value), and the action call's rung on the full ladder ([portfolio-workflow.md §Step 6f](portfolio-workflow.md#step-6f-interpretation-and-action)).
  The thesis document is where the holding's standing view lives — thesis, drivers, scenarios, falsifiers, triggers — as the model's own prose, tested by the self-review at the next full pass rather than by any app-side evaluation.
  The document is read as text and validated by nothing, and each run's document supersedes the prior run's; the run-by-run record of how the thesis moved is the chain of reviews, each stating what changed since the prior analysis and whether the prior read held up.
  The appendix carries the model arm's only **declared domain**, app-enforced at decode: each present expected price **finite and strictly positive** (the accuracy check divides by it), a present conviction one of its three values, and `null` accepted on every field as the document's silence.
  The rule is general, not a list: a typed model-arm field is gated to its declared domain at decode, so a slice that adds one extends the gate with it.
  An off-domain object is rejected whole — never clamped or persisted — and the appendix message re-issues once under the adapter seam's bounded retry before the hard model-call posture applies ([local-models.md §The local-model adapter seam](local-models.md#the-local-model-adapter-seam)).
  Nothing else about the model arm is checked: not the document against the appendix, not the prices against the bands, not the scenarios against the engine.
  A null is acted on by presence, never read as content: a null price opens no model leg at that horizon ([§Outcome learning](#outcome-learning-calibration)), a null conviction renders as none, and an appendix with every field null opens no episode.

Three rules keep the experiment honest.
**Model-arm values never alter or bind the engine baseline** — the quick check, the hurdle test, the band-relation stamp and the accuracy check read engine values only, and **no channel carries a model value into the engine**, so the baseline is an incorruptible control arm by construction.
Deterministic machinery downstream of the model's **choices** is intentional, not an exception to that line: the episode store records the model's expected prices and scores them, and the action's hard-forensic annotation reads the model's rung.
**Both arms are scored identically** by the accuracy pass ([§Outcome learning](#outcome-learning-calibration)) — the model's expected price and the engine's base value at the same horizon against the same close, the same per-check score — so "was the model better than the baseline" is arithmetic over the same events, never opinion.
And the **prompts carry the retrospective**: the self-review reads the prior position, the prior thesis document and the engine's realized data with the holding's accuracy record, and the thesis-document message reads the review — self-assessment against the baseline is the model arm's point — with the model's own reflection persisting as prose, never as the scorekeeper.

### Intrinsic verdict

Decided in the per-holding loop with **no whole-book context** — it is a property of the holding alone, **and of no investor**: every intrinsic field — the disposition, the engine's grade, bands, tier, hurdle read and forensic state, and the model's thesis document, conviction and expected prices — is **profile-independent**, so the same security and evidence produce the same intrinsic record for any investor (what keeps the accuracy record and cross-run comparison honest).
The investor profile reaches **no interpretation call** — the thesis-document message does not render it — so no intrinsic judgment is taken with an investor in view, and the profile shapes the prescription at the per-holding action call only ([§Portfolio action](#portfolio-action)).
The thesis-document message also names no app concept — no arm, baseline, stage or seam — and the two-arm contract above is the app's description of the record, never text the model reads ([local-models.md §Prompt posture](local-models.md#prompt-posture)).
What a holding's analysis resolves to is first an **outer three-arm disposition** — kept distinct so the UI and the roll-up can tell a holding that *was* analyzed from one that *can't* be (wrong asset class) and one that *shouldn't* be (too little evidence): **`not-rated`** (an ineligible class — [§Asset eligibility](#asset-eligibility)), **`insufficient-evidence`** (eligible but below the evidence floor — the explicit abstention of [§Evidence floor](#evidence-floor), never a low-conviction guess and never a conviction *value*), or an **analyzed verdict**.
The analyzed verdict is then a **discriminated union of two branches**, and every downstream schema branches on the type — the action call's packet and the episode store.
The default **`priced`** branch is the two-arm record above: the engine arm, and the thesis document with its appendix.
A holding whose vehicle class is structurally unpriceable ([§Asset eligibility](#asset-eligibility)) returns the **`role_risk_only`** branch instead: the engine's **class** line, the **exposure tilt**, the observable **risk** read, expense drag, the **structural flag and evidence gaps**, and a thesis document carrying the **role** read — the vehicle's mandate and the exposure it exists to supply, read **in isolation** like every intrinsic field (what it does for *this* book is the future portfolio planner's whole-book judgment) — with the risks, the triggers for trimming or selling and the summary paragraph.
It carries **no letter, no bands, no risk tier, no implied-expectations read, no hurdle read, no conviction and no expected prices**: none of the return-derived machinery has an input, and no appendix follows the document.
Its confidence surface is the **evidence gaps and degraded-input flags**, never a fabricated conviction.
Its action comes from the same per-holding action call as the priced branch, decided from the branch's own attributes — the engine set for this branch stays the reduced {sell all, trim, hold}, rendered as evidence with the choice structurally open and departures annotated ([§Portfolio action](#portfolio-action)).
The isolation of the role read is enforced by the packet's inputs — no profile and no book reach it — rather than stated to the model.

### Portfolio action

Decided by the dedicated **per-holding action call** after the intrinsic verdict is finished — one holding at a time, from that holding's own verdict and position plus the investor profile, with **no whole-book input** (the tunnel-vision contract; the whole-book reconciliation belongs to the future portfolio-planner job):

- **Action**, on a fixed ladder: **sell all → trim → hold → add → add aggressively** — **rung only**, with a one-line rationale persisted on the verdict.
  The model's rationale states the investment reason; the app appends a separate tax-caveat sentence where applicable.
  An empty rationale fails the holding — isolated like any 6c–6f failure, the run continuing ([§Failure posture](#failure-posture)); the one-sentence shape is a prompt preference, not validated.
  The ladder reaches the model through the return shape's enum, the message closing on a placeholder-only return shape ([portfolio-workflow.md §Step 6f](portfolio-workflow.md#step-6f-interpretation-and-action)).
  No target weight, share count, or dollar figure is authored — sizing is whole-book work, deferred to the planner — and no orders are ever placed.
- **The decision's evidence set.**
  The rung is decided from an explicit input set rather than a model's gestalt: the **position** — shares held, cost basis, market value, unrealized gain or loss, and the position change since the last pull — the one model-facing packet that sees the position's economics; the **verdict** — the conviction, the three expected prices and the thesis document verbatim; the engine's **computed reads** — its own action rung shown as a computed read, never a recommendation, its grade, its bands beside the model's prices, the capital-efficiency read as the tested total returns against the hurdle rate, the hard-forensic state from the filings classification, the overlay's financing legs, the option overlay as structure and ratios, and the commodity prints where they apply; on a continuity run the **prior action** and its rationale; the **supported actions** as one data line — the engine's own per-holding set, stated as complete, with no permission sentence and the engine's pick withheld; and the **investor profile** less its tax row.
  The accuracy record does not ride this call: it reaches the model in the self-review, whose conclusions the thesis document carries ([§Outcome learning](#outcome-learning-calibration)).
  The engine computes its **own per-holding feasible set** — the add family enters only when the new-money admission test passes, the hurdle isn't `fails`, the grade isn't F, the hard-forensic state is clear and no overlay rule bars it; *add aggressively* additionally needs an A/B grade; severe deterioration restricts the whole set to the exit family ([§Starting parameters](#starting-parameters-calibratable)) — and that read reaches the model as **evidence, never a bar**: the full ladder is open, and a chosen rung outside the engine set persists exactly as authored with the departure **app-stamped on the holding's audit** (`action_annotations`).
  A tripped **hard-forensic state** is one such annotation: it bars the add family from the engine's set and sets the engine's own rung to the exit family — trim, or sell all with dead money or an F — and the model's chosen rung persists as authored with the trip recorded beside it — annotate, never override.
  The set carries **no book-level term** — concentration headroom and buying power are whole-book context, the planner's domain.
  A model-chosen prior action renders as chosen in the prior analysis and anchors the task's firmness clause; a rule-demoted one renders as set by rule after the prior analysis and anchors nothing ([§Triggering](#triggering)).
  **Tunnel vision is enforced by input isolation**: no cash position, sector weights, concentration or other holdings exist in the packet.
  A **`role_risk_only`** holding ([§Intrinsic verdict](#intrinsic-verdict)) decides from its own attributes — class label, role read, exposure tilt, expense drag, observable risk, structural flag, evidence gaps and its thesis document — and its **engine set** is **{sell all, trim, hold}**: the add family requires return evidence this branch has none of by construction, so an add-side rung must be earned by the vehicle's own merits in the rationale, persisting with the recorded annotation (the full ladder is open to this branch).
- **The profile's one entry point.**
  The investor profile's objective, risk tolerance and horizon ([configuration.md §Investor Profile](configuration.md#investor-profile)) frame the decision — an aggressive risk tolerance can justify the aggressive rung where the evidence supports it — and never change the verdict's facts, which are authored profile-blind upstream.
  The app uses tax posture only for the caveat after the action is decided.

  **Capital efficiency and the sunk-cost guard.**
  A holding flagged **dead money** is where the decision deliberately overrides the disposition reflex.
  The instinct to hold a deep loser "until it comes back" — or because selling "wouldn't free much cash" — treats the unrealized loss as a reason to stay; the spine treats it as the opposite.
  When the hurdle read is **fails** — even the bull case misses over the holding's horizon — **realizing the position (some or all) is leaned toward, not away from**, once forward prospects are independently judged poor.
  The packet's capital-efficiency section is the three tested twelve-month total returns and the hurdle rate as numbers, with no state word; the sunk-cost lean is one clause of the task on every priced packet, asking for the returns weighed by value rather than by their relation to another figure.
  An unscorable read says that no assessment exists this run.
  Redeployment optionality is high-level context; the job names no replacement position (that remains Trade Opportunities' job, kept isolated — [trade-opportunities.md](trade-opportunities.md)).
  Under a tax-aware profile, possible tax consequences appear only as the app's fixed caveat sentence appended to the rationale after the rung is fixed — on a trim or sell-all on a position with an unrealized gain or loss — with no effect on the chosen rung, and the model's sentence is never edited.
  Account type, tax lots, holding periods, and rates are unmodeled; under a tax-exempt profile, no tax consideration is applied.
  Two disciplines keep this from becoming a license to dump every red position: the unrealized loss **never moves the grade or the thesis document** — the engine's reads are cost-basis-agnostic, and the thesis-document message carries no position economics at all ([§Intrinsic verdict](#intrinsic-verdict)) — and the tilt applies **only once the forward prospects are independently judged poor**.
  The action call sees the loss, as a fact of the position; the sunk-cost clause rests the lean on the hurdle's `fails` state and the forward read, never on the P/L figure.
  A loser with an intact, improving thesis is still a hold (or an add); the tilt toward realize-and-redeploy is reserved for a position the forward read has already written off.

The fixed action ladder and grade vocabulary are load-bearing: like the report's fixed regime labels ([storage.md](storage.md)), they keep verdicts comparable across runs and prevent the model from retreating into hedged, non-comparable language.
The grade is **intrinsic** to the holding; the **action** additionally reflects the investor profile (horizon, risk tolerance, objective, tax sensitivity) through the action call — and nothing else.

## Portfolio roll-up

After the per-holding pass, the app builds a **deterministic run-level roll-up** (application layer, no model): the verdict counts by disposition, the largest single-position weight and the cash weight (descriptive reads for the page, consumed by no action logic), and **positions closed since the last run** (the exited names from the holdings diff — graded nowhere, but acknowledged rather than silently dropped).

The roll-up also carries the **run-level data-health read**, rolled up from the per-holding audits' typed target derivations and persisted research gaps plus the run's adapter outcomes: targets rate-anchored vs raw-percentile vs current-multiple carry, dispersion-floor engagements, deep-history failures, a run-wide DGS10 history gap, research-degraded holdings and total research gaps, and the **local-context fit**.
The data-health record retains the complete ordered `prompt_usage` list, including ordinary, count-less, failed, retried, and length-stopped physical attempts, with measurement semantics single-homed in [local-models.md §The local-model adapter seam](local-models.md#the-local-model-adapter-seam).
The context-fit leg reads the raw API `prompt_eval_count` against `num_ctx`, retaining the peak reported fill and naming calls at ≥ 90% as context pressure in the measured runtime phase.
For single-phase calls, a count too small for the serialized messages-plus-tools characters is **likely front-truncation**, the signature fill alone cannot see ([§Starting parameters](#starting-parameters-calibratable) the compression covenant).
On thinking-plus-format calls the runtime's second-task count cannot establish original-packet truncation or whole-call length-stop attribution; those counters stay raw observations and the length stop remains an attention trigger without attributing its cause.
Per-holding fail-soft is honest but silent at run level — the first live run left 43 of 44 anchor windows empty behind a clean-looking run — so the aggregate persists with the roll-up and renders as a one-line readout on the roll-up card.
It carries an **attention** state on infrastructure degradation (a deep-history failure, any multiple-carry target, a run-wide rate-history gap, any context-pressured call, any length-stopped local generation — the output-budget diagnostic from the pre-run slice); a raw-percentile fallback from genuinely thin issuer history and additive research degradation are counted but never flagged.

**What this section no longer contains — the retired construction stage.**
Through `portfolio-v8` a whole-book construction stage followed the loop: deterministic book aggregates (concentration, overlap clusters, sector exposure, the sizing spine), a 122B synthesis reconciling each holding's standalone lean into a final action and target-weight range, a joint-feasibility solve, a divergence-cause vocabulary, and a portfolio-level view.
The stage was **removed whole by the tunnel-vision ruling** (user decision 2026-08-14): this job must not compare holdings — each action is decided from the holding alone plus the profile ([§Portfolio action](#portfolio-action)) — and the whole-book questions the stage answered (concentration, overlap, funding, sizing, the deployment stance) move to the future **portfolio-planner** job, which will read this job's report beside the market report and Trade Opportunities.
Retained history is honored, not rewritten: any **readable** persisted run lists and opens read-only, while a corrupt row lists as **unreadable**, cannot open, and is excluded from every baseline read ([§Failure posture](#failure-posture)).

One stronger alternative recorded here stays **deferred, not adopted**: a deterministic allocation optimizer — the app solving every target weight, the model only explaining the result.
The estimation-error evidence (constrained and even naive allocations beating optimized ones out of sample) cut against optimizing at this data quality, and the question now belongs to the portfolio planner's design.

## Starting parameters (calibratable)

The deterministic engine runs on concrete constants, gathered as a single **calibration surface** at the top of `src-tauri/src/portfolio/engine.rs` (with the durable plan-time parameters in `portfolio/mod.rs`).
Every value below is an **MVP starting point chosen to be shadow-tuned against live runs, not frozen** — the same stance the report's thresholds take.
They are recorded here so the spec matches the engine, not to pin them.

**As-built.**

- **Composite grade.**
  The letter reads the **momentum-free** sub-score weights **quality 0.40 / valuation 0.30 / risk 0.30** (fixed; the roll-up divides by their sum); letter cutoffs over the 0–100 composite — **A ≥ 85, B ≥ 70, C ≥ 55, D ≥ 40**, else F.
  **Momentum lives outside the letter** (the settled re-weight, landed with the fund slice's engine update) — computed alongside and re-homed to the **market-setup read** in the conviction / positioning layer, because a price move is the one grade input that isn't a business fundamental and the letter is described to the user as *what the business is*; keeping it in would also force two grades (a display letter and a gating composite), which the move dissolves.
- **Sub-scores.**
  Each a clamped linear map to 0–100 (higher = better): **quality** from net and gross margin, **valuation** from inverted P/E · P/S · P/B (a negative P/E scores low, never "cheap"), **momentum** from trailing price return (computed alongside; outside the letter — see Composite grade), **risk** (higher = safer) from realized volatility and debt/equity — where a **negative debt/equity** (negative equity — levered beyond the equity base) takes the band's floor rather than riding the inverted clamp to "maximally safe", the negative-P/E rule's mirror.
  Momentum reads the short undated EOD window on the stock and fund branches alike, never the deep dated history ([data-sources.md §Financial Modeling Prep](data-sources.md#financial-modeling-prep)).
  A multi-year cumulative return against a band tuned to that window would pin the read at either end.
  The band constants were **shadow-tuned against the first calibration dataset** (its sub-score formulas first certified exact against the persisted audits): the v1 bands read normal large-cap-growth multiples as junk-expensive, compressing the whole book to C/D/F, so the recentered bands live in the engine's calibration surface and each audit stamps the **grade parameter version** (`engine::GRADE_PARAMETER_VERSION`), so a letter-bearing parameter or input-semantics change stays recognizable to the self-review's parameter-boundary line.
  Each stamp in the history names what it changed and on which branch — a band move, an input-semantics change such as the signed P/E derive (a loss-maker's negative P/E reaching the fixed "never cheap" valuation score), an input-window change such as the fund momentum re-homing onto the short window, or an admission rule such as the complete-exchange fund sector-P/E rule — bands, weights and cutoffs moving only where the row says so.
  A boundary reaches the self-review as what it changed for the holding, read cumulatively from the stamp history on the prior verdict's own branch — the fund path scores on its own bands and never reads the holding P/E, so a bump can touch one branch alone, and a symbol reclassified between runs reads the branch its prior was scored on.
  The review's parameter-boundary line names a band recalibration, the fund momentum re-homing, or the fund sector-P/E exchange-basis correction ([portfolio-workflow.md §Step 6b](portfolio-workflow.md#step-6b-deterministic-financial-analysis)).
  It does not render where the boundary changed nothing on that branch, where the prior verdict was not priced, or where the prior stamp is unrecognized — an undescribable boundary asserts no cause, so no citable line exists for a move it could not have made.
  The scenario-target stamp carries the same mechanism (the **Scenario targets** bullet below).
  A missing sub-score is **imputed to the neutral midpoint (50)** and the composite divides by the full weight sum — so a missing input pulls the composite toward neutral rather than being dropped (not a renormalization over the present sub-scores); the evidence floor guarantees at least two sub-scores are real, and a grade resting on an imputed sub-score carries a visible **low-confidence marker beside the letter** on the card — the degraded input surfaced at the grade itself, not only inside conviction.
- **Engine action rung.**
  The engine arm's own rung is a drafted rule over its reads, read in order: a tripped **hard-forensic state** → trim, or sell all when the holding is also dead money or F-graded (the trip is the engine's reading, never a bar on the model's); otherwise F-grade + dead money → sell all, either alone → trim, A/B + hurdle-clears + admission → add (*add aggressively* is deliberately never the rule's pick — the most aggressive rung stays a judgment call no formula fakes), else hold; the chosen rung is then walked toward hold, and past it toward trim where hold is barred, until it sits inside the engine's own per-holding feasible set (the **Action feasible-set bounding** bullet below), so the constrained-runway add-family bar and the severe-deterioration exit restriction bind it by construction.
  It reaches the action call as a computed read beside the model's verdict, never as a recommendation ([§Portfolio action](#portfolio-action)); the engine authors no conviction and no outlook.
- **Statement basis (one per holding).**
  The margin / growth / multiple family computes on a single statement basis per holding, because a ratio's numerator and denominator must share a period basis and revenue denominates several: the preferred **FMP TTM basis** sums the four newest quarterly income prints (revenue and net income required on all four; gross profit sums where every quarter carries it, or derives per-quarter from cost of revenue, else stays an honest gap **even when an annual print exists** — an annual gross profit over a TTM revenue would fabricate a margin), with quarters five through eight supplying the prior-TTM revenue the growth read compares against.
  The quarterly prints' period and filing dates arrive canonical from the adapter ([data-sources.md §Financial Modeling Prep](data-sources.md#financial-modeling-prep)), so the newest-first order the window reads is the calendar's.
  Too few usable quarters falls back to the **SEC annual basis** wholesale — the latest 10-K full-year lines, with the prior-year revenue read from the **same GAAP concept** as the latest (never a different revenue tag).
  The leverage leg is FMP-first either way — the latest quarterly balance sheet's total debt and stockholders' equity, SEC equity the fallback — a balance-sheet instant, not a flow line, so it rides outside the flow-basis rule.
  The adopted basis is recorded in the audit's sources line.
  The annual basis is stamped only where the SEC fill supplied a flow line; a balance-sheet instant standing alone — FMP's own beside thin quarters, or an equity-only SEC fill — carries no flow basis (ruled off the slice's Codex rounds, 2026-08-28).
  Equity-source continuity — a debt/equity or price/book step when the equity leg moves between FMP's quarterly instant and SEC's annual one — is not the flow-basis stamp's to track and never was.
  It is the two instants' own: the SEC merge stamps which balance sheet supplied the equity (`equity_source` — FMP's quarterly, SEC's annual, or none).
  The thesis-document message's computed section states the holding's basis this run — TTM, SEC annual, or none — beside the engine's statement-derived metrics, whose labels name no basis; the line states the basis for the flow series, names debt/equity and price/book as balance-sheet instants outside it, and names which balance sheet supplied the instants' equity this run — FMP's quarterly, SEC's annual, or none.
- **Split-adjustment bridge** (this entry is canonical).
  FMP dated EOD — the suite's only deep-price rung — is retroactively split-adjusted, so after a split every stored price value sits on the old basis while fresh prints sit on the new one.
  Each full pass therefore stamps an **anchor bar** on the holding's audit (`HoldingAudit.authoring_close`, both verdict branches): the newest settled close **strictly before** the run's ET session, from the run's own fetched series.
  A later engine read re-reads the same bar date from its fresh fetch; `fresh close ÷ stored close` is exactly the cumulative re-basis factor between the two fetch times (`engine::split_bridge_factor`), snapped to exactly 1.0 inside a **10% deadband** (drafted) so a rare retroactive data revision never masquerades as a split — real splits sit at ≥ ~20%.
  Every stored price-denominated comparator converts through the factor before comparison.
  The quick check's conversions are transient — the stored-multiple rescale's spot, the hurdle re-anchor's spot and same-sweep filing dividend, the frozen twelve-month band, and every raw fiscal-period EPS row the revision preflight reads — and nothing stored is rewritten ([§The quick check](#the-quick-check-engine-only)).
  The full pass bridges the **prior position's expected prices, the prior spot, the episodes' recorded prices and every prior raw fiscal-period consensus-EPS row** where the series was re-based since the prior pass, so every comparison and every rendered typed value sits on one basis, each bridged value labeled as bridged in the prompts; the prior spot and the matched consensus-EPS rows bridge **together**, since their ratio — each prior matched-period multiple — is basis-free and must stay so.
  A document rendered verbatim — the prior analysis and the prior thesis document — is never rewritten: where a split intervened since it was written, a **split-context line** above it states the split's date and ratio and the factor that brings its prices to today's basis, so the model reconciles the prose against the bridged numbers without the app touching the text (canonical at [portfolio-workflow.md §Step 6b](portfolio-workflow.md#step-6b-deterministic-financial-analysis)).
  An anchor whose bar date is missing from the fresh window is an **unverifiable basis: the comparison is excluded, typed — never run cross-basis**.
  The sweep excludes the affected legs and reads the vouching families `unknown` (the revision comparator and the frozen band included, each note naming the cause).
  The full pass records the degraded input and **carries the prior anchor forward unchanged**: provenance is preserved, so later passes stay fail-closed while the bar is missing and convert correctly the moment it resolves — a fresh stamp would certify carried values on a basis the run could not verify, and dropping the anchor would fail open at factor 1.0 one pass later.
  An unresolvable pass also withholds its **fresh anchor-dependent comparators** — the quick-check basis and the band-relation stamp — so every value a later bridge reads shares the carried anchor's basis and nothing double-converts when the anchor resolves; the verdict's own displayed bands stay fresh (the pass's user-facing read, coherent with its own prices).
  An anchor-less row — a priced verdict whose run had no dated closes — runs as stored until a resolvable full pass stamps an anchor; a real re-basis inside such a window goes undetected, the accepted residue.
  The accuracy pass rides the same anchor mechanism: an episode records, beside its spot, the **anchor close** of its creation session — the newest settled close strictly before it, with its bar date — and a check re-reads that bar from the refreshed series, `fresh close ÷ recorded close` the factor its recorded prices convert through under the same deadband, so a split can never score as a miss and an ordinary day's move can never pose as one; an episode with no anchor (created with no dated closes), or whose anchor bar a served series no longer carries, writes the horizon unscorable with that cause rather than comparing cross-basis ([§Outcome learning](#outcome-learning-calibration)).
- **Evidence floor.**
  Fewer than **2** computable sub-scores, or no current price, abstains as `insufficient-evidence` rather than grading on too little.
- **Listing-resolution guard** (landed 2026-08-05).
  The US-listing test is an **exchange allowlist** — the FMP profile's `exchange` in **NYSE / NASDAQ / AMEX** (case-insensitive), deliberately excluding OTC/PNK: a foreign ordinary or unsponsored ADR quotes there without SEC filings, and that venue is where ticker collisions concentrate (the ruled cost, 2026-08-05: a genuine US microcap quoted only OTC is never graded).
  The issuer-name comparison is deliberately **conservative**: both names uppercased, apostrophes collapsed inside their word before the split (`McDonald's` → `MCDONALDS`), then split on remaining non-alphanumerics with corporate-form / share-class stopwords and single-character tokens dropped; a **conflict requires zero shared significant tokens** — the gross OTC-collision shape — so a near-collision never spends a spurious abstention ("American Airlines" vs "American Express" share a token and do not conflict; the bound is test-pinned).
  Nothing to compare — a ticker-only account description, an all-stopword name, a resolved profile missing its exchange or name — reads **unverified**, which proceeds with a degraded-input flag rather than routing terminal.
  The guard recomputes each fresh pass from the one per-stock profile call (no cache, no persisted field); the stopword list and allowlist are drafted constants in `portfolio/listing.rs`.
- **Scenario targets.**
  The **v2 rate-anchored scenario-target function** below is the as-built implementation, stamped `engine::SCENARIO_TARGET_PARAMETER_VERSION`; the v1 drift formula it replaced — `clamp(0.5 × revenue-growth + 0.02, −0.25, +0.35)` applied to spot — is retired.
  The three horizons carry **rolling three-month / twelve-month / three-year** names (`three_month` / `twelve_month` / `three_year`), each a window from the run date — calendar year-end is not twelve months away outside January, and the accuracy pass scores each band at its own horizon date ([§Outcome learning](#outcome-learning-calibration)); Trade Opportunities' docs read the twelve-month window as its target window.

  Conviction is categorical **`high` / `medium` / `low`** (model-authored, transcribed from the thesis document); the expected share price is a **single point at each of three months, twelve months and three years** — a stance, no band — finite and strictly positive ([§The holding verdict](#the-holding-verdict)).

**Drafted starting values (each lands with the slice that needs it; bullets marked designed are not built).**

- **Rate / return representation (suite-wide).**
  Every rate, return, spread, premium, and haircut in the suite's engine math — and every such value it persists — is a **decimal ratio**: a FRED `percent` print (`4.5` for 4.5%) normalizes to `0.045` at the adapter seam before any engine consumption ([data-sources.md §Portfolio Analysis — endpoint surface](data-sources.md#portfolio-analysis--endpoint-surface)), a threshold written `Npts` means `N ⁄ 100` (`+8pts` → `0.08`), and the ε = 1% guard reads `0.01`.
  Driver yields are ratios by construction (a per-share driver over a price), and the emerging-track hurdle `2^(12 ⁄ H) − 1` already pins returns to the same scale (`H = 12` reads `1.0` — a double), so this bullet states the one convention every formula below and Trade Opportunities' entry-gate row share, rather than leaving each consumer to convert independently ([trade-opportunities.md §Starting parameters](trade-opportunities.md#starting-parameters-calibratable)).
- **Scenario-target function (v2).**
  The priced-stock bear / base / bull targets are a **rate-anchored forward-multiple** construction — per-share driver × scenario multiple — defined here as the single canonical function both jobs compute (Trade Opportunities applies it per archetype through the driver-override table in [trade-opportunities.md §Starting parameters](trade-opportunities.md#starting-parameters-calibratable)).
  The **driver ladder** picks the per-share fundamental deterministically — consensus **forward EPS** where a positive consensus exists, else consensus **forward revenue per share** (the ladder position recorded in the methodology) — and a rung is eligible only on a **finite, positive driver**: a non-positive or absent EPS consensus skips to the revenue rung (reciprocal-yield math over a non-positive driver is meaningless, and there is deliberately **no FCF rung** — the documented surface carries no forward-FCF consensus ([data-sources.md §Portfolio Analysis — endpoint surface](data-sources.md#portfolio-analysis--endpoint-surface)), and a pre-profit name prices on the revenue rung, the same P-S lens Trade Opportunities' pre-profit overrides apply), while **no admissible rung** drops the holding to the evidence floor under the named **`no-admissible-driver`** reason ([§Evidence floor](#evidence-floor)).
  The consensus the ladder reads is the **NTM (next-twelve-months) read**: the two nearest **coming** fiscal-year rows blend time-weighted by each row's overlap with the rolling twelve-month forward window (a single forward row keeps single-row semantics; no forward row abstains exactly as before), so a mostly-reported current fiscal year — whose consensus ≈ the trailing print — contributes only its remaining months rather than masquerading as the forward year (the first live run's flat-target mechanism, closed 2026-08-01; the rows blended and the near weight are recorded).
  The raw fiscal-period EPS mids and their authoring-time NTM weights persist beside that valuation read for revision comparisons; they do not change the target driver.
  Scenario values come from the consensus — **base from the mid, bear / bull from the low / high**.
  Where the analyst spread is missing the driver is held **flat** across scenarios and recorded as flat-driver on the target meta; scenario width then comes from the multiple axis and the dispersion floor, and the drafted base ∓ trailing-revision-dispersion widening waits on the revision feed.
  The implied annual growth is clamped by the v1 sanity bound (−25% / +35%), and a published spread the clamp collapses to a single value is **recorded as clamp-flattened**, distinct from a published-flat spread, so calibration data never mistakes manufactured flatness for honest consensus.
  Since `targets-v4` the clamp carries a **trough release**, gated three ways: a corroborated consensus (≥ 2 forward rows **contributing to the selected rung's blended mid** — the per-field contribution counts, never the blend count a single estimate can ride, nor mere field presence on a weightless boundary-day row), the current trailing multiple above the bounded anchor window's own rich end (P75), and the trailing print itself depressed against the window's largest admissible print (the direct trough test) — price held while the trailing print collapsed, so the clamp would crush valid recovery consensus to trough scale (attempt 2's GM: a $14.35 consensus to a $2.67 driver, a −79% "base") — whereupon the unclamped consensus prices instead, recorded as **clamp-released** and superseding the collapse record.
  The gates deliberately exclude whole-window troughs, downward re-ratings, and price-driven multiple expansion with earnings intact, where releasing would remove the sanity bound exactly when valuation is stretched; every release input is drafted, calibratable ([verification/2026-08-13-big-run-attempt-2.md](verification/2026-08-13-big-run-attempt-2.md) §Workstream 3).
  The revenue rung converts total consensus revenue per-share on **one stated share basis: the latest reported diluted share count** (the most recent filing's; where the newest filing carries no diluted count the quote-vintage shares outstanding substitutes, a fail-soft second basis — abstaining over a routinely absent field would cost more than the vintage drift).
  That is the vintage every **forward** per-share conversion in the suite reuses, Trade Opportunities' archetype overrides included ([trade-opportunities.md §Starting parameters](trade-opportunities.md#starting-parameters-calibratable)).
  The anchor window's historical revenue-per-share prints stand on a different basis: each is denominated on a diluted count from inside its own TTM window — the anchoring quarter's, else the nearest quarter's within the window — never the latest filing's or today's.
  A later count would put the history on a different share basis than its own dated close, skewing the multiple history under buybacks or dilution.
  A window with no in-window count is therefore inadmissible like any other.
  The **scenario multiple re-anchors the driver multiple's own history on the run-level `DGS10`** — over a trailing **~3-year (12-quarter) anchor window** the engine takes the **P25 / P50 / P75 of the driver-yield spread** (driver yield − the contemporaneous `DGS10`), admitting **only anchor quarters whose trailing driver print is finite and positive** (a non-positive print is an economically invalid multiple observation — excluded, and counted against the window floor below), and maps each through today's rate, `M_s = 1 ⁄ (spread_s + DGS10_now)` — so multiples compress deterministically when the ten-year rises and expand when it falls; this is where "scenario discounting keeps `DGS10`" cashes out, the long-duration rate sensitivity living in the multiple rather than a cash-flow-by-cash-flow DCF.
  Since `targets-v4` admission also holds an **anchor-multiple sanity bound**: an observation whose raw multiple exceeds the holding's current trailing multiple by more than a drafted factor (3×) is excluded and counted as **anchor-bounded** on the target meta — a multiple that far above what the market pays today, inside a ~3-year window, is a near-zero-denominator artifact (attempt 2's RKT anchored at 420×–2,511× against a 90× current multiple) or a departed valuation regime, not reversion evidence.
  The bound is relative rather than absolute so a genuinely extreme regime the market still pays keeps its history, and a dropped observation counts against the window floor like any other inadmissible quarter — thinning to the raw fallback or the recorded multiple-carry rather than fabricating a surface.
  The anchor-window inputs are **dated, under one deterministic join**.
  Each admissible quarter anchors on its trailing driver print's **filing date** (the statement feed's; period end plus the drafted ~45-day filing grace where no filing date is carried — the freshness basis's constant, reused).
  Its driver yield reads that print against the **latest daily close on or before the anchor date** (the deep dated-EOD history already on each job's surface), and the *contemporaneous* `DGS10` is the **latest published `DGS10` observation on or before the same anchor date**.
  The full/deep path loads that history as **one date-ranged FRED request per run covering the anchor window plus alignment slack, retained as dated observations** (the acquisition rule on the DGS10 row — [data-sources.md §Portfolio Analysis — endpoint surface](data-sources.md#portfolio-analysis--endpoint-surface)), while the engine-only quick paths still fetch only the run-level print they re-anchor on ([§The quick check](#the-quick-check-engine-only)).
  A failed history request leaves every spread observation inadmissible, so the window falls below the ≥ 8-observation floor and takes the documented raw-percentile fallback — no new failure state.
  The percentile→scenario assignment is **inverse in the spread domain** — `spread_bear = P75`, `spread_base = P50`, `spread_bull = P25`: a wider spread is a cheaper multiple, so the reciprocal yields `M_bear ≤ M_base ≤ M_bull` — and each scenario then pairs its own driver with its own multiple (bear × bear … bull × bull); **scenario identity comes from this mapping, never from sorting the finished prices**.
  Two guards keep the mapping honest: a **degenerate denominator** (`spread_s + DGS10_now` below a drafted ε = 1%) falls back to that scenario's raw multiple percentile, recorded; an anchor window with **fewer than 8 admissible quarterly observations** drops the rate correction entirely (raw percentiles, recorded).
  On either raw-percentile fallback the assignment **flips back to direct** — `M_bear = P25`, `M_base = P50`, `M_bull = P75` **of the raw multiples** — because the percentile rank inverts between the spread domain and the multiple domain (the cheap multiple is the bear multiple in both).
  The three prices are **monotonicity-sorted as a defensive repair only** — a residual crossing remains possible through the fallback seams (one scenario rate-anchored, another raw), and a repaired crossing is recorded — never the mechanism that assigns scenario identity.
  A **volatility-scaled dispersion floor** then guards the finished band after every target path: bear / bull are widened — never narrowed — to at least a minimum half-spread around base (drafted: annualized realized volatility × 0.5, clamped to a 5–20% half-spread, the lower bound where volatility is uncomputable), because zero scenario dispersion — a near-realized consensus, or any path's collapsed axes — degenerates the three-state hurdle into a point test and reads `fails` with false certainty; an engagement is recorded, and the **fund form shares the floor** (its deliberately flat driver would otherwise leave a carried multiple fully flat).
  The twelve-month scenario **total return** is `TR_s = (P_s + trailing-TTM dividends per share) ⁄ spot − 1` — a payout proxy rather than a forward estimate, and exactly the dead-money bullet's decomposition (per-share driver growth + proxy dividend yield + valuation change) computed as one function rather than three estimates, the share-count discipline holding because the drivers are per-share.
  The **three-month leg** is the near-horizon form: base = spot × (1 + PR_base ⁄ 4), where `PR_base = P_base ⁄ spot − 1` is the twelve-month **price-return leg** — dividends excluded, because the band is a *price* band scored against a close ([§Outcome learning](#outcome-learning-calibration)) — with a half-band of the daily realized σ × 2 × √63, the suite's √t convention shared with the dispersion floor and the technology-event pre-flag, clamped to [3.5%, 26%], and 8.7% where volatility cannot be computed (each the one-month leg's constant scaled by √3; drafted).
  The **three-year leg** is a **declared extrapolation**: each scenario's twelve-month driver — the consensus low / mid / high on the selected rung — compounded two further years at the annual growth the two coming fiscal-year rows imply, under the same −25% / +35% clamp, times the **same rate-anchored scenario multiple** `M_s`, so the band assumes today's rate and spread regime holds; a single forward row holds growth flat and records it, and the dispersion floor's half-spread scales by √3 (drafted, calibratable).
  The leg exists so the model's three-year expected price has a baseline to be scored beside, and its method clause renders with the band so it is weighed as the extrapolation it is.
  The function is **versioned** (`engine::SCENARIO_TARGET_PARAMETER_VERSION`), and the **fund form** swaps the consensus ladder for the exposure-priced composite — the settled fund-form bullet below.
  The stamp moves whenever a stored band's basis changes — an anchor denomination, a band, a clamp, a rung's admission, a horizon — by correction as much as by calibration, so a comparator never reads two bases as one.
  A target-stamp bump describes itself the way a grade-stamp bump does: the version moves only with a row appended to the target stamp history (`engine::SCENARIO_TARGET_PARAMETER_HISTORY`) naming which of the three horizons the bump can have moved on each branch.
  The self-review's parameter-boundary line reads a prior verdict's boundary from that history — over a priced prior with a stamped target record, on the prior's own branch, naming the union of the horizons the rows after its stamp touched — so a band that moved on a version bump alone is never read as the company's doing.
  It does not render where the prior carries the current stamp, an unrecognized one, or no target record.
- **Fund-form scenario targets.**
  A priced equity fund's bear / base / bull targets are the **v2 function applied to the fund's exposure-priced composite** ([§Asset eligibility](#asset-eligibility)) in place of the consensus driver ladder — the same construction, guards, and fallbacks, with fund inputs swapped in.
  The **driver** is the fund's implied look-through earnings per share — `spot × composite earnings yield` (the covered-weight-renormalized `Σ(wᵢ ÷ PEᵢ) ÷ Σwᵢ` under its ≥ 70% coverage guard) — held **flat across scenarios**: no consensus low / mid / high exists for a fund, so scenario identity comes entirely from the multiple axis and the targets read as a **mix re-rating** — what the current exposure mix would be worth at cheap / median / rich pricing of that mix relative to rates — with the flat driver recorded in the methodology.
  The **anchor window** is the composite yield's own constant-current-mix trailing history (`historical-sector-pe` — the same series, exchange blend, and renormalization-and-coverage convention as the valuation read), sampled quarterly over the shared ~12-quarter window and joined to the dated `DGS10` history under the same latest-published-on-or-before join; the spread percentiles, the inverse mapping (`spread_bear = P75` … `spread_bull = P25`), the ε = 1% degenerate-denominator guard, the ≥ 8-observation floor, the direct-mapped raw-percentile fallbacks, and the recorded defensive monotonicity repair are the stock function's, unchanged.
  The exchange blend is all-or-gap at retrieval: the snapshot candidate and each sector history must have non-empty NYSE and NASDAQ legs before either enters the fund engine; an incomplete candidate walks to the prior weekday, an exhausted snapshot records one memoized reason on every fund, and a failed sector history records its memoized reason on every later fund that depends on that sector.
  The twelve-month scenario **total return** adds the fund's trailing-twelve-month distributions (`dividends`) as the forward-distribution estimate — the sustainable basis a fund's payout honestly supports; the **three-month leg** is the stock form's (`spot × (1 + PR_base ⁄ 4)` with the √63 half-band); and the **three-year leg carries the twelve-month scenario prices unchanged**, recorded flat-growth — the flat driver has no growth leg to compound — so a fund's three-year band is the same mix re-rating held across the horizon.
  The known **conservative bias is named**: the flat driver carries no earnings-growth leg, so `TR_base` understates a growing mix and the three-year band understates it most — the engine's accuracy score at each horizon is the read that sizes it ([§Outcome learning](#outcome-learning-calibration)).
  The flat-driver form is the **settled design, not a stopgap**: no honest fund-level consensus exists on the current surface, and a scenario-differentiated priced-fund formula returns only on realized-outcome evidence — the same evidence-first rule that governs grade normalization.
  The fund form introduces **no new floor reason**: a fund whose composite fails its coverage guard already abstains under the evidence floor's fund analog ([§Evidence floor](#evidence-floor)), and a constant-mix history below the shared ≥ 8-observation floor abstains the same way — the history serves the vs-own-history valuation read too, so a window too thin to anchor is too thin to letter (the stock form's raw-percentile fallback has no fund analog).
- **Risk-tier assignment.**
  The tier the hurdle premium and the action call's evidence consume is **assigned deterministically in the engine stage** ([portfolio-workflow.md §Step 6b](portfolio-workflow.md#step-6b-deterministic-financial-analysis)), per branch.
  A **priced stock** adopts Trade Opportunities' **High / Low / else-Medium rule** — [trade-opportunities.md §Starting parameters](trade-opportunities.md#starting-parameters-calibratable) stays the canonical constants — under a stated **missing-input rule**: a leg whose input Portfolio's surface doesn't carry (event exposure rides discovery feeds this job never touches; float / liquidity is an enriching input here — [data-sources.md §Portfolio Analysis — endpoint surface](data-sources.md#portfolio-analysis--endpoint-surface)) simply **cannot trigger**, and a holding whose tier inputs are **wholesale missing** reads **Medium with a logged tier-input gap** (the neutral-imputation stance, surfaced as a degraded-input flag, never a fabricated High or Low).
  A **priced equity fund** takes its own mapping over the fund path's actually-available inputs — **High** on annualized realized volatility > 40% or maximum drawdown > 50%; **Low** on annualized realized volatility < 25%; **else Medium** (drafted — the stock rule's volatility and drawdown legs kept; no liquidity series is on the fund surface).
  Structural vehicles route to role/risk before this tier read, so no structural-flag input or priced-card flag exists on the priced branch.
  A **`role_risk_only`** holding carries **no tier** — none of its return-linked consumers exists on that branch, whose action call reads observable risk directly ([§Portfolio action](#portfolio-action)).
- **Dead-money hurdle.**
  `hurdle = rf + risk premium`, where **rf = the run-level `DGS2`** (the suite's short-end anchor, mirroring Trade Opportunities' entry-threshold anchor — a two-year yield read against an annual window, the already-fetched short rate chosen for cross-suite consistency rather than an exact duration match; scenario *discounting* keeps `DGS10` — the v2 scenario-target function's rate-anchored multiple above) and the premium is **risk-tier-scaled** — drafted **+3pts (Low) / +5pts (Medium) / +8pts (High)** — in place of a flat 5% (a high-risk holding held to a utility's premium misprices risk with the tier already computed in the spine — the assignment rule above).
  The read the hurdle tests is the holding's **base-case annual *total* return** — the v2 function's `TR_base` directly — whose decomposition `expected total return = per-share driver growth + trailing-TTM dividend-yield proxy + valuation change` is what that function computes as one expression.
  **Share-count change appears exactly once**: the retired v1 drift used *company-level* revenue growth, so a separate net-buyback-yield term added correctly; v2's per-share drivers fold the buyback in, and the term must not also be added.
  The payout term is read **as-built from the trailing-TTM dividend sum — every dividend row in the window, specials included** (a buyback still never enters the payout leg — v2 folds it into the per-share drivers above; and FMP's dividend rows carry no special/regular flag for a clean filter to key on).
  The **forward / sustainable** payout basis — a one-off special not setting the yield — is the designed target, and until a filter lands a special inside the window inflates `TR` and can flip the hurdle / admission reads, an accepted, watched exposure.
  The hurdle verdict is **three-state, not binary**, with one exact deterministic rule over the scenario bands the engine already computes: **clears** when even the *bear-case* total return clears the hurdle; **fails** when even the *bull-case* total return misses it; **indeterminate** otherwise (a point estimate missing the hurdle inside its own scenario dispersion proves nothing).
  Only **fails** makes a holding **dead money** — a **weighed exit input** for the action decision, per the sunk-cost guard in [§Portfolio action](#portfolio-action); **indeterminate neither tilts the decision nor creates dead money** — the scenario-dispersion tolerance is *exit-side* hysteresis; the add family runs its own admission test in the feasible-set rule below.
  The bars sit deliberately **below** Trade Opportunities' entry thresholds (rf + 8/16/30 — [trade-opportunities.md §Starting parameters](trade-opportunities.md#starting-parameters-calibratable)): a holding may continue below the bar a fresh entry would need (hold-side hysteresis, so the book doesn't churn at the boundary); the *add* side — new dollars, which are an entry decision — is governed by the feasible-set rule below.
- **Action feasible-set bounding.**
  Before the model picks a rung, the engine narrows **its own action set** — prompt evidence and the annotation bound, never a schema bar — from **per-holding engine inputs only**: grade, dead-money, the new-money admission test, the hard forensic state, and any pre-profit-overlay rule (the retired concentration and cash terms were whole-book context, the planner's domain).
  It offers *add* / *add-aggressively* only when the holding passes the **new-money admission test**: the **base-case forward total return clears the tier-scaled hurdle as a point test**.
  New dollars are an entry decision, and the three-state read's dispersion tolerance is *exit-side* hysteresis — it protects held capital, never licenses new capital; an indeterminate read whose base case clears still admits, and the test deliberately stops short of Trade Opportunities' full entry asymmetry, since an add to an owned, already-diligenced name is not a cold entry, the same rationale that sets these bars below TO's.
  Dead money (the hurdle's **fails** state) drops the family a fortiori at **any** grade — *hold* stays available, the hysteresis above — as does grade = F, a tripped **hard forensic state** (restatement / auditor change — the filing-classified kinds; the **Narrative and forensic reads** bullet below), or a **constrained-runway / severe-deterioration** overlay state.
  It offers *add-aggressively* only for an A/B grade.
  Severe deterioration additionally restricts the engine's own action set to {trim, sell all}.
  **Every grade test in these rules reads the momentum-free letter** (the re-weight above), so a price crash alone — a momentum swing with the business unchanged — can never bar the contrarian add.
  A **`role_risk_only`** holding's engine set is **{sell all, trim, hold}** — the add family never enters it without return evidence ([§Portfolio action](#portfolio-action)).
  This whole rule surface is the **engine arm's** — the set renders into the action call's prompt as one data line naming the rungs the computed read supports, the engine's own rung obeys it by construction, and a model rung outside it persists with an audit annotation, never a rejection ([§The holding verdict](#the-holding-verdict)).
  (The profile's `available_cash` is consumer-less since `portfolio-v9` — cash bounds are whole-book work, the future portfolio planner's; the field survives for the read-only Settings display and the planner.)
- **Material not-rated threshold.**
  The not-rated materiality threshold (**≥ 5%** of the account) is retained as a drafted constant with **no as-built consumer**: its consumer — the whole-book aggregates' not-rated contribution — retired with the construction stage, and the read belongs to the future portfolio planner ([§Portfolio roll-up](#portfolio-roll-up)).
- **Narrative and forensic reads.**
  These are conviction-layer reads the model weighs; the engine authors no conviction, so none of them caps anything — each renders into the thesis-document message as evidence with its rule stated as a fact, and only the hard-forensic state binds the engine's own action set.
  The **narrative-vs-reality read** is **built** as a cadence-honest **pace pair against the prior run's stored comparator** (the audit basis's spot + raw fiscal-period EPS rows, all already persisted): it matches periods present on both snapshots, applies the prior snapshot's NTM weights renormalized across the matches, and reads the matched-period forward-multiple change against the same-period consensus revision over the same interval — the interval cancels in the ratio and calendar roll-forward changes neither leg.
  With no usable common fiscal period it falls back, like a thinly-covered name, to the **operating-reality-vs-price** form (reported TTM revenue growth year-over-year against the annualized price move — [trade-opportunities.md §The two non-negotiables](trade-opportunities.md#the-two-non-negotiables)), so the read neither silently vanishes nor fires on noise exactly where coverage is thinnest; as-built the fallback triggers on **absent** estimates only — the consensus read carries no as-of, so the staleness arm waits on a dated cross-check — and its price leg is the annualized price move alone, the fallback's multiple leg waiting on a persisted prior trailing print.
  A debut has no comparator and carries no read; an unreadable pace on a carried holding records its typed reason on the audit, never a fabricated neutral.
  Three drafted, calibratable constants bound it: the **~1.5×** hype ratio — multiple expansion outrunning estimate revisions by more than that — a **5%** minimum multiple-expansion floor (sub-floor expansion is noise), and a **7-day** minimum elapsed interval.
  A ratio that overflows past a finite number reads as hype — expansion outran reality beyond any finite multiple — with the ratio itself persisted absent; the prompt names that state as the ratio overflowing, distinct from a flat or declining reality leg, and renders a decimal leg whose percentage overflows as the ratio itself.
  The **hard forensic state** reads the item-classified EDGAR filing kinds alone — **restatement / auditor change** — within a drafted **365-day lookback** from the run's session (`FORENSIC_EVENT_LOOKBACK_DAYS`); an older classified filing stays visible history without tripping the state, and an unresolved CIK or failed sweep types it `unknown`, never a fabricated clear ([data-sources.md §SEC EDGAR](data-sources.md#sec-edgar)).
  A tripped state takes **Portfolio's own outcome, canonical here**: Trade Opportunities' hard outcomes are a debut's exclusion at an entry gate or a carried pick's forced archive ([trade-opportunities.md §Starting parameters](trade-opportunities.md#starting-parameters-calibratable)), and an owned holding admits neither — it cannot be excluded or removed — so the trip translates to the strongest disposition an owned name admits: the verdict **stays analyzed** (the user needs an action on exactly this holding), the **add family is barred from the engine action set** ({sell all, trim, hold}) and the engine's own rung reads the exit family — trim, or sell all with dead money or an F (the **Engine action rung** bullet above) — the model's rung stays structurally open with the trip **annotated** beside it, and the letter grade is untouched.
  A restatement or auditor change surfacing **between runs** arrives as a material filing through the evidence-event list below (a quiet badge) — the quick check never rewrites verdicts, so the outcome lands at the next full or selective pass.
  A **fraud allegation has no filing leg**: it reaches the model only through the research write-ups and the analysis, as prose it weighs, and never trips the state — a stated boundary, never a silent clear.
  The **soft forensic flags** — **Altman Z < 1.8**, **Piotroski ≤ 3**, **net income > 1.3× operating cash flow**, **receivables / inventory growth > 1.5× revenue growth** — are designed, landing with `financial-scores`, and will render as evidence the same way.
  These move the model's read of conviction and risk, **never the letter grade**.
- **Implied-expectations read.**
  The engine inverts its scenario math at the live price into the growth / margin trajectory the price *already assumes* — under the v2 function, the driver growth the spot implies at each scenario multiple `M_bear … M_bull`, a closed-form **range under stated assumptions** rather than one solved number (the margin dimension read where the ladder's driver is revenue-based; the shared primitive Trade Opportunities computes at Step 5c — [trade-opportunities-workflow.md §Step 5c](trade-opportunities-workflow.md#step-5c-deterministic-analysis-archetype-weighted-engine)) — computed per holding and fed to the thesis-document message beside the bands.
  It is the priced-in anchor for the job's most common real decision — trimming or keeping a winner; it informs the conviction and action read and is never itself a gate.
  **Built** on the stock path, sharing the one scenario-multiple derivation with pricing so the two can never disagree; the **current-multiple carry inverts to nothing** (its multiple is derived from the spot itself, so no independent read exists), and the fund form's settled flat driver prices no trajectory to invert — both read as absent, never a fabricated range.
- **Fund valuation coverage.**
  A fund letter requires **≥ 70% of fund weight in P/E-usable sectors** (drafted); below the bar the valuation sub-score records as a gap and the fund abstains under the evidence floor's fund analog ([§Evidence floor](#evidence-floor)).
  The composite's mechanics — covered-weight renormalization, the uncovered share reported beside the read, never averaged in, and the same exchange-blend / coverage convention on the snapshot and its history — are specified once in [§Asset eligibility](#asset-eligibility).
- **Quick-check attention triggers.**
  The two deterministic flag conditions — the hurdle newly reading fails, and a change in spot's relationship to the twelve-month band — their priced-only scoping, and the clear-on-full-pass semantics are specified once at [§The quick check](#the-quick-check-engine-only); listed here as a pointer, not re-drafted: they carry no constants of their own.
- **Technology-event pre-flag.**
  The input delta flags a possible third-party repricing event — an **equity-holding read** — when the holding's **sector-relative move since the prior run** exceeds **2 × its interval-scaled realized volatility** (drafted; √-of-time scaling, the suite's cadence-honest convention), read against the same sector benchmark series the outcome labels use.
  The pre-flag only adds the conditional research topic — it asserts nothing about the cause ([§The per-holding pipeline](#the-per-holding-pipeline) stage 3).
  Both window endpoints are the holding's own sessions: its latest close on or before the prior read, and its newest close.
  The benchmark must carry a close on each.
  A missing one types the read unevaluable rather than reading the two legs over mismatched windows.
- **Vintage over-age bound — the badge safeguard, not a research-age force-include.**
  A carried holding's last full pass is **over-age** past **~4 weeks** (drafted), the one constant the carried add-family demotion reads ([§Triggering](#triggering)); the vintage age counts whole ET session days, the same date-diff the card's stale-vintage stamp mirrors.
  Past it a carried holding gets no guaranteed re-analysis: the quick check's card badges are the targeted between-run freshness safeguard, and deep research for a carried holding comes from selecting it or the next full run — a selective run never force-includes.
- **Pre-profit execution / financing overlay.**
  A priced stock enters the overlay when **TTM operating income is non-positive**, or when it has **no positive forward-EPS consensus and TTM free cash flow is negative**; funds and `role_risk_only` holdings never enter it.
  The eligibility read is computed — and its result persisted — for **every priced stock**, as a three-state record: **eligible** (with the arm reasons), **not eligible**, or **not entered — inputs missing** (naming which eligibility arms were uncomputable, each a recorded gap — a missing input never infers an entry); a satisfied arm admits even while the other arm's inputs are missing, and the derived financing / execution / dilution states ride every record but are **meaningful only on an eligible read** — a non-entered record carries their neutral / unscorable defaults (the persisted shape in [storage.md §Local Analysis Suite Storage](storage.md#local-analysis-suite-storage)).
  The structured leg computes from comparable quarterly statements: **liquid resources = cash and cash equivalents + short-term investments** (an absent short-term-investments line reads zero — only absent cash is a recorded gap); **TTM cash burn = max(0, −TTM free cash flow)**; **runway months = 12 × liquid resources ÷ TTM cash burn** (`not_burning` when burn is zero, `unscorable` when a required input is absent); TTM capex intensity; split-adjusted year-over-year diluted-share change; the latest two-quarter average gross margin; and its change from the preceding two-quarter average.
  Financing state is drafted as **not_burning** when TTM cash burn is zero, **adequate** at ≥ 24 months, **watch** at 12–<24 months, **constrained** below 12 months, and **unscorable** where runway cannot be computed.
  The overlay's **execution read** — the issuer's guidance against its delivered results — has **no deterministic producer**: the research write-ups report the issuer's operating observations as dated, sourced prose, the engine computes no attainment from them, and the execution leg types **`unscorable`** and enters no conjunction ([portfolio-workflow.md §Step 6b](portfolio-workflow.md#step-6b-deterministic-financial-analysis)).
  **Economics deterioration** means the latest two-quarter average gross margin is non-positive and at least 5 percentage points below the preceding two-quarter average; **material dilution** means split-adjusted diluted shares rose at least 15% year over year (both drafted).
  **Severe deterioration** is economics deterioration plus at least one of constrained runway and material dilution — statement legs alone; financing plus dilution without the economics leg cannot manufacture it.
  The consequences bind the engine arm and annotate the model's (the two-arm contract — [§The holding verdict](#the-holding-verdict)): constrained runway drops the add family from the engine set, and severe deterioration narrows the engine's action set to the exit family **{trim, sell all}** — each matched rule persisting on the audit and rendering into the prompts as the engine's own binding, while the model's conviction and action stay unrestricted with any departure recorded beside the rule.
  These consequences never change the letter grade, and no single burn, margin, or dilution metric can force a sale.
  The overlay's parameter version (`pre_profit::PRE_PROFIT_PARAMETER_VERSION`) moves with the rule, and every eligibility result, input, derived state, matched rule, and unscorable gap persists for audit.
- **Evidence events.**
  The **evidence-event list** — referenced by the quick check's card badge (an unexamined evidence event badges the carried holding; it never force-includes) — is defined once.
  A **new earnings actual** is a fresh `earnings` surprise row since the last full pass, re-pulled per stock by the quick check, so the leg is checkable between full runs.
  A **material filing** is a new 8-K / 10-Q / 10-K on the EDGAR sweep, CIK-gated: a symbol whose CIK doesn't resolve reads the filing family `unknown`, which badges through the degraded-sweep rule rather than silently skipping the leg ([data-sources.md §SEC EDGAR](data-sources.md#sec-edgar), [§The quick check](#the-quick-check-engine-only)).
  A **large revision move** is drafted as same-fiscal-period consensus EPS moving **more than ~5%**, with the prior run's NTM weights held constant and renormalized across the periods present in both snapshots; after a fiscal boundary the surviving common row compares to itself, and with no common period the family reads `unknown` rather than inferring a revision from calendar roll-forward.
  The percentage read applies only where the matched prior consensus is **positive and at least ~$0.10/share** (the denominator floor); a negative or below-floor consensus tests an **absolute move of ~$0.10/share or more** instead — both constants drafted — so the ratio cannot explode into a noisy trigger.
  The consensus-EPS legs read from the quick check's lightweight **revision preflight** (a per-stock `analyst-estimates` snapshot matched against the raw fiscal-period rows the last full pass stored); the NTM blend remains the target ladder's valuation driver and is deliberately not the revision comparator.
  The **breadth-flip sub-leg is specified but undetectable as-built** — the preflight snapshot carries no revision-breadth read, so the sub-leg stays inert until a breadth read joins the snapshot rather than silently counting as covered.
  There is **no news leg**: a headline's materiality can't be classified without a model, and a fabricated gate would be worse than the honest boundary — the next full pass's news leads catch it whenever that pass runs (a selection or a full run).
  So every active leg of the list is deterministically detectable by the pass that promises it (the breadth-flip sub-leg above being the one recorded inert exception).
  Those legs are **equity legs** — the estimate and earnings series are company-scoped.
  A **fund** holding carries its own deterministic legs, detected from the quick check's **fund refresh**: a **material `etf/info` change** — the reported expense ratio moving, or the asset-class / mandate fields that route its strategy classification changing (a structural-flag reclassification, a vehicle newly reading leveraged / inverse, counts here) — for every fund, and, per **equity** fund on either verdict branch (the guard crossing flips the branch in **both** directions — a demotion below it or a promotion above it), an **exposure shift**: the US share crossing the ≥ 70% US-exposure guard, or a top sector weight moving **~10 points or more** (drafted).
  Each fund comparison is **independently gated on what each side actually derives from**: the mandate / asset-class fields, the strategy label, and the structural (leveraged / inverse / overlay) flag each compare only where **both** the stored basis and the fresh read actually carry that field — blank `etf/info` metadata strings normalize to absent at the adapter (so blank → value reads as data coverage arriving, never as a mandate change), and a degraded fund refresh types the family **`unknown`**, never a change.
  Fund legs badge in a selective run exactly as the equity legs do.
- **Research memory — the analysis.**
  The research loop runs full every run for every analyzed holding — there is no reuse-skips-the-loop path and no lighter-vs-heavier agenda ([§The per-holding pipeline](#the-per-holding-pipeline) stage 3).
  The holding's prior **analysis** is its whole research memory: it rides every research prompt and the analysis call dated, with **no age window**, and the analysis task states that a topic with no write-up this run keeps what the prior analysis says about it; no earlier write-up is ever rendered into a later prompt, and no typed research field persists.
  Page-level reuse is the web tool's: the holding-scoped **pages already retrieved** block and the shared document cache ([web-research.md §The research loop and context management](web-research.md#the-research-loop-and-context-management)).
- **Resume window.**
  An interrupted run offers **resume** only while its pinned holdings pull is younger than **48 hours** (drafted); past the bound the checkpoints are stale against a book that may have moved, so Run analysis starts a new run ([§Failure posture](#failure-posture)).
- **Rate-cache max age (quick paths).**
  The engine-only quick paths' cached-print fallback for a failed rate retrieval ([§Failure posture](#failure-posture)) is eligible only while the cached print is younger than **~1 week** (drafted — reusing the house-view freshness bound); older, or no cache at all, types the rate-dependent families **`unknown`** rather than computing off a stale anchor ([§The quick check](#the-quick-check-engine-only); Trade Opportunities' Quick Audit shares the rule — [trade-opportunities-workflow.md §ATO: the audit flow](trade-opportunities-workflow.md#ato-the-audit-flow)).
- **Accuracy pass (constants).**
  The full contract — the episode store, the due rule, the checks and the scores — lives in [§Outcome learning](#outcome-learning-calibration); its drafted constants are homed here.
  **Episode cadence**: an episode opens for a priced holding analyzed this run when it has none, or when its latest is **one month** or more old.
  It opens only where the appendix stated at least one price; a horizon whose model price is null is recorded null and its check scores the engine leg alone, the model's accuracy score at that horizon counting no such check.
  **Horizon proximity**: a check reads the close on the horizon date, or the last session at or before it within **5 sessions**; a served series with no close inside that window writes the horizon **unscorable**, a failed refresh leaves it **pending**.
  **Per-check score**: `100 × (1 − |expected − actual| ⁄ actual)`, floored at 0, computed for the model's expected price and for the engine's base value alike.
  **Aggregation**: a holding's accuracy score at a horizon, per arm, is the **arithmetic mean** of its per-check scores at that horizon; "no score yet" before the first check.
  **Review check lines**: the self-review's realized block shows the checks written since the prior analysis was written — this run's own checks included, since the checks precede the per-holding loop — **newest by horizon date up to 12**, one line per episode and horizon carrying both arms.
- **Length bands.**
  Each prose document carries a drafted length band the prompt states and the app does not check: the **write-up** 400–900 words; a **distillation** at most half its input and at most 1,200 words; the **analysis** 900–1,800 words; the **review** 400–900 words; the **thesis document** 900–1,800 words.
  The bands are what bound the consolidation budget check — without them the check would distill the write-ups to nothing to make room for a growing analysis ([web-research.md §The research loop and context management](web-research.md#the-research-loop-and-context-management)).
- **Grade normalization & inputs (full Portfolio).**
  When the full slice lands, the sub-score inputs inherit the shared engine's Trade-Opportunities-side machinery rather than staying raw clamped maps: **quality** lifts the value-creation reads — **gross profitability (GP / assets)**, the **ROIC-vs-cost-of-capital spread**, and **FCF conversion** — rather than resting on margins alone, and every factor normalizes against **sector-adjusted absolute bands + the name's own history** (the Step-5c basis) with **sector-appropriate metric selection** — P/B-family valuation for financials, FFO-style economics for REITs, debt/equity dropped where it is structurally meaningless (banks) — because universal margin / P-E / D-E bands misgrade banks, REITs, cyclicals, and negative-equity names; the weights and letter cutoffs recalibrate then.
- **Whole-book reads — deferred to the planner.**
  Correlation / overlap co-sizing and the dedicated **factor-exposure model** are the future portfolio planner's, deferred beside the rest of the whole-book machinery ([§Portfolio roll-up](#portfolio-roll-up)); the construction stage's drafted thresholds retired with it (above), for the planner to re-draft.
  That deferred factor model is also the **named home for portfolio stress reads** — rate / credit / commodity / dollar shock scenarios and marginal risk contribution, the tail co-movement a short-window return correlation can't see — deferred with it, not separately scheduled.

## Continuity and isolation

The job retains its most recent N runs.
A holding's continuity is the deterministic load of its own documents — the prior position, the prior analysis and the prior thesis document — by identity at dossier assembly ([portfolio-workflow.md §Step 6a](portfolio-workflow.md#step-6a-dossier-assembly)), plus its episode store, which persists outside the run window ([§Outcome learning](#outcome-learning-calibration)).
The job **writes nothing to vector memory** — no summaries, no learnings — so there is no Portfolio partition to search and nothing of the job's for the report or Trade Opportunities to read; the review carries the holding's learning as prose, read by the next thesis document ([local-models.md §Run history and continuity](local-models.md#run-history-and-continuity)).
The Market Signal Report enters as a read-only shared input, loaded deterministically from the report store, never by searching its memory ([local-models.md §Context-memory discipline](local-models.md#context-memory-discipline)).

## Outcome learning (calibration)

The job's model arm is a forecast — an expected share price at three horizons — and so is the engine's base value beside it; outcome learning is the engine-computed record of how those forecasts resolved, kept so the model reads its own track record and the baseline's before it writes again.
Trade Opportunities shares the record and its mechanics, adding only a decision class for the names its gates turned away ([trade-opportunities.md §Outcome learning](trade-opportunities.md#outcome-learning-calibration)); here the universe is the holdings list, and the record scores prices, not decisions — the user acts on the book between runs, so what happened to a position reflects both the job's call and the user's response, and no per-decision verdict is ever assigned.

**The episode store.**
An **episode** is a price record: the holding's symbol, the creation date, the spot that day and the anchor close that bridges the record across a later split (the newest settled close strictly before the creation session, with its bar date — [§Starting parameters](#starting-parameters-calibratable)), the model's expected share price at three months, twelve months and three years, and the engine's base value at the same horizons — nothing else, the engine's bear and bull edges staying on the run record.
The accuracy pass opens one, after the per-holding loop, for every priced holding analyzed this run that has none, or whose latest episode is a month or more old (the cadence in [§Starting parameters](#starting-parameters-calibratable)); a holding re-priced between those points is not recorded, so the scored forecast is the monthly snapshot.
A holding whose appendix stated no price at all opens none; a horizon whose model price is null is recorded null and its check scores the engine leg alone ([§Starting parameters](#starting-parameters-calibratable)).
A `role_risk_only` holding has no prices and no episodes, and an `insufficient-evidence` exit opens none ([§Evidence floor](#evidence-floor)).
The store is **append-only**: an episode is never updated or deleted, the checks below are written onto it once each, and it persists independently of the run retention window, because a three-year horizon outlives any count-based retention ([storage.md §Local Analysis Suite Storage](storage.md#local-analysis-suite-storage)).
Which episode is the holding's latest is **insertion order**, matching run identity across the suite; the creation date is data, never identity.

**The checks.**
An episode's horizon dates are its creation date plus three, twelve and thirty-six calendar months.
A horizon is **due** when its date is on or before the run's ET session date and nothing has been written for it — one query over the store, so nothing is ever re-scored and a horizon is scored by the first run on or after its date, however many runs later that is.
The checks run **before the per-holding loop** ([portfolio-workflow.md §Step 5](portfolio-workflow.md#step-5-load-shared-context)), so a run's self-reviews read every check that has come due by its session, and a resumed run never re-scores a written horizon.
For every due horizon the pass reads the **close on the horizon date, or the last session at or before it within the drafted proximity** ([§Starting parameters](#starting-parameters-calibratable)), from the symbol's dated-EOD series, refreshed through the shared price-bar cache for every symbol with a due horizon — an exited name and an unselected carried holding alike, since the record measures the forecast, not the book, and a user's exit never stops measurement.
The episode's prices first cross the **split-adjustment bridge** where the series was re-based since the episode was created ([§Starting parameters](#starting-parameters-calibratable)).
The pass then writes the **check** onto the episode — the horizon, the check date, the close read, and for the model's price and for the engine's base value the expected price and the **per-check score**, one hundred times one minus the absolute error over the close, floored at zero.
A horizon whose refresh **failed** stays **pending** and is due again next run.
A horizon whose refresh **succeeded but served no close inside the proximity** — a delisting, an acquisition, a ticker change, a symbol the source never covered — or whose episode's anchor bar the served series no longer carries, is written **unscorable** at once with its cause: it leaves the due query, counts in no score, and the symbol spends no further pull.
The one-off risk of a truncated response closing a horizon a later pull would have served is accepted — one unscored horizon on one episode.
The episode is the log: every check and every unscorable state is readable on it.

**The accuracy scores.**
From the checks the pass derives each holding's **accuracy scores**: at each horizon, the mean per-check score over the holding's checks at that horizon, for the model and for the engine separately, 0 to 100, with "no score yet" before the first check, and beside each score the date of the last check that moved it and whether the prior analysis read it — the checks precede the loop, so a score moved by this run's checks, or by any run's checks after the prior analysis's run, was not (the formula and the aggregation in [§Starting parameters](#starting-parameters-calibratable)).
The scores persist with the holding and render on its card beside the typed strip ([§Storage and display](#storage-and-display)).
They reach the model in the **self-review alone**, as the realized block's accuracy record ([portfolio-workflow.md §Step 6e](portfolio-workflow.md#step-6e-self-review)): the six scores each with its last-moved date and whether the prior analysis read it; the individual checks written since the prior analysis was written — this run's own checks included — newest by horizon date up to the drafted count, under a heading stating that every line landed after the prior analysis and none was read before, with the total when the cap trimmed some; and, when none landed, one fixed sentence saying so and that the scores shown are the ones the prior analysis read, its thesis document under the prior-thesis heading.
The distinction is run order, not the calendar: a review reads exactly the checks written by its own run and by earlier runs, so the app states it as a word rather than leaving a date to imply it.
A holding analyzed every run finds only this run's checks new, while a carried holding's next review finds every check since its last pass new.
A score the prior analysis read has the model's reaction standing in the prior thesis document's summary paragraph, so on a frequent run cadence a repeated score reads as unchanged, not as new evidence.
The thesis-document message and the action call carry no accuracy section: the review is where the record is weighed, and the thesis document draws on the review.

Three disciplines keep the record honest.
**The engine keeps score and never plays**: every check is engine-computed from the dated-EOD series, the model's self-assessment is prose the review persists, and nothing the model writes alters a check or a score.
**The record scores the forecast, not the book**: held and exited names score alike, and no alignment with what the user did is recorded or inferred.
And **nothing is derived beyond the scores**: no cohort reads, no calibration proposals, no per-decision verdict — the learning rides the review's own answer to what should change in how the holding is analyzed, and the engine's drafted constants move only on the user's reading of the record.

## Storage and display

Each run persists its per-holding verdicts — the engine arm app-stamped, the model arm as authored — each holding's action with its rationale, `action_source` and annotations, and the portfolio roll-up, together with the **run audit record** that makes the run traceable and reviewable: the holdings snapshot it ran against, the write-ups as written, the distillation shape and call count, the analysis, the review, the page roster (address, title, publication date, retrieval time and source tier — never page text), the research gaps, the engine's computed reads and the band methodology, the model ids and the prompt stamp, and degraded-input flags — with the field set, which fields each verdict branch records, and the as-built wired subset all specified once in [storage.md §Local Analysis Suite Storage](storage.md#local-analysis-suite-storage).
(Source addresses, timestamps and the documents make a verdict's basis inspectable; full page snapshots are never stored, so a run is traceable rather than bit-for-bit reproducible.)
The episode store persists beside the runs, outside their retention ([§Outcome learning](#outcome-learning-calibration)).
Retention keeps the last N runs (parallel to report retention — [storage.md](storage.md)); the retained runs are browsable from the shared-history sidebar, an older one opening read-only ([interface.md §Main Layout](interface.md#main-layout)).
The **Portfolio page** renders each holding's verdict.
The priced card is **text-first**: the **thesis document** as its body, with the **typed strip** beside it — the action with its rationale (no sizing, per the tunnel-vision contract), the conviction and the three expected prices with their horizon dates — a null field shown as none — and the holding's **accuracy scores** for the model and the engine at each horizon ("no score yet" where none has landed) — and one compact **engine line** beneath the strip: the grade with its low-confidence marker where the letter rests on an imputed sub-score, the risk tier, the three bands and the hurdle state, each a computed read labeled as such.
The card is anchored by the thesis document itself as its *why we hold this view*: there is no separately authored summary, so there is one source of truth and no drift between what the job carries forward and what the user reads.
A **`role_risk_only`** verdict renders its own explicit card branch instead: its thesis document with the role read, the class label, exposure tilt, observable risk, expense drag, structural flag and evidence gaps beside the action, with **no prices, no conviction and no empty priced-field placeholders** ([§Intrinsic verdict](#intrinsic-verdict)).
Every card carries the amber, actionable **attention flag** when the quick check has flagged the holding, retained until the next successful full pass over it clears it ([§The quick check](#the-quick-check-engine-only)); a per-card **selection control** (with select-all / deselect-all) driving selective re-analysis ([§Triggering](#triggering)); after a selective run an **analysis-vintage stamp on each carried card** (a current-vintage card is unstamped, reading as the run's own date), so mixed-vintage verdicts read as labeled vintages rather than a blend; and a **failed badge** over carried stale data where the holding's analysis failed this run ([§Failure posture](#failure-posture)).
All of this renders alongside the portfolio roll-up, and the page shows not-rated and insufficient-evidence positions with their reason (see [interface.md](interface.md)).

**The current-holdings view.**
The page also carries the latest standalone **Pull holdings** snapshot ([§Triggering](#triggering)) as a compact, position-level view — symbol, quantity, the per-unit price the app **derives** as market value ÷ signed net quantity (Schwab reports no price field at all — [schwab-integration.md §What is pulled](schwab-integration.md#what-is-pulled); absent where net quantity is zero, which is the only case that leaves it null, and for option contracts it is therefore the per-contract value the source's market value implies, not a per-share quote), market value, cost basis, the percentage gain on cost (the card sort bar's same per-position-totals ratio, rendered as a directional value), and a pulled-at stamp.
Every column head sorts the rows **in place** — symbol alphabetically (opens ascending); quantity, price, market value, cost basis, and percentage gain numerically (open descending), a position missing a key's value (no reported price or cost basis) sorting last under that key in either direction, the card sort bar's convention — defaulting to the account's as-pulled order, with the last-used column remembered in webview `localStorage` like the card sort.
Being a real data grid, its heads carry **`aria-sort`** through keyboard-operable head buttons — the pattern the card-stack sort bar deliberately reserves for tables.
**Before any run exists it *is* the page body** (holdings viewable with no analysis — and no local-model configuration — at all, framed as *pulled, not yet analyzed* with Run analysis as the call to action); **once runs exist it appears only when the pull is fresher than the last run**, as a stamped section *above* the verdict cards — **never replacing them** — so fresh quantities and the run's verdicts read as two labeled vintages (*holdings as of…* / *analysis from…*) rather than a blend.
Position churn between the two vintages is tagged by **symbol presence only**: a pulled symbol absent from the run's snapshot reads *new · not in last analysis*, and a verdict card whose symbol has left the pull reads *no longer held* (the card itself stays, untouched — run output is never mutated or hidden by a pull).
Quantity-move classification is deliberately **not** re-derived here — that stays the run-time engine diff's job, with its short-position and reversal handling ([§Holdings change tracking](#holdings-change-tracking)) — and the *no-longer-held* tag is provisional until the next run formalizes the exit in the roll-up's closed-positions record.

**Holdings sorting.**
Above the holding-card stack a compact **sort bar** reorders the cards **in place** — no separate table view, so every card keeps its full thesis-document / typed-strip content.
It renders only when more than one card exists — a single card has nothing to reorder.
It offers four deterministic, **position-level** keys, all engine-computed (never the model's grade or conviction — sorting by position size or P/L is orthogonal to the analysis read) from two **per-position account-currency totals** — the position's **market value** (Schwab-reported, so it already accounts for option contract multipliers, bond conventions, and cash balances) and its **cost basis** (the app-derived signed total, which does **not** apply the option contract / bond par multiplier — [schwab-integration.md §What is pulled](schwab-integration.md#what-is-pulled)) — rather than a naïve `quote × shares` that would misprice options, fixed income, and cash: **overall value** (market value), **dollar gain** (market value − cost basis, the unrealized P/L the app uses for the tax caveat after the action is decided — [§Portfolio action](#portfolio-action)), **percentage gain** (that gain over cost basis), and **total cash invested** (cost basis).
A position Schwab reports **no cost basis** for (cash, typically) has an **undefined gain and cash-invested**, so it sorts **last** under the dollar-gain, percentage-gain, and cash-invested keys (the holdings analog of a debut Trade Opportunity's null since-flagged read), while still sorting normally by overall value.
A **negative netted basis** (a net-short book, where the short side's proceeds push the basis below zero — [schwab-integration.md §What is pulled](schwab-integration.md#what-is-pulled)) keeps its **dollar gain** — signed totals hold market value − cost basis equal to the book's aggregate unrealized P/L — but has **no honest percentage gain or cash-invested**, so both render **undefined** and sort last under those two keys; an **exactly-zero** netted basis is indistinguishable on the wire from an unreported basis, so it takes the no-basis treatment above (all three keys undefined); a zero, negative, or missing denominator never produces a divide-by-zero rank.
The default is **overall value, descending** (biggest positions first), tie-broken alphabetically by ticker; the last-used key is remembered as **ephemeral frontend state** in webview `localStorage` — the same store the Light/Dark appearance preference uses (pure presentation, no backend consumer), not the SQLite config store.
**Not-rated** positions (options / fixed income / cash) carry no grade but a real market value (and cost basis where Schwab reports one — cash typically has none), so they sort by **overall value** alongside graded holdings, kept visually tagged as not-rated — while **option and fixed-income rows withhold every cost-derived figure** (cost basis, average cost, dollar and percentage gain), the derived basis leaving the contract / par multiplier unapplied, so those render undefined and sort **last** under the dollar-gain, percentage-gain, and cash-invested keys exactly as an unreported basis does, until the `averagePrice` multiplier probe settles the convention; **exited** positions (closed since last run) live only in the roll-up ([§Holdings change tracking](#holdings-change-tracking)), never in the sortable stack.
The control is **display-only** — it reorders already-computed fields and touches no engine, schema, or workflow — and follows the project's frontend-craft requirements (keyboard-operable **toggle buttons** exposing the active key via `aria-pressed` plus a screen-reader-announced current-sort state (the active button's **accessible name carries the key *and* its sort direction** — e.g. "Sort by value, descending" — since the `▾`/`▴` glyph is decorative / `aria-hidden` and can't be relied on to announce direction) — *not* `aria-sort`, which is reserved for grid/table column headers such as Trade Opportunities' List view, not this card-stack toolbar; a stable sort; and a reduced-motion-respecting reflow).
The sort bar is a small **design-system extension**: it ports the `.ana-grid` sortable-header vocabulary (the neutral `▾` / `▴` glyph) to a non-table toolbar of tracked-caps triggers, since the holdings surface is cards rather than a data grid — no off-system dropdown or pill control ([interface.md](interface.md)).

## Failure posture

The execution gate requires the local model daemon and roster ([local-models.md](local-models.md)), **a connected Schwab account** ([schwab-integration.md](schwab-integration.md)) — holdings and the options signal both come from Schwab, so a missing or lapsed connection blocks the job (manual-import holdings do not satisfy the gate) — and the shared **FMP / FRED credential presence** ([portfolio-workflow.md §Step 1](portfolio-workflow.md#step-1-job-start-and-gate)).
Because holdings are independent, the job **checkpoints per holding** — each completed holding's verdict and audit persist as they land, so a cancellation or a crash resumes the unfinished holdings rather than restarting the (potentially hours-long) run, each completed holding's row carrying its verdict, its action and its audit record — the write-ups, the analysis, the review, the thesis document and the page roster included — so a resume restores the documents whole; a selective re-analysis checkpoints identically, its work-list and tail sweep pinned with the run.
A single per-holding model failure no longer interrupts the run — it is isolated (below), so the resumable trail is the mark of a cancellation, a crash, or a run-level failure, not of one holding's failed analysis.
The checkpoint writes are themselves fail-soft — a failed header or holding write logs and the run continues unprotected, since a checkpoint must never fail a run that can succeed.
A holding whose checkpoint did not land is absent from the trail, and one whose row no longer reads is skipped at load; a resume re-analyzes both; a run whose header never landed has no trail to resume at all; the finished run's persist never depends on the trail.
The checkpoint trail is **transient machine-local operational state**: deliberately excluded from the data-portability archive (ruled 2026-08-21), discarded whole by any new run as it opens its own trail, and cleared by its own run's successful persist — a failed or cancelled run still persists **no partial run row**; its partial work lives only in the trail its resume consumes.
The discard deliberately sits after the new run's fresh holdings pull and shared-context loads: a new run failing before that point has changed nothing the prior trail depends on, so the interrupted work stays resumable rather than being destroyed by a run that accomplished nothing.
**Resume is its own entry path, distinct from a new run** — the checkpoint contract is only coherent against one holdings snapshot.
A **resume** — offered from a failed / cancelled run's tracker state, only while an eligible checkpoint trail exists and its pinned pull is younger than the drafted resume window ([§Starting parameters](#starting-parameters-calibratable)) — **reopens the interrupted run's ID and pins everything from it**: the original holdings pull (held option positions included), the Step-5 shared context, and the model / prompt / schema versions, with **no new holdings pull** — so completed and resumed holdings alike are computed against one book and one run-level context, and the finished run is honestly stamped with that pull's as-of time.
Per-holding retrieval is deliberately not pinned: option chains and the per-symbol FMP / EDGAR evidence fetch live at each holding's own analysis inside any run ([portfolio-workflow.md §Step 2](portfolio-workflow.md#step-2-load-holdings)), so a resumed holding's evidence is fresher than the pinned as-of by up to the resume window — the intra-run skew any hours-long run already carries, stretched.
The pinned vintage stamp is the conservative side of that skew: the next run's evidence-event boundary re-examines the stretch a resumed holding's fresher evidence already saw, never skips past it.
A version or roster that changed since the interrupted run — or a newer run persisting in between — refuses the resume with its reason rather than mixing verdicts across contracts.
The stamps are the resume contract (ruled 2026-08-29 off the review's Codex I18): the six version axes — prompt, grade, target, pre-profit, quick-check evaluation, and evidence floor — stamp what a completed holding's verdict, audit, and selective carried-tail state mean, the checkpoint format stamp (`store::CHECKPOINT_FORMAT_VERSION`) the trail's own shape, the roster the models, and the prior-run identity the baseline.
A rebuild that moves none of them resumes, the restored holdings carrying the pre-change behaviour.
A slice that changes what a completed holding's verdict or audit means is therefore obliged to move the axis it changed, and one that changes the trail's shape the format stamp.
No build identity is checked.
A trail stamped under another format loads its header alone — no row is read or skipped — so its refusal is the only surface it reaches.
The run-level keyed identities (episode sector identities, prompt-header names) ride the trail's accumulators so completed holdings' contributions survive into the finished run.
The complete physical-attempt observations and fired-retry events of every completed holding ride its own checkpoint row, drained from the analyst at that holding's checkpoint boundary, so the trail's telemetry membership is its row membership by construction.
The deep-history and benchmark contributions to the data-health counts ride the row the same way (ruled 2026-08-29 off the review's Codex I17).
The finished run rebuilds those counts from the rows it restored and the rows it wrote, so a re-analyzed holding counts once and a benchmark read unavailable in both processes once.
A resumed run's data-health read — the complete observation list, peak prompt, context pressure, length stops, and retries — therefore spans both processes.
Failed-holding observations remain in an uninterrupted finished run but have no completed checkpoint row; they do not survive a later interruption and re-analysis.
The finished run retains its full observation list even after successful persistence clears the checkpoint trail.
A row that never landed or no longer reads takes its calls with it and that holding re-analyzes whole, so no call is counted twice.
Absent are exactly the superseded calls — those of any holding the resumed process re-analyzed: the interrupted holding's abandoned calls, and the original calls behind a row that never landed or no longer read.
Each such holding re-issues them, so every retry the finished run lists still succeeded (ruled 2026-08-28).
The tracker's terminal state is deliberately the offer's **only** surface (ruled 2026-08-21): a trail orphaned by an app restart is unreachable by design, dying at the resume window or the next new run's discard.
The offered trail is not necessarily the shown run's own — a run failing before it opens its own trail leaves an earlier run's standing — so the offer identifies the trail by its own pinned as-of and progress, never by claiming it as the shown run's work.
A **new run** — what the Run analysis control always starts — takes a fresh holdings pull under a new run ID and **discards any interrupted run's checkpoints** (its partial verdicts never became a persisted run — the run-is-never-a-report analog); it re-runs the full pipeline including the 6c–6d research loop for every analyzed holding, the shared document cache serving repeat fetches and the prior run's analysis riding as on any continuity run, so the rerun is warm at the page level rather than a cold re-research ([web-research.md §The research loop and context management](web-research.md#the-research-loop-and-context-management)).
Within a run, web research is fail-soft by design (thinner evidence, lower conviction).
A hard **per-holding** model / grade failure is **isolated**, not fatal (ruled 2026-08-31): the holding is recorded failed and the run continues to the next.
A run fails outright only on a **run-level** failure — the rate anchors, the persistence write — or when **every attempted holding fails**, recorded like any other job ([scheduling.md](scheduling.md)).
The complete split, in one place — the failure matrix [scheduling.md](scheduling.md) delegates here.
**Hard, fails the run** — the Step-2 Schwab positions pull ([schwab-integration.md §Failure posture](schwab-integration.md#failure-posture)), a **run-level rate-anchor load failure**, the run-persistence write, and **every attempted holding failing** — a systemic cause (the daemon down, the roster misconfigured) under which the run accomplished no fresh analysis, so it persists **no snapshot** and the prior good run stays the latest view rather than being demoted by an all-failed one.
A run that fails here persists **no partial run row** — its checkpointed holdings live in the trail the resume path above consumes.
The run-persistence write validates before it lands (ruled 2026-08-29 off the review's Codex I16).
It decodes the record it serialized, and a record that would not read back — a non-finite required value serde writes as `null` — is refused, so the run fails here rather than persisting a row every later read would skip as unreadable.
The refusal names the holding whose record failed, or the run alone where the value sits outside the per-holding records.
A resume restores the same record from the trail and fails the same way, bounded by the resume window and the new run's discard — the accepted residual.
An internal error — a panic anywhere below the job spine, the compute modules over hostile feed values — is **contained at the job seam** and fails the run the same way, recorded `Failed` with the panic message as its detail (an unwinding panic; an abort is not catchable in-process).
The tracker reaches its failed terminal state, so any eligible standing checkpoint trail is offerable exactly as after any other failed run — a panic before the run opened its own trail leaves none of its own.
A panic is never a user stop — it records `Failed` even with a cancel pending.
A transient model-call failure on that path first re-attempts once under the adapter seam's bounded retry-once before the failed holding is isolated ([local-models.md §The local-model adapter seam](local-models.md#the-local-model-adapter-seam)) — the run-level fail applying only when the isolation leaves the run with no fresh verdict at all.
Since `portfolio-v9` no post-loop model stage exists to fail, so a run either persists complete or leaves no row: the construction stage that could fail after the per-holding pass was removed with tunnel vision, and the **fresh-start ruling** (2026-08-17) deleted its `constructed`-marker / degraded-row machinery whole ([verification/2026-08-17-fresh-start-legacy-removal.md](verification/2026-08-17-fresh-start-legacy-removal.md)).
A corrupt persisted blob still lists as **unreadable** and is skipped from `latest_run` and every baseline read, so the refusal surfaces distinguish a never-ran store from one whose only rows are unreadable.
A store read error on the prior run or the quick-check state degrades the same way — the run proceeds as a first run — and leaves a logged trace (ruled 2026-08-18; [storage.md §Local Analysis Suite Storage](storage.md#local-analysis-suite-storage)).
The rate-anchor failure is the Step-5 FRED `DGS10` / `DGS2` retrieval still failing after the shared bounded retries ([data-sources.md §FRED](data-sources.md#fred-federal-reserve-economic-data)): the engine consumes the rates numerically in every target and hurdle, so the run fails **before any per-holding work is spent** rather than computing them off a stale or guessed print.
This is the suite's **canonical rate-anchor rule** — Trade Opportunities' failure posture points here, and the engine-only quick paths instead fail-soft to the cached print under the drafted max age ([§Starting parameters](#starting-parameters-calibratable)).
**Fail-soft, degrades** — the optional web research and every enriching feed (FINRA, CBOE, the commodity context, CFTC positioning, option chains), each to its typed gap or degraded-input flag.
**Per-holding, never run-level** — missing floor-bearing inputs exit that holding as `insufficient-evidence` at Step 6b ([§Evidence floor](#evidence-floor)).
A hard **model / grade / persistence failure** on one holding's required 6c–6f path (the action call included) is likewise per-holding, and distinct from `insufficient-evidence` — the latter is a graceful analysis outcome, the former an error the run isolates.
The failed holding is recorded in the run's `failed_holdings` with a concise cause (the failing operation plus its root cause; the full chain on the tracker's failed step and stderr), its prior verdict **carried forward vintage-stamped** where one exists — the card shows that stale data beside a **failed badge** — or rendered as an **empty debut-failure card** where no prior exists, and the run completes and persists (ruled 2026-08-31).
A mid-holding cancel is not a failure: it re-checks the cancel flag and stops the run as `Cancelled`, never a failed card.
The one run-level escalation is the all-attempted-failed case above: a run left with no fresh verdict at all fails outright rather than persisting an all-failed snapshot.
And the engine-only **quick check** types each failed signal family **`unknown`** — never a silent clear — badging the holding in a selective run; only the rate legs fail-soft to a cached print under the drafted max age, and a failed price refresh has no cache to fall to ([§The quick check](#the-quick-check-engine-only)).
A carried holding stays carried under the ordinary rules whatever the sweep finds — the next full run (or selecting it) re-analyzes it, there being no research-age re-analysis rule ([§Starting parameters](#starting-parameters-calibratable)).
The **quick check** is engine-only — no model call (it runs even configured-but-down, like Trade Opportunities' Quick Audit), no web research, no Schwab call — so its failure surface is the local store and its refresh retrievals ([§The quick check](#the-quick-check-engine-only)) — surfaced through the typed per-family sweep states, so a failed retrieval is visible and selective-run-safe rather than indistinguishable from a clean pass.
