# Synthesis

*What is being built — the standing orientation. `BUILD.md` is the ordered backlog that builds it; `docs/` holds the reasoning behind each item.*

## What it is

Market Signal is a local-first macOS desktop app (Tauri 2 with a Rust backend, a Vue 3 frontend, SQLite) built for one investor running it on their own machine. It has two halves on one deterministic spine. The **Market Signal Report** is a cloud-model job that writes an evolving, professional-grade market thesis on demand. The **local analysis suite** runs on open-weight models on the user's Mac and applies that house view to the user's actual holdings and to the hunt for new ideas. The app is not a trading bot: the report gives no buy/sell instruction, and the suite, though deliberately prescriptive, never places an order. The suite is also framed as a research instrument — a test of whether a local reasoner, given primary-source data and the open web, can author and price a defensible thesis — so its results are an experiment's record, not investment guidance.

## The spine

The Rust application layer owns the control flow, every network and store call, every limit and all persistence; model calls are pure stages — structured input to type-checked output — behind traits swappable for deterministic stubs. One global run slot serializes every job, a live run tracker streams per-step progress, and a de-duplicating persistent warning area surfaces configuration gaps and job problems. Each job's Run button locks until the configuration it needs is present; connectivity is checked only at the run gate. Jobs are user-initiated and run only while the app is open; there is no scheduler.

## The Market Signal Report

An 18-step pipeline: validate configuration, load prior report context and audit earlier calls, retrieve vector memory, read the research inbox, gather market, macro and positioning data (FMP, FRED, BLS, CFTC) and news (FMP Articles, Tavily, GDELT), filter and route research under hard executor bounds, build a condensed packet, run the Bull, Bear and Balanced analysts, and have the main agent write the report in one voice. The four agents are user-configurable OpenAI or Anthropic models; fixed internal models handle headline filtering, research routing and embeddings. Reports are canonical Markdown with HTML generated only for display and PDF export; the most recent 30 are retained, durable learnings outlive them, and the thesis evolves across reports — stable through noise, pivoting on structural change.

## The local analysis suite

The substrate: an Ollama daemon the user installs serves the roster — a 122B reasoner every local job needs, an embedder Trade Opportunities needs, an optional fast tier — with schema-constrained output; a connected Charles Schwab account supplies holdings and option chains; a SearXNG-only search / fetch / extract loop is the model's web tool; FMP, SEC EDGAR, FINRA and CBOE supply the hard data. The suite makes no external model call and costs nothing at the model layer.

**Portfolio Analysis** analyzes every gradable holding from a fresh Schwab pull and recommends an action for each. A priced holding gets a two-arm verdict. The engine arm is deterministic: a letter grade with sub-scores, bear/base/bull bands at three months, twelve months and three years, a risk tier, a capital-efficiency hurdle read, a hard-forensic state from the filings, and the engine's own action rung. The model arm is the reasoner's prose: per-topic research conversations against the web produce write-ups, consolidated into one analysis that is the holding's only cross-run research memory; on a continuity run a self-review judges the prior call against realized prices; then a thesis document argues thesis, drivers, scenarios, falsifiers, triggers, conviction and the expected price at each horizon, a typed appendix transcribes the conviction and the three prices, and a separate action call — the only stage that sees the position's economics — returns the rung. The app checks model output on type alone, never on content. An unpriceable fund takes a role / risk read instead. Outcome learning is an append-only episode store: each run records spot, the anchor close, the model's expected prices and the engine's base values at the three horizons; a check comes due at each horizon and scores both arms by percentage error; each holding carries accuracy scores that ride its self-review and its card. Around the full run sit an engine-only quick check (the hurdle and twelve-month-band monitors plus evidence events), a selective re-analysis that carries unselected verdicts forward vintage-stamped, a view-only holdings pull, and a portfolio roll-up.

**Trade Opportunities** hunts for new ideas outside the book. Discover finds new names through a discovery funnel and deep web research across a fixed risk-by-horizon matrix, each anchored on a countable, dated leading metric; Audit re-evaluates the names the user selects. Only a deep re-evaluation can archive an opportunity; the cheap engine-only pass only flags.

## Storage

SQLite holds every record: report metadata, job history, warning state, baseline snapshots, the vector table (exact cosine in Rust), holdings snapshots, Portfolio runs with their checkpoint trail, the episode store, the document cache and the price-bar cache. Markdown reports and the research inbox live on the filesystem. Whole-corpus export and import move all of it between machines.
